B. Кто как использует bb: три уровня, и главный оркестратор это не «один агент на всё»

Паттерн, который автор сам называет ежедневным, описан на https://getbb.app/blog/building-a-restrained-software-factory.

Уровень 1. Любой агент внутри bb плодит дочерние треды другого провайдера. Пример автора: Fable через Claude Code пишет код, дочерний тред на другой модели ревьюит, родитель получает сигнал, когда ребёнок остановился. Большой веер он использует редко. Для обычной реализации один агент у него лучше роя. Веер он оставляет на случай «сначала много решений, потом дешёвая однотипная правка».

Уровень 2. Долгоживущий manager thread, которого будит Automations. Модель данных прямо делит треды на standard и manager, дети разрешены: https://github.com/get-bb/bb/blob/main/docs/system-overview.md. Два его утренних менеджера: Marketplace Manager (смотрит PR плагинов, ставит их в тестовый bb, кликает, даёт да/нет и помнит прошлый отказ) и Issue Report Manager (сводка issues, дубли, темы, по просьбе спавнит агентов на фикс и PR). Он прямо пишет, что идея «один менеджер делает всю работу» у него не сложилась, и сравнивает такого менеджера с «лёгким OpenClaw на одну обязанность». С 0.43.0 (11 сентября 2026) тред можно перетащить на другой тред и сделать ребёнком: https://getbb.app/changelog.

Уровень 3. Плагины. SlopCop, https://getbb.app/marketplace/slopcop, исходники https://github.com/SawyerHood/sawyer-plugins: правила на событие GitHub (issue, PR, упоминание хэндла) и новый тред по шаблону. У автора правило на каждый issue: воспроизвести, отчёт, лёгкий фикс сразу в PR. Workflows, https://github.com/get-bb/bb/blob/main/plugins/workflows/README.md: агент пишет JavaScript, QuickJS оркестрирует, рассуждает обычный тред bb, провайдер выбирается на каждого воркера. Автор зовёт это для больших миграций (линт по файлам), не как ежедневный пульт.

Сайт https://getbb.app/ прямо рисует обратную схему: внешний cron, shell, Hermes или OpenClaw в Telegram/Signal/Slack сами вызывают CLI bb и оставляют тред в сайдбаре. То есть штатная картинка мира: bb это командный центр и журнал, а «главный мозг» может жить и снаружи, и внутри manager thread. Авторский вывод 17 сентября 2026: одна говорящая голова на весь завод не работает. Работает несколько узких менеджеров плюс ручное наблюдение.

C. Несколько агентов и кто что делает

Штатный набор на https://www.npmjs.com/package/bb-app и в https://github.com/get-bb/bb/blob/main/plugins/provider-acp/src/known-agents.ts:

| Провайдер | Как поднимается | Логин на той машине, где крутится тред |
| --- | --- | --- |
| Claude Code | свой плагин | `claude` по доке Claude |
| Codex | свой плагин, CLI от 0.136.0, https://github.com/get-bb/bb/blob/main/plugins/provider-codex/PLUGIN_OVERVIEW.md | `codex login` |
| Cursor | `cursor-agent acp`, id `acp-cursor`, в списке всегда | `cursor-agent login` |
| OpenCode | если на PATH есть `opencode acp` | `opencode auth login` |
| omp (oh-my-pi) | `omp acp`, https://github.com/can1357/omp | `omp login` |
| Grok Build | `grok agent stdio` | `grok login` или `XAI_API_KEY` |
| Hermes Agent | `hermes acp` | `hermes login` |
| Pi | отдельный плагин, npm `@earendil-works/pi-coding-agent` от 0.84.0 | по доке Pi |

Gemini CLI, GLM и Mistral в этом списке нет. Gemini всплывает в чужом плагине Handoff как сессия, которую можно забрать из терминала в тред bb (Claude Code, Codex, Gemini CLI, OpenCode): https://getbb.app/marketplace/handoff. Свой ACP-агент добавляется без перезапуска: https://github.com/get-bb/bb/blob/main/docs/configuration.md, секция Custom ACP Agents, `bb plugin config provider-acp set customAgents '[...]'`, id станет `acp-<id>`. Команда агента исполняется только рядом с локальным daemon. Если Gemini/GLM/Mistral CLI умеют ACP, их можно дописать так. Если не умеют, путь через omp: сам omp внутри bb один провайдер, а модели (в том числе Mistral) он роутит у себя, https://ohmypi.xyz/ и https://github.com/can1357/oh-my-pi/blob/main/docs/providers.md.

Деление работы, которое видно в живых текстах, а не в маркетинговой табличке сайта:

Планирует сильная модель в родительском треде. У Hood это Fable через Claude Code. Исполняет более дешёвый воркер в ребёнке или в workflow. Ревьюит другой провайдер в дочернем треде, либо плагин Advisor (второе мнение, карточка на странице SlopCop, автор Salem Sayed Abdel Gawad, счётчик 158). Сдача между агентами: встроенный handoff с 0.43.3 (другой провайдер или другая модель, черновик и workspace сохраняются, https://getbb.app/changelog) и плагин Handoff, который тащит транскрипт и незакоммиченный diff патчем на другую машину. Codex можно заставить делегировать через треды bb, а не через свои скрытые субагенты: настройка `Disable provider subagents` в https://github.com/get-bb/bb/blob/main/plugins/provider-codex/PLUGIN_OVERVIEW.md. По Claude Code есть открытый баг от 20 сентября 2026, https://github.com/get-bb/bb/issues/3959 (luketraas): выключение субагентов запрещает вызов, но список инструментов всё равно уходит в контекст. Ультра-уровень reasoning у Codex включает автоматическую делегацию уже на стороне Codex.

Account Pooler (с 0.42.0, 5 сентября 2026, в тех нотах помечен experimental; в 0.43.0, 11 сентября, расширен письмами аккаунтов, порядком и лимитами на мобиле) крутит только аккаунты Claude и Codex, когда упираются в лимит подписки. На Grok, Cursor, Gemini, GLM это не распространяется.

Маршрутизатор «сам выбери проект, машину и модель» есть как плагин Magic Compose (карточка на https://getbb.app/marketplace/slopcop). Он шлёт промпт, инструкции и сведения о машинах наружу, в TypeSafe через Vercel AI Gateway или OpenRouter. Для флота с секретами это отдельный контур, не дефолт.

D. Интерфейсы и что реально ставить на headless VPS

Куски из https://github.com/get-bb/bb/blob/main/docs/repository-overview.md и https://github.com/get-bb/bb/blob/main/docs/multiple-devices.md:

Web app. Это и есть UI. На VPS его отдают `npx bb-app`. Десктоп тоже грузит тот же UI.

Desktop. Рекомендуемый старт: macOS Apple Silicon. Linux x64 AppImage в README назван alpha. Intel Mac идёт через npx. Нативный Windows PowerShell и CMD не поддерживаются. Windows только как Ubuntu в WSL2, репозитории лучше внутри файловой системы WSL. Путь `/mnt/c/...` поддерживается и прямо назван более медленным и менее надёжным для file watching: https://www.npmjs.com/package/bb-app. Для хаба с двумя GPU это главное ограничение: daemon bb на Windows живёт в WSL2, не в родном Task Scheduler-мире.

CLI `bb`. Тот же контракт, что у UI. Агенты и внешний cron зовут его. По умолчанию целится в `http://127.0.0.1:38886`, переопределение `BB_SERVER_URL`.

HTTP API и WebSocket. Контракт `@bb/server-contract`. Node SDK `BBSdk` из пакета `bb-app` умеет `threads.spawn` / `wait` / `output`.

iOS. Клиент, сам ничего не исполняет. С 0.41.0 это WebView вокруг того же web app. TestFlight указан в нотах 0.42.0: https://testflight.apple.com/join/T9MayTMb. В https://github.com/get-bb/bb/blob/main/docs/platform-support.md магазинного релиза нет, Android не собран, ранний доступ спрятан за эксперимент `mobileApp`. Телефон не логинит провайдеров, не открывает локальный редактор и не показывает фронты плагинов. Панель Automations на телефоне недоступна. Пуши идут через Expo, серверу нужен выход на https://exp.host, ключи Apple не нужны.

bb connect. Опциональный реле `https://<handle>.getbb.app`. Туннель держит сам сервер, пока включён плагин connect. С 0.39.0 (19 августа 2026, строка в https://github.com/get-bb/bb/blob/main/CHANGELOG.md) лимит 20 серверов и 20 машин на аккаунт. Телефон, десктоп-клиент и execution-машина едят один и тот же слот машин. Код спаривания живёт 10 минут и одноразовый. Сессия getbb.app обязательна, публичной ссылки нет. `bb connect expose <port>` публикует порт машины как `https://<label>--<port>.getbb.app`.

Что люди ставят на всегда включённую машину. Док прямо говорит: сервер ставьте на компьютер, который не засыпает (десктоп, домашний сервер, VM). Пока он выключен, bb недостижим и текущие треды могут остановиться. Headless-путь это `npx bb-app` под своим процесс-менеджером, не AppImage. Отдельного unit-файла «сервер bb» в открытых доках нет. User-systemd описан для подключённой execution-машины: `~/.config/systemd/user/bb-host-daemon-<server>.service`, с `--auto-update`. Daemon подтягивает артефакт сервера, сверяет SHA-256, никогда сам не откатывается на старый протокол. Браузер на ноутбуке сервером не становится. Запись машины не открывает UI.

Tailnet против connect. Документированный приватный путь: слушать loopback и опубликовать Tailscale Serve.

`tailscale serve --bg --https=443 http://127.0.0.1:38886`

затем `npx bb-app config set BB_APP_URL https://<machine>.<tailnet>.ts.net`

Граница доступа это ACL Tailscale. Funnel и публичный интернет в доке запрещены. Совместимый флаг `--server-bind-host 0.0.0.0` в README и в multiple-devices описан одной фразой: публичный API без аутентификации, он разрешает выполнение команд и чтение файлов. Его держат только за доверенной границей сети и никогда через Funnel. Политика https://getbb.app/privacy (обновлена 20 августа 2026): через connect трафик проходит реле, TLS обрывается на реле, записи содержимого авторы обещают не хранить, но это не сквозное шифрование. Реле видит содержимое в полёте. Для VPS в tailnet основной пульт это Tailscale Serve на loopback. Connect имеет смысл как второй вход с телефона вне tailnet, с пониманием реле и лимита 20 слотов. Если :8443 слушает 0.0.0.0, это как раз тот неаутентифицированный API, даже когда «мы думаем, что снаружи только tailnet»: файрвол и bind надо сверить отдельно. В upstream-доках порта 8443 нет.

E. Automations bb и внешний планировщик

Плагин описан в https://github.com/get-bb/bb/blob/main/plugins/automations/PLUGIN_OVERVIEW.md. Два типа расписания: cron с таймзоной, либо one-shot (дата или задержка вроде `2h`). Два типа работы: агент (провайдер, модель, reasoning, permission, новый тред, дописка старого треда или новый worktree на каждый запуск) и скрипт (bash, sh, node, python3) на машине, где крутится сервер bb. История прогонов, stdout/stderr/код выхода. Команды `bb automation create|list|show|update|pause|resume|run|runs|delete`. Тред, который родила автоматизация, сам автоматизации создавать не может.

Починка очереди в 0.39.0, строка changelog: упавший прогон больше не перезапускается мгновенно. Повтор через 30 с, потом 60 с, после третьей неудачи подряд автоматизация встаёт на паузу. На одну автоматизацию одновременно один запуск. Таймаут скрипта убивает всю группу процессов. Сироты закрываются на старте. В 0.43.3 у скриптовых автоматизаций появился явный working directory. В 0.41.0 починили загрузку «деградировавшей» автоматизации.

Отдельный механизм, не cron: dispatch queue с 0.41.0. Плагин Send later держит сообщение до срока. Concurrency limit не даёт стартовать больше тредов, чем позволяет лимит, и очередь ждёт, пока тред освободится. Это очередь сообщений, не замена Task Scheduler.

Кейса «перенесли парк из 100 cron внутрь bb» в открытых блогах, HN и issues этого прогона нет. Официальная история на https://getbb.app/ обратная: внешний cron, shell или бот вызывают bb и оставляют тред человеку. Hood перенёс в Automations два утренних менеджера, не операционную систему.

Практическое разрешение конфликта двух планировщиков, собранное из этих контрактов. Источник правды для уже живущих рутин остаётся systemd timer и Windows Task Scheduler: они не требуют, чтобы процесс bb был жив, не едят контекст модели и не делят один слот «один запуск на автоматизацию». В bb кладут только то, что должно проснуться как тред агента и остаться на таймлайне (утренний разбор issues, ревью PR). Скриптовый режим bb имеет смысл для короткого скрипта на самом VPS-сервере bb. Скрипт на Windows-хабе из автоматизации bb не запустить: скрипты исполняются на хосте сервера. Мост в обратную сторону уже есть: внешний планировщик вызывает `bb thread spawn` или SDK. Два планировщика сталкиваются, если одна и та же работа и в timer, и в Automations: лимит «один execution», пауза после трёх падений и concurrency limit начнут глотать запуски без сообщения в Task Scheduler.

F. Что в 0.42–0.44 реально про мульти-агентов, а что сырое

Уже было в вашем 0.41.0 (1 сентября 2026), https://getbb.app/changelog: очередь отправки, Send later, Concurrency limit (дефолт равен числу процессоров машины), равная сетка split panes, восстановление Automations, воркеры Workflows архивируются вместе с retention. Хук `bb.experimental_hooks.on("message.dispatch")` и события `message.queued`, `message.dispatched`, `turn.failed` помечены experimental.

0.42.0, 5 сентября 2026. Account Pooler для Claude и Codex, в этих нотах experimental. Пуши на mobile, web и desktop. Каталог плагинов. `/clear` сбрасывает контекст, историю треда не стирает. Очередь: стоп треда ставит очередь на паузу, группа сообщений уходит вместе, follow-up переживает офлайн хоста. Много `experimental_*` в API плагинов (`experimental_schema`, `experimental_appOverlay`, `experimental_sidebarFooter`, `experimental_contributeEnv`, `experimental_websocket`, `experimental_appUrl`). Починка старта Linux AppImage названа «intermittent».

0.43.0, 11 сентября 2026. Перетаскивание треда на тред. Experimental: Modal sandboxes и Browser Automation (в том числе headless-браузер на выбранной машине). Account Pooler дописан (почта, порядок, лимиты на мобиле) без повторной пометки experimental в этом абзаце. Машины умеют паузу и resume через plugin API.

0.43.3, 18 сентября 2026. Черновики. Handoff из композера на другой провайдер или другую модель. Working directory у скриптовых автоматизаций. Experimental: перенос сервера на другую машину (репозитории, workspace и сессии провайдеров остаются на старых машинах), multi-machine picker, dispatch context (`queuedMessages`, автор, origin), browser extensions, composer controls, discoverable RPC. Вложенный bb может пользоваться Account Pooler родителя для Claude и Codex. Починка спаривания машины по голому HTTP.

0.44.0, 25 сентября 2026. Plugin safe mode: одним шагом гасит все плагины, которые не входили в поставку bb, и возвращает их при выключении режима. Фильтр диффа глобами. Архивация с undo 30 секунд, живой ход и терминалы в этом окне не убиваются. Claude Code fast mode на поддерживаемых Opus. Починки туннеля bb connect, застрявших workspace и вопросов, мобильной клавиатуры. Новые experimental API: `aiServices`, `sidebarHeader`, `useSidebarNavigation`, `sendMenu`, событие `experimental_host.deleted`. Opt-in обновление из UI: `npx bb-app start --in-app-updates`.

Workflows, цифры с https://github.com/get-bb/bb/blob/main/docs/configuration.md. На чистой установке плагин выключен. `maxActiveRuns` по умолчанию 4 (диапазон 1–32), применяется сразу ко всей очереди плагина. `maxConcurrentAgents` 8 (1–64) внутри одного прогона, включая ребёнка. `maxAgentCalls` 100 (1–1000). `totalRunTimeoutMs` 86400000, то есть 24 часа. Retention 7 дней. Эти пять настроек, кроме `maxActiveRuns`, снимок на момент старта прогона. QuickJS не имеет Node, файловой системы, shell, сети, часов и случайности. Ребёнок workflow не может позвать внука. Воркеры это скрытые root-треды: уведомление родителя на них не приходит. Это другой механизм, чем manager thread, где родитель узнаёт об остановке ребёнка. Повтор transient-ошибок провайдера два раза. Resume переигрывает успешные вызовы по SHA-256, пока скрипт не разошёлся. Issue https://github.com/get-bb/bb/issues/1573 (SawyerHood, 14 августа 2026) описывает, как пачка скрытых воркеров держала процессы и съедала память, если `threads.stop` не отпускал idle runtime.

Concurrency limit, https://github.com/get-bb/bb/blob/main/plugins/concurrency-limit/PLUGIN_OVERVIEW.md. Дефолт: один бегущий тред на процессор хоста. Можно фиксировать хост и поставить общий потолок или `unlimited`. Диапазон 0–10000. Ноль держит все новые ходы. Сообщение в уже бегущий тред не ставится в эту очередь. На маленьком VPS дефолт «по числу CPU» легко занимает все ядра агентами. На хабе с GPU лимит считает процессоры, не видеокарты.

Split views к оркестрации агентов почти не относятся. Это раскладка панелей: равная сетка с 0.41.0, хоткеи между сплитами в 0.44.0, вкладки панели треда с 0.40.0 (26 августа 2026). Открытый запрос https://github.com/get-bb/bb/issues/3891 (mgmobrien, 18 сентября 2026): восстановить целый split-layout из плагина без перезагрузки. Для флота это удобство глаз, не маршрутизация.

G. Альтернативы, по абзацу

OpenClaw (https://github.com/openclaw/openclaw, на странице организации около 391k звёзд, сайт https://openclaw.ai). Это личный ассистент с Gateway на своей машине и входом из Telegram, WhatsApp, Slack и ещё десятков каналов. Модели и harness подключаются плагинами, состояние лежит локально. Для вашего флота он сильнее как рот и диспетчер сообщений (у вас шина уже Telegram), и слабее как IDE тредов с диффом, worktree и несколькими подписанными CLI в одном таймлайне. Сам bb предлагает звать себя из OpenClaw, а не заменять его.

Conductor (https://www.conductor.build/docs). Нативное приложение Melty: параллельные Claude Code, Codex, Cursor и OpenCode, у каждой задачи свой workspace, ветка, терминал и дифф. Подписку не перепродаёт. В открытой доке это Mac-приложение. Веб-пульт на Linux-VPS и запись Windows/Mac машин в один сервер там не обещаны. Для «сижу на маке и ревьюю несколько веток» он проще bb. Для вашего якоря на Hetzner он не ложится.

Vibe Kanban (https://github.com/BloopAI/vibe-kanban). Канбан: задача, workspace с веткой, терминалом и dev-сервером, инлайн-комменты в дифф, PR. Список агентов шире bb в одну сторону: Claude Code, Codex, Gemini CLI, Copilot, Amp, Cursor, OpenCode, Droid, CCR, Qwen. README сейчас начинается с «Vibe Kanban is sunsetting» и ссылки на https://www.vibekanban.com/blog/shutdown. PR https://github.com/BloopAI/vibe-kanban/pull/3388 смёржен 24 апреля 2026 именно как объявление заката. Issue https://github.com/BloopAI/vibe-kanban/issues/3396 (26 апреля 2026) пишет, что облачные Projects стали export-only даже на своём сервере. Как веб-UI поверх CLI он близок к вашему сценарию и умеет Gemini из коробки, но компания-автор закрыла продукт. Брать его ядром флота в сентябре 2026 значит жить на архиве.

omp, он же oh-my-pi (https://ohmypi.xyz/, https://github.com/can1357/oh-my-pi). Это не пульт над несколькими CLI, а один терминальный агент-форк Pi с десятками провайдеров моделей, субагентами и ролями. Внутри bb он уже один из ACP-провайдеров (`omp acp`). Имеет смысл как «дёшевый разномодельный исполнитель» в одном треде, включая Mistral, а не как замена сервера bb.

claude-squad (https://github.com/smtg-ai/claude-squad, README: Claude Code, Codex, Gemini и Aider, каждый в своём git workspace, tmux, бинарь `cs`). Звёзды на странице README в этом прогоне около 8.5k. Интерфейс терминальный. Веб-UI, телефона, мультимашины и журнала тредов между ноутбуками нет. Для человека, который живёт в tmux на одной Linux-машине, он легче. Для хвоста «VPS плюс флот плюс глаза Антона в браузере» он пустой.

Коротко по соседним именам из обзоров, которые открыты, но не разобраны по исходникам так же глубоко. AgentsRoom сравнивает Conductor, Crystal, Claude Squad и Vibe Kanban на https://agentsroom.dev/blog/best-multi-agent-coding-tools (обновление страницы 29 сентября 2026) и сам стоит в этой же витрине. amux на https://amux.io/blog/best-multi-agent-orchestrators-2026 описывает себя как сервер с вебом, PWA и канбаном. Nimbalyst на https://nimbalyst.com/blog/best-agent-management-tools-2026 продаёт более широкий workspace и пишет, что облако Vibe Kanban кончилось 10 апреля 2026. Ни один из открытых обзоров не показывает связку «один Linux-VPS, свои подписки Claude/Codex/Cursor/Grok, Windows-хаб с GPU, сотня уже существующих timer'ов» лучше, чем bb. Ближе всех по форме Vibe Kanban, и он как раз гаснет.

H. Целевая схема для этого флота и риски

Оркестратор состояния: один сервер bb на Linux-VPS, который уже не спит. Поднять его с 0.41.0 на 0.44.0 до того, как на него сядут менеджеры: между ними очередь, лимит конкуренции, handoff, safe mode и починка туннеля. Процесс `npx bb-app` оставить под тем systemd, которым он уже живёт. UI только через Tailscale Serve на loopback 38886, `BB_APP_URL` на magicDNS tailnet. Слушающий 0.0.0.0 адрес, включая отдельный :8443, сверить: если он есть, это неаутентифицированный API с запуском команд. Connect не делать основным входом. Включить его позже, если понадобится телефон вне tailnet, и помнить про 20 слотов и про то, что реле обрывает TLS.

Глаза: браузер на Windows-хабе и на ноутбуках по tailnet. Десктопное приложение имеет смысл на Mac Apple Silicon как оболочка над удалённым сервером (меню Server в доке это умеет). Linux AppImage не брать за основной клиент, пока README зовёт его alpha. Телефон через TestFlight только как пульт чтения, после эксперимента `mobileApp`. Панель автоматизаций с телефона не откроется.

Исполнение. VPS enrollить как первую машину для лёгких тредов и для скриптов Automations. Windows-хаб с GPU подключать второй машиной только из WSL2, с CLI провайдеров, залогиненными внутри того же WSL, и с репозиториями по возможности не на `/mnt/c`. Ноутбуки держать браузерами. В execution-машины превращать ноутбук только когда нужен именно его логин или его диск. Потолок конкуренции на VPS поставить руками ниже числа CPU (`bb concurrency-limit host <id> <n>`), на хабе считать от того, сколько подписочных сессий вы готовы жечь, а не от числа ядер.

Четыре-шесть агентов, роли. Claude Code: план и ревью, долгоживущие узкие менеджеры (не один на весь завод). Codex: реализация в worktree, с `Disable provider subagents`, чтобы делегирование было видно как тред bb. Cursor: точечный рефакторинг там, где уже есть его логин. Grok Build: отдельный исполнитель на своей подписке. omp: разномодельный дешёвый воркер, сюда же Mistral, если он нужен как модель, а не как отдельный CLI. Шестой слот оставить под custom ACP, когда будет проверенный ACP-вход Gemini или GLM. До проверки не считать их подключёнными. Плагин Handoff использовать, чтобы забрать уже идущую терминальную сессию Gemini в тред. Account Pooler включить только для ротации своих аккаунтов Claude и Codex. Workflows не включать, пока нет одной конкретной миграции. Для неё потолок `maxConcurrentAgents` держать маленьким. Скрытые воркеры родителю не рапортуют, внуки запрещены.

Планировщик. Сотню рутин Windows не переносить. Task Scheduler и systemd timers остаются хозяевами расписания. В Automations bb завести единицы утренних менеджеров, которым нужен таймлайн. Если рутине нужен агент, timer на той машине, где лежит логин, вызывает `bb` по `BB_SERVER_URL` внутри tailnet. Одну и ту же работу в оба планировщика не класть.

Риски, которые следуют из открытых страниц. API без логина при bind не на loopback. Реле connect видит трафик. AppImage и нативный Windows сырые или отсутствуют. WSL на `/mnt/c` ломает ощущение «хаб и так рядом». Workflows и часть API 0.43–0.44 помечены experimental, README всё ещё пишет, что workflows эволюционируют. Дефолт конкуренции равен CPU и на VPS съест машину. Пул аккаунтов не покрывает Grok, Cursor, Gemini, GLM. Линейка 0.41 на 0.44 не умеет откатывать daemon вниз по протоколу. Телеметрия продовых запусков включена, выключение `BB_TELEMETRY=false` (README). Чужой плагин может уронить UI: для этого в 0.44 есть safe mode. Публичного доказательства, что кто-то уже прогнал такой флот месяц, нет. Ближайший доказанный режим это режим автора: несколько узких менеджеров, редкий веер, человек смотрит таймлайн.

Покрытие этого прогона. Открыты сайт, changelog, README, npm, system overview, multiple-devices, configuration, platform-support (через выдачу и цитаты страницы), workflows README, automations и concurrency PLUGIN_OVERVIEW, known-agents.ts, privacy, SlopCop, Handoff, HN-тред 49272048, Show HN 48752835, hunted.space по Product Hunt, README claude-squad, README vibe-kanban, дока Conductor, README и организация OpenClaw, сайт omp. Не читались Discord bb, комментарии Product Hunt целиком, YouTube. Отдельного кейса миграции cron-парка не найдено. Это отсутствие в открытом вебе на 29 сентября 2026, не доказательство, что такого внедрения нет в закрытых чатах.

I. Простыми словами

bb это общий стол, за которым уже сидят ваши Клод, Кодекс, Курсор и Грок. Стол лучше поставить на включённый сервер в хвосте и смотреть на него через Tailscale, как в закрытую дверь дома. В интернет эту дверь не выставлять: у неё нет замка. Одного начальника на всех агентов авторы сами не удержали. Держат нескольких дежурных, а старые будильники Windows не выбрасывают. Телефон и красивое маковское приложение умеют смотреть на стол. Работать руками они не обязаны.
