# Официальные API (2025–2026)

- **Meta Graph API**: Нативно **нельзя публиковать на личный профиль** (no `publish_actions` существует с 2018 г.). API позволяет публиковать только в *Pages* (страницы) и группы. Чтение собственных постов личного профиля возможно через `GET /me/posts` с токеном пользователя и правом `user_posts`. Для этого не требуется одобрения, если вы публикуете/читайте только свои данные. Однако для более широкого использования придётся проходить App Review: нужна бизнес-верификация и демонстрация использования (скринкасты, политика приватности).  
- **Лимиты Graph API**: Стандартно приложение имеет **200 вызовов/час** на пользователя (rollover). Одобренный для бизнес-использования — до **4 800 вызовов/час** на приложение. Лимиты на уровни страниц (`X-Page-Usage` header) учитываются отдельно. Избыток – ошибки 4xx. Для длительных интеграций токены страниц остаются действительны до смены пароля или деавторизации.

- **X/Twitter API v2**: Начиная с 2026 года действует «pay-per-use» модель (free tier убран). Затраты: 
  - **Чтение своих данных (Owned Reads)** – $0.001/ресурс. 
  - **Публикация (POST)** – $0.015 за твит без ссылки, $0.20 с любой ссылкой. 
  - **Лимиты**: API позволяет до 100 постов/15 мин на пользователя (10 000/сутки на приложение). Но есть отдельный *ограничитель аккаунта*: для непроверенных аккаунтов с мая 2026 – **~50 оригинальных постов в сутки** (остальные ответы/ретвиты – до 200). Превышение – задержки 429 и возможная блокировка. Класс Free/Basic/Pro – в настоящее время нет: остались лишь платные или Enterprise, бесплатный уровень отменён (лишь узкий гейтхелм для особых сервисов). Legacy Basic ($200), Pro ($5000) доступны только для старых подписчиков. 

# Мониторинг личной стены Facebook

- **Graph API**: Самый устойчивый способ – **опрашивать `/me/posts` с user-token** (право `user_posts`). Это даёт свежие посты пользователя. Нет нативных вебхуков для личной ленты, придётся опрашивать с удобным интервалом (например, каждые 5–10 мин). Такой метод официально разрешён и не ведёт к бану, если использовать через авторизованный токен. Минус – нужно собственное приложение и авторизация.
- **RSS-мосты/сервисы**: Специальных RSS для личных профилей нет (RSS.app и аналоги обычно требуют Business Page и платны). Возможен RSS-Bridge (open-source), но он хуже поддерживается и для профилей в Facebook часто не работает из-за входа/кэпчи.
- **Скрейпинг**: Автоматизированные запросы к веб-странице профиля (через HTTP или headless-браузер) технически возможны, но Facebook активно с ними борется: частые запросы вызывают капчи и временные блокировки. Это ненадёжно и рисковано для учётки. 
- **Мониторинговые сервисы**: Нет известных бесплатных сервисов, отслеживающих личную ленту. Можно настроить n8n/Puppeteer/Playwright-скрипт, который раз в X минут открывает страницу профиля, сравнивает ID последнего поста. Если пост новый – уведомлять. Подход рабочий, но неофициальный. Чтобы снизить риск блокировок, требуется имитировать человеческое поведение (нестатичные User-Agent, случайные задержки). 

**Вывод**: самый надёжный путь – Graph API со своим user-token и периодическим опросом (технически поддерживается, безопасно по правилам). Все остальные «RSS/скрейп» решения нестабильны и могут привести к капчам/бану.

# Анти-бан / правила

- **Facebook**: Автоматический постинг личного аккаунта запрещён (любое несанкционированное API- или скриптовое размещение нарушает правила). Даже для страниц частое или дублирующее содержание может привести к ограничению: показ ошибки "Too Fast" (слишком частая активность). По неофициальным данным, постинг чаще чем **~1 раза в 6–10 минут** может триггерить защиту (пользователи жалуются на блоки при <6 мин). Стабильный режим – 1–2 поста в несколько часов. Дублирование контента (одинаковые тексты) на нескольких профилях/группах – сигнальный фактор спама. Безопаснее использовать официальный API/Business-инструменты, а не браузерную роботизацию.

- **X (Twitter)**: Автоматизация должна идти через официальный API, без обхода лимитов. Запрещено массовое спам-поведение: повторные или похожие посты, нежелательные массовые сообщения, «мультиаккаунтинг» для спама. Нельзя подделывать ссылки (многоэтапный редирект). **Лимиты**: как отмечено, не более ~50 оригинальных твитов в сутки для непроверенного аккаунта. Если проверен (входит в „Premium“), лимит выше (не раскрыт). **Человеческий паттерн** – редкие посты с собственным текстом, отсутствие кликов «мультиссылка»; время между постами считается в минутах, а не секундах. Боты, постящие раз в секунду или многократно ретвитящие себя – быстро блокируются.

# Браузер-автоматизация (fallback)

Когда API **недоступен**, можно использовать автоматическое управление браузером (Selenium/Playwright/Claude-in-Chrome). Например:
- **Facebook (личный профиль)**: API не позволяет, значит для постинга единственная опция – браузер. Подобная автоматизация всегда рискована: Facebook активно детектирует необычную активность. Для снижения риска нужно тщательно имитировать человека: реальный User-Agent, задержки/тайминги случайные, минимизировать число операций (один пост за сессию), использовать стабильную сессию (не перелогиниваться), желательно VPN/прокси постоянные для одного аккаунта. Всегда сохранять учётку (в сети, телефоне) и 2FA – чтобы снять возможные блокировки вручную.  
- **X (Twitter)**: Крайне не рекомендуется обходить API через UI-скрипт, X это прямо запрещает (автоматическая навигация по сайту ведёт к перманентному бану). Использовать следует только API.  

**Когда юзать**: Только если **нельзя иначе** – например, исключительно для личного профиля FB, т.к. Graph API не даст опубликовать туда. Всегда как запасной вариант. Иначе – каждые 50–100 операций требовать капчу/рекапчу, что превратит задачу в рутину. 

# Рекомендованный стек

**Вариант «дёшево/self-hosted»**:
- **Мониторинг FB**: Воспользоваться собственным Graph API. Создать приложение (Dev), авторизовать свой аккаунт через OAuth, получать `user_posts`. В n8n добавить HTTP-запрос `/me/posts` каждые 5–10 минут и проверять появление новых постов. Для отправки уведомлений – уже есть Telegram-боты. Это бесплатно (кроме хостинга n8n).  
- **Постинг в X**: Использовать нативный X API через HTTP (или node.js, Python). Можно вызывать API v2 через n8n Webhook/HTTP (использовать токен и кредиты). Стоимость минимальна (несколько центов за пост) и оплачивается при необходимости.  
- **Постинг в FB**: Для ЛИЧНОГО профиля – применять **Playwright или Claude-in-Chrome**. Запланировать через n8n: по расписанию запускать скрипт, логиниться один раз, выполнять постинг тизера. Оба варианта self-hosted. Главная “оплата” – ваша надежность и время на настройку.  

**Вариант «надёжно/платно»**:
- **Мониторинг FB**: Если нужна гарантия, можно использовать специализированные сервисы (например платные Social Listening tools), но для личного профиля их мало. Скорее – остаться на Graph API с выделенной поддержкой.  
- **Постинг (FB+X)**: Использовать готовые облачные продукты: например, **Buffer Pro** или **Publer Business**. Они официально поддерживают оба канала (создают посты на FB Pages и на X) и имеют надёжную инфраструктуру. Хотя они не работают с ЛИЧНЫМ профилем на FB (вписать разве что страницу), зато риск бана минимален, поддержка и SLA есть. Или Ayrshare (дорогой) – богатый API для всех задач.  

# Безопасные лимиты постинга

- **Facebook**: Не более *нескольких постов в день*. Практически не чаще, чем раз в 5–10 минут. Рекомендуется до 5–10 постов в сутки (включая любые пересылки/репосты). Избегать резких всплесков активности.  
- **X (Twitter)**: Поставить ~50 оригинальных твитов в сутки (для непроверенного аккаунта). Реже 2–3 постов в час. Не превышать **1 пост/минуту** на протяжении 15 мин (условие API) и учитывать дополнительный суточный потолок.  
- **Человеческий паттерн**: нормальное распределение постов по дням; отсутствие тысяч постов в минуту; отсутствие дубликатов и бесконечных одних и тех же коротких твитов/ссылок. Качественный оригинальный контент, перемежаемый личным временем.

# Топ-3 риска и как избежать

1. **Блокировка аккаунта из-за частоты**. Решение: соблюдать щадящий график (см. безопасные лимиты выше), включать случайные паузы, не класть одинаковые тексты подряд. Использовать официальные API вместо чистого скриптинга. Посты с картинками/медиа поменьше (они дольше обрабатываются).  

2. **Отмена прав приложению или API**. Решение: провести официальное App Review (Meta/FB) с правами (pages_manage_posts, etc.) и бизнес-верификацией. Хранить long-lived токены, обновлять их заранее. Постоянно проверять статус доступа приложения.  

3. **Детектировка и капча при скрейпинге**. Решение: если уж используется браузер-автоматизация, то делать её «человечной»: генерировать случайные User-Agent, проксировать или использовать честный IP провайдера, не входить/выходить слишком часто. Минимизировать количество операций (например, оставлять сессию залогиненной). Если появляется капча/2FA, иметь процедуру быстрой ручной разблокировки (через Telegram-уведомление администратору).  

Все рекомендации опираются на официальные ограничения и практику 2025–2026 годов.
