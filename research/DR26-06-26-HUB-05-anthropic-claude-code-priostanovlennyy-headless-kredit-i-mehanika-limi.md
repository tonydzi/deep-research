# Insight (DR DR26-06-26-HUB-05): Anthropic Claude Code: приостановленный headless-кредит и механика лимитов подписки Max/Pro

> Как с середины июня 2026-го должны были измениться (и почему приостановлены) лимиты фонового/headless использования Claude Code, и как реально устроены недельные/сессионные лимиты и расход бюджета по моделям.

## Ключевые выводы
- Anthropic планировала с середины июня 2026 выделить headless-использование в отдельный месячный кредит: $100 для Max-5x, $200 для Max-20x; по заявлению от 15 июня переход приостановлен, реальные лимиты пока не изменились
- Планы Max имеют два недельных лимита — общий (все модели) и отдельный для Sonnet; Pro — один общий лимит
- Действует скользящее 5-часовое сессионное окно, открывается на первом запросе; и `claude -p`, и обычный чат расходуют одно и то же окно
- До 15 июня headless и интерактивные запросы делят один общий пул, разделить вручную нельзя кроме полного перехода на API-ключ
- При исчерпании headless-кредита запросы просто останавливаются с ошибкой (нет автопереключения на более дешёвую модель); дальше работа идёт по платным API-ставкам: $3/$15 за Мток Sonnet, $5/$25 за Мток Opus
- Opus дороже Sonnet примерно в 1.67 раза (не в 5×, как считалось ранее); Haiku стоит ~1/3 от Sonnet
- Ошибка при исчерпании лимита возвращает ненулевой код выхода (наблюдался код 1) и сообщение вида 'Rate limit reached' или 'billing_error'; hook StopFailure ловит это как error_type rate_limit/billing_error
- Порядок выбора модели в Claude Code: флаг --model → переменная ANTHROPIC_MODEL → поле model в settings.json; есть режим 'opusplan' (Opus на планировании, автопереход на Sonnet при исполнении) и fallbackModel-цепочка для отказоустойчивости
- Командные тарифы не консолидируются: у Team-seat headless-кредит $20, у Premium — $100
- Перенос простых задач (классификация, эмбеддинги, суммаризация) на локальные LLM или гибридные прокси (LiteLLM) может сократить расходы в 10× и более

## Рекомендации / решения
- Не устанавливать <key-var> в окружении, чтобы гарантированно тратить квоту подписки через OAuth, а не платный API
- Явно задавать модель для фоновых/автофлот-задач (--model sonnet или settings.json), чтобы экономить бюджет — Opus только там, где нужна интеллектуальная нагрузка (планирование через opusplan)
- Настроить fallbackModel (sonnet,haiku) для отказоустойчивости при перегрузке/недоступности Opus
- Мониторить расход через /status, /usage и веб-панель Usage; распределять тяжёлые задачи на ночные часы
- Повесить hook StopFailure на rate_limit/billing_error для авто-уведомления (например в Slack) или запуска fallback-сценария
- Для масштабных CI/CD задач держать отдельный Console API аккаунт или несколько лицензий (кредиты между аккаунтами не складываются)
- Выносить простые задачи (классификация/эмбеддинги/суммаризация/транскрипция) на локальные модели (Open LLaMA, Qwen, Mistral) через LiteLLM вместо Claude
