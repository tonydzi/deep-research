# Insight (DR DR26-09-24-ZB-01-1922): Plaud (Note/Note Pro/NotePin): интеграция с Claude/Codex/Obsidian-волтом/CRM

> Исследование отвечает, как подключить голосовые рекордеры Plaud (официальные @plaud-ai/cli, @plaud-ai/mcp, платформа platform.plaud.ai и сторонние обвязки) к Claude/Codex, Obsidian-волту и CRM на флоте из 6 машин.

## Ключевые выводы
- Публичного API для своих записей у Plaud нет: поддержка (обновлено 7 сентября 2026) прямо пишет «Plaud does not offer a public API today», «no API key, no waiting list». Вместо ключа — два read-only клиента: CLI `@plaud-ai/cli` и MCP `@plaud-ai/mcp`, GA обоих — 12 мая 2026.
- MCP даёт 7 инструментов: `login`, `logout`, `get_current_user`, `list_files`, `get_file`, `get_note`, `get_transcript` — плюс шесть скиллов-инструкций. Официальные клиенты из коробки: Claude Desktop, Claude Code, Codex Desktop, Cursor, Windsurf, VS Code, Zed, Claude Web, ChatGPT Web.
- Токены хранятся раздельно: CLI — `~/.plaud/tokens.json`, MCP — отдельный `~/.plaud/tokens-mcp.json`, оба в одном каталоге `~/.plaud/`; снос каталога гасит и чат, и робота. Ссылка на скачивание аудио живёт 24 часа — робот обязан скачать файл сразу, сохранённый URL протухнет.
- CLI ищет только по имени записи (не по тексту транскрипта) и только среди 500 последних; список файлов — страницы 1–1000 по 10–100 штук. Коды выхода: 0 успех, 1 аргументы, 2 auth, 3 сеть, 4 таймаут.
- Вебхука «новая запись» для личного аккаунта нет вообще — единственный официальный push это Zapier, и он стреляет только на события «transcripts generated» / «summaries generated», не на загрузку аудио. Для детекта новых записей остаётся только polling.
- Многомашинность не документирована в опасную сторону: срок жизни access/refresh-токена нигде не назван, а единственный официальный совет при ошибке refresh — «удалить tokens.json и войти заново». Общий файл токена через Syncthing на 6 машин опасен: одна машина «починит» токен и сломает остальные.
- Риски: короткие записи (<~200 слов) не запускают автосаммари; согласие на запись Plaud не проверяет («give others a quick heads-up, local regulations differ» — ответственность на пользователе); EU/EEA-аккаунт хранится во Франкфурте под SCC, но HTTP-MCP сервер физически в США; официальные CLI/MCP не запрещены ToS для скриптов и ассистентов — серая зона это неофициальный обратный web API (сторонние тулы сами пишут про риск рейт-лимита/бана).

## Рекомендации / решения
- Для живого чата (ноутбук, Claude Desktop/Code, Codex): официальный stdio MCP — read-only, поддержан, локальный токен.
- Для ночного робота → Syncthing-волт → карточка CRM: один поллер на официальном CLI, на ОДНОЙ бодрствующей машине (VPS после разового `ssh -L 8199`, либо хаб-Windows). Второго поллера не заводить — риск гонки токенов.
- Цикл поллера: раз в 10–15 минут `plaud recent --days 3`, по каждому новому `id` — `plaud file <id>`; если `transcript`/`summary` ещё false — не писать финальную заметку, положить id в очередь и выйти повторным проходом.
- Идемпотентность — по `id` Plaud (не по заголовку, не по имени файла): журнал `id → sha256 тела` рядом с поллером, вне синкаемой папки заметок.
- Токен поллера — только `~/.plaud/tokens.json` на этой одной машине, права 0600, вне волта и вне Syncthing; на остальных пяти машинах этого файла быть не должно. Не копировать токен между машинами «чтобы не логиниться».
- Нативного HubSpot/CRM-коннектора нет — CRM-карточка собирается из заметки волта существующим конвейером «recap → карточка → черновик», а не напрямую из Plaud.

## Открытые вопросы
- Срок жизни (TTL) официального access/refresh-токена CLI/MCP не найден в доке — известно только «при ошибке refresh удали tokens.json и войди снова».
- Можно ли официально держать один refresh-токен параллельно на нескольких машинах — не задокументировано; неофициальные форки называют разные несовместимые сроки (30 дней, ~300 дней), это не перенести на официальный OAuth.
- Лимит запросов в минуту у CLI/MCP не найден.
- Дословный текст пользовательского соглашения `web.plaud.ai/user-agreement` не открылся в этом прогоне (пустая оболочка) — про жёсткий запрет автоматических агентов есть только косвенный сигнал из поискового индекса, цитатой не подтверждено.
- Сравнение качества транскрипции Plaud против self-hosted Whisper large-v3 на официальных страницах не проводится.
