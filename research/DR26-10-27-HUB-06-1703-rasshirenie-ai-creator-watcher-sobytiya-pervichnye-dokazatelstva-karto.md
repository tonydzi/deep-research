# Insight (DR DR26-10-27-HUB-06-1703): Расширение AI Creator Watcher: события, первичные доказательства, карточки знаний и радар

> Как расширить существующий ночной AI Creator Watcher (Telegram, HN, Reddit, X, GitHub, официальные блоги) до событийного конвейера с карточками знаний и релевантностью проектам, и что разрешают условия источников.

## Ключевые выводы
- Решение GO, но как узкое расширение существующего watcher, а не новый агрегатор. Главная проблема: единица отбора сейчас «длинный пост» (порог <2000 символов), а нужна единица «event» (model_release, repo_release, breaking_change, security_advisory, API_change и т.д.). Короткий релиз на GitHub или пост в X ценен как указатель на событие, но не как durable evidence.
- RAG (внешняя непараметрическая память, обновляется без переобучения) технически отличается от обучения весов, но договорные запреты источника могут быть шире обучения. Это ключевое для Telegram.
- Telegram Content Licensing запрещает scraping, indexing, harvesting, aggregation для AI development, enhancement, benchmarking и deployment. Исключение требует индивидуального, явного, информированного и продолжающегося согласия всех relevant users. Публичность канала разрешением не является. Слово RAG в тексте не встречается, поэтому это интерпретация, но индексирование плюс агрегация плюс deployment делают embedding и retrieval высоковероятно запрещёнными. Вердикт: NO-GO для автоматического AI-пути, fail-closed, только ручное добавление первичного внешнего URL.
- Reddit: условно, только discovery после одобрения use case. Data API Terms (ред. 20.07.2026) ограничивают хранение одобренным use case, требуют удалять удалённый контент (рекомендация удалять сохранённое в пределах 48 ч), запрещают ML/AI-обучение на User Content без разрешения; бесплатный eligible OAuth даёт 100 QPM. Применимость к LLM inference/RAG не определена, интерпретация не решена.
- X: только официальный API, scraping и browser automation запрещены, AI/ML-обучение запрещено (кроме Grok). Pay-per-use: Post Read $0.005, User Read $0.010, потолок 3 млн чтений в месяц. Удаление недоступного контента ≤24 ч, при завершении доступа ≤10 рабочих дней. Для 14-дневного пилота при 100/250/500/1000 постов в день это $7 / $17.50 / $35 / $70. Статус RAG-инференса не решён.
- HN (Firebase API, без документированного rate limit, платы нет) и GitHub (releases/tags/advisories, conditional requests, 5000 запросов в час с авторизацией) плюс официальные changelog и RSS дают основную отдачу MVP. Социальные источники только для обнаружения, evidence берётся из первичных.
- Build vs reuse: Miniflux, FreshRSS, RSSHub, n8n, Huginn, Node-RED, changedetection.io решают смежные задачи, а не главный дельта (семантика событий, верификация, релевантность). Рекомендовано: существующий watcher плюс небольшие адаптеры плюс SQLite. RSSHub только как опциональный адаптер для разрешённых сайтов (AGPL-3.0, не обход политик X и Telegram). n8n под Sustainable Use License, FreshRSS AGPL-3.0, Miniflux Apache-2.0 с отдельным PostgreSQL. Графовая БД не нужна.
- Сильнейшее возражение: больше внешней памяти не улучшает решения. Lost in the Middle показывает, что наличие нужных данных в контексте не гарантирует их использование, RAG-Stress (октябрь 2026) показывает, что вводящее в заблуждение retrieval-свидетельство может заменить ранее верный ответ. Поэтому метрики: primary-event recall, precision алертов, false merges, hit@5, реальное переиспользование, а не объём собранного.
- Конвейер состояний DISCOVERED, VERIFIED_EVENT, KNOWLEDGE_CARD, VALIDATED_PRACTICE; последний переход только с одобрением человека или локальным свидетельством. Автоматической установки и принятия нет. Дедупликация иерархическая (id источника, канонический URL, структурный ключ repo+tag или vendor+model+version, затем entity+type+version+окно дат, и лишь потом мультиязычная семантика как кандидат на слияние); пример: v2.1 и v2.10 не сливать.
- Безопасность: внешний контент как враждебный ввод, LLM без инструментов, сети, секретов и записи; строгая схема вывода; импликации помечены как hypothesis, обязательное поле unknowns. Схема SQLite: source, fetch_state, artifact (ревизии, nullable payload_location), event, event_artifact, claim, card, project_relevance. Радар пересчитывает старые карточки при смене fingerprint проекта, повторные алерты подавляются ключом project+fingerprint+card+reason.
- Публичных измеримых метрик самого alpha monitor не найдено (идентификатор DR не соответствует публичному артефакту), поэтому латентность, ошибки, ресурсы и покрытие остаются UNSPECIFIED, а все пороги предложенные, не измеренные.

## Рекомендации / решения
- Не заменять watcher готовым feed-ридером или оркестратором; добавить адаптеры GitHub, HTTP RSS/Atom и HN, затем узкий адаптер X, SQLite durable inbox с транзакционными курсорами и ревизиями.
- Ввести реестр политик источников (allow / discovery_only / block) и жёстко заблокировать Telegram для AI-пути (telegram.ai_ingest_enabled=false), оставив только ручное добавление первичных URL.
- Убрать глобальный порог <2000 символов, заменить правилами по источнику и событию; приёмочный тест: короткий релиз GitHub в 200 символов проходит как событие, а 5000-символьный пересказ новостей без первичной дельты нет.
- Reddit подключать только после одобренного use case, хранить минимум, настроить автоматическое удаление; X использовать через официальный API с лимитом расходов и ограниченным списком официальных аккаунтов (около 20).
- Стартовый список: около 20 GitHub-репозиториев текущих зависимостей, 5–10 changelog вендоров моделей, около 10 инженерных блогов, HN как обнаружение; Reddit отключён до одобрения, Telegram 0.
- Дедупликация по иерархии ключей, уровни доверия P0/P1/D0/D1/D2 вместо псевдоточных чисел, свежесть по классам (immutable_versioned, mutable_current_state, security_sensitive, durable_practice), перепроверка первичного источника при запросах «latest/current».
- Retrieval: жёсткий лексический буст точных имён, версий, URL и CVE, мультиязычный семантический слой, переранжирование по классу доказательств и свежести; радар с fingerprint проектов и подавлением повторов; еженедельный обзор.
- 14-дневный MVP (27.10–09.11.2026) с размеченной выборкой 200–400 кандидатов, ограниченной gold-вселенной для recall, набором 30–50 запросов для hit@5, телеметрией обязательным выходом; предложенные пороги: false merge ≤1%, precision ≥0.80, recall первичных событий ≥0.90, hit@5 ≥0.85, обзор ≤30 мин в неделю.
- Критерии остановки: адаптер отключается при >30 мин/нед обслуживания и <10% переходов в карточки или нарушении гарантий удаления; Day-30 (26.11.2026) заморозка расширения при precision ниже 0.70–0.80 или hit@5 ниже 0.80; Day-60 (26.12.2026) сужение до official primary + GitHub + HN при малом реальном переиспользовании.
- Не отправлять каждый сырой элемент в LLM: порядок raw → детерминированный фильтр → дедупликация событий → первичная верификация → LLM, чтобы 20 репостов давали одну дистилляцию.

## Открытые вопросы
- Распространяются ли Telegram Content Licensing Terms на RAG и inference, а не только на обучение: официального FAQ нет, вывод остаётся интерпретацией.
- Разрешает ли Reddit Data API хранение и использование данных для LLM inference/RAG в рамках одобренного use case.
- Что именно X допускает для inference и RAG (запрет явно касается обучения), нужно ли раскрывать use case.
- Условия лицензирования и хранения у официальных блогов и changelog по каждому сайту отдельно.
- Предельная стоимость LLM (провайдер, модель, цены токенов не заданы) и реальные объёмы потока.
- Базовые метрики существующего watcher (латентность, ошибки, ресурсы, покрытие тестами, инциденты) не измерены и не опубликованы.
- Выбранные пороги (precision, recall, hit@5, false merge, 30 минут обслуживания, пять повторов) предложены, а не подтверждены.
- Отчёт из источника report обрезан (прочитано 51883 из 56191 знаков), финальная часть критериев аварийной остановки по compliance не дочитана.
