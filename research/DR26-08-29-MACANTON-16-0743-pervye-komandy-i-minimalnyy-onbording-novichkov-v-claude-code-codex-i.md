# Insight (DR DR26-08-29-MACANTON-16-0743): Первые команды и минимальный онбординг новичков в Claude Code, Codex и Grok Build

> Ресёрч отвечает, какие проблемы чаще всего возникают у новичков в Claude Code/Codex/Grok Build и какие первые несколько команд и упражнение дать студентам, никогда не пользовавшимся coding-агентами, чтобы «зацепить» их с первой сессии.

## Ключевые выводы
- Точного вендорского датасета частот проблем новичков нет (нет данных типа «23.7% спрашивают про PATH») — ранжирование построено на официальной документации и issue-трекерах, а не на статистике
- Проблемы новичков схожи на всех трёх платформах: запуск не из той папки, PATH/установка, путаница с авторизацией, тревога из-за permission-запросов, расплывчатые промпты, невозможность проверить результат, страх разрушительных правок, замусоренный контекст長сессий
- Ключевая идея: учить не slash-команды, а универсальный цикл Folder → Ask → Plan → Build → Verify → Inspect → Iterate → Recover; переключение между агентами после этого — вопрос названий команд
- Claude Code хорошо подходит для первого урока: есть гайд для тех, кто вообще не пользовался терминалом, `/powerup` (интерактивные демо), plan mode, автоматические чекпоинты, `/rewind`, `/doctor`
- Codex удобен, если аудитория уже пользуется ChatGPT: стартовый экран сам показывает `/init /status /permissions /model /review`; OpenAI формализует структуру промпта Goal/Context/Constraints/Done-when
- Grok Build (не «Grok Code») — отдельный терминальный агент, запущен в мае 2026 и открыт как opensource 15.07.2026; `grok-code-fast-1` — это отдельная модель, вышедшая 28.08.2025; у Grok Build есть plan mode, rewind, компакция контекста, `grok inspect`
- Для первого занятия рекомендуется zero-dependency статичное приложение («My Command Center» на чистых HTML/CSS/vanilla JS с localStorage) — любой фреймворк/зависимость добавляет отдельный домен отказа (PATH, сеть, credentials, sandbox)
- Дефолтные permission-режимы нельзя ослаблять на первом занятии: запрещены Claude bypass-permissions, Grok `--yolo`/always-approve, чрезмерные Codex full-access профили — цель «машина действует, но я контролирую», а не «может всё»
- Верификация важнее удачного промпта: агент должен предоставлять наблюдаемое доказательство (тест, билд, скриншот, diff), иначе он лишь считает работу «выглядящей законченной»
- Обучение восстановлению (Claude/Grok `/rewind`, Codex `/diff` + git-чекпоинты) снимает главный скрытый страх взрослых новичков — «что если робот всё сломает»

## Рекомендации / решения
- Сначала учить ОДИН универсальный workflow (Understand→Plan→Change→Verify→Review→Recover), а не сравнивать три платформы параллельно
- На день 1 давать не более 5-6 команд на продукт (не полный референс), остальное — «набери / чтобы увидеть остальное»
- Использовать шаблон промпта GOAL/CONTEXT/CONSTRAINTS/DONE WHEN как основной паттерн для запоминания студентами
- Первое упражнение — zero-dependency одностраничное приложение без фреймворков/пакетов/API-ключей/аккаунтов
- Заранее установить и авторизовать агент до занятия — установка не имеет демонстрационной ценности
- Явно запретить bypass/yolo/full-access режимы разрешений на первом занятии
- Встроить в первое занятие намеренную демонстрацию «сломай специально → посмотри → откати» через /rewind или /diff
- В конце 1-2 занятия дать упражнение на создание персистентных инструкций проекта (CLAUDE.md/AGENTS.md)
- Не вводить MCP, subagents, hooks, plugins, worktrees, автономные режимы до тех пор, пока студент не отвечает не задумываясь на 6 базовых вопросов (папка/цель/ограничения/проверка/diff/откат)
