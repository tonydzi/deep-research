# A. Executive summary

Anton's `sqlite-graph-memory` pipeline (e5-base embeddings → dense top-60 → optional 1-hop wikilink expansion capped at 40 → cross-encoder rerank → top-12, with an `--ab` telemetry table) is already structurally close to the state of the art for a single-user, SQLite-only, markdown-based memory system. The single highest-leverage, lowest-cost fix is swapping the English-only `e5-base` embedding model for a multilingual one (it currently cannot represent Russian text properly) and moving from flat-file cosine similarity to `sqlite-vec`. The single most defensible terminology finding: call this a **"second memory,"** not a "second brain" — the two terms have different, traceable lineages and Anton's stated goal (compensating real biological memory gaps) matches the "second memory" lineage precisely, not Tiago Forte's "second brain" (a productivity/organizing methodology for people with healthy memory, which Forte himself renamed "Personal Context Management" in 2026).

All findings below come from live web research conducted in this session (GitHub API queries, model cards, papers, benchmark leaderboards fetched 2026-09-16). Every non-obvious claim carries its source URL. Where a number could not be verified, it is marked "not found" rather than guessed.

## Zero-API-cost private eval-set recipe

1. **Wikilink graph as retrieval ground truth (free).** Every hand-placed `B` inside note A is an asserted relevance edge Anton already curated. Take A's title+first paragraph as a synthetic query, mark B as gold-relevant. Score dense-only top-k vs after-graph-expansion top-k separately — the delta is a direct, ground-truth-backed measurement of what the 1-hop expansion step actually buys, replacing eyeballing the `ab_recall` table.

2. **Temporal questions from frontmatter (free).** Anton's own CLAUDE.md §8.4-бис convention (`status`/`valid_from`/`valid_to`/`superseded_by`/`refuted_by`) is a pre-built temporal gold set. For every `superseded_by: X` note, generate "what did I think about `<topic>` before it was superseded?" (gold=old note) and "what's the current view?" (gold=X). This directly tests LongMemEval's hardest category.

3. **Hard negatives from near-duplicates (free, reuses existing embeddings).** Run pairwise cosine similarity once over the e5 vectors already computed by `index_notes.py`; cluster pairs >0.90 as near-dup candidates; use one cluster member as the gold answer and the rest as hard negatives to test whether the reranker actually discriminates near-duplicates rather than just detecting topical relevance ([cluster-aware hard-negative mining](https://arxiv.org/html/2605.24236)).

4. **Synthetic Q&A generation, locally, zero API cost.** Tier 0 (free, deterministic): template questions from frontmatter+headings, no LLM. Tier 1 (local LLM, still zero API $): point RAGAS's [testset generator](https://docs.ragas.io/en/stable/getstarted/rag_testset_generation/) (Headline Extraction/Splitting → persona-driven synthesis) at a local Ollama/llama.cpp model instead of OpenAI; Giskard's `RAGET` does the same pattern.

5. **Scoring `brain_ask.py --ab`, deterministic, zero LLM cost** (formulas per [Pinecone's IR eval writeup](https://www.pinecone.io/learn/offline-evaluation/)): `Recall@k = mean(retrieved_gold/total_gold)`; `MRR = mean(1/rank_of_first_gold)`; `nDCG@k = DCG@k/IDCG@k`. Log `(query, ranked_doc_ids, gold_doc_ids, condition)` next to the existing `ab_recall` table. For faithfulness/answer-correctness (needs generated answer text): RAGAS's [Faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/) = supported-claims/total-claims; [Context Recall](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/) has a free, non-LLM ID-based variant if gold doc IDs already exist from steps 1–3; [Context Precision](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_precision/) — run these as sampled Claude-judged batches (~20–30 queries/run), not continuously.

## 5 highest-priority tests, in order, with targets

1. **Dense-only Recall@10/MRR/nDCG@10 vs the wikilink gold set.** Target: recall@10 > 0.70 as an initial "trustworthy enough to use daily" bar — *loosely calibrated against BEIR/MTEB e5 ranges, not a hard published number for this exact task.*
2. **Graph-expansion delta on the same gold set.** Target: expansion should recover ≥50% of the cases dense-only misses. *Loosely calibrated* — no external benchmark measures this exact operation, but it's the most decision-relevant number (a low recovery rate argues for cutting the graph-expansion step per Anton's own AK-47 rule).
3. **Near-duplicate hard-negative Precision@1.** Target: >0.90 within duplicate clusters ([Shelf.io reports ~80% of production RAG accuracy issues trace to data-quality/duplication](https://shelf.io/blog/10-ways-duplicate-content-can-cause-errors-in-rag-systems/)) — *0.90 is an engineering choice, not benchmark-derived.*
4. **Temporal/knowledge-update accuracy on superseded_by chains.** Target: 60–70% correct — *directly calibrated* against LongMemEval's documented ~30% accuracy drop on this category across the field generally, so a lower bar than other tests is justified here specifically.
5. **Sampled faithfulness/context-recall (RAGAS-style, Claude-judged, ~20–30 queries/run).** Target: faithfulness > 0.85 — higher than typical open-web RAGAS scores (0.6–0.8) because the corpus is hand-curated first-person text, not noisy web sources. *No directly comparable "faithfulness on a personal vault" baseline found — loosely calibrated.*

Upgrade path: **`BAAI/bge-m3`** (same footprint, 8192-token context, MIT, hybrid dense+sparse+multi-vector output as a future poor-man's late-interaction option). If GPU headroom allows: **`Qwen3-Embedding-4B`** (cleanest single-source multilingual MTEB number, 69.45, Apache-2.0, 32k context) — but no RU-specific number exists anywhere for this family, so it's a bet on general multilingual quality, not a verified RU win. Reranker — **`bge-reranker-v2-m3`** (same backbone family as bge-m3, tiny, permissive license); alternative if rerank quality is the actual bottleneck: **`Qwen3-Reranker-4B`** (best cleanly-sourced multilingual number, MMTEB-R 72.74, but 4B vs 0.6B is a real latency/memory cost). Do not default to any Jina model if there's any chance the vault or outputs become commercial — both Jina embeddings and reranker are CC-BY-NC-4.0.

# Q4. Consolidation, forgetting, bitemporal memory

**Zep/Graphiti** ([paper](https://arxiv.org/html/2501.13956v1)): true bi-temporal model, two timelines — `t_valid`/`t_invalid` (real-world validity, LLM-extracted from absolute or relative dates) and `t'_created`/`t'_expired` (transactional/ingestion time). Contradictions are resolved by invalidating the old edge (`t_invalid = new edge's t_valid`) rather than deleting it, so history stays queryable. **Default policy is recency-wins** — the paper states Graphiti "consistently prioritizes new information."

**Mem0** ([paper](https://arxiv.org/abs/2504.19413)): historically used a second LLM call choosing ADD/UPDATE/DELETE/NOOP per candidate fact. As of its documented 2026 pipeline change ([mem0.ai blog](https://mem0.ai/blog/state-of-ai-agent-memory-2026)), it **abandoned LLM-decided UPDATE/DELETE** entirely — now single-pass ADD-only extraction, old and new facts both kept, and "temporal reasoning" happens only at retrieval-ranking time via hybrid semantic+BM25+entity-linking fusion. Reported +20/+26 points on LoCoMo/LongMemEval from this redesign.

**Letta (ex-MemGPT)** ([blog](https://www.letta.com/blog/agent-memory/)): three-tier OS-analogy — core memory (always in context), recall memory (past conversation, searchable), archival memory (cold, embedding-indexed, explicit tool calls only). Its **"sleep-time compute"** feature ([blog](https://www.letta.com/blog/sleep-time-compute/)) runs an asynchronous background agent between conversations to consolidate/dedup/reorganize memory blocks — reported ~5x reduction in test-time compute for equivalent accuracy.

**Cognitive-science-grounded, concretely implemented**: [MemoryBank](https://arxiv.org/abs/2305.10250) (AAAI 2024) is the clearest real implementation — maintains a per-item "memory strength" with Ebbinghaus exponential decay over time, boosted on each recall, computed inline at read time (no separate forgetting job). No production PKM tool implementing FSRS/SM-2-style spaced-repetition *for retrieval prioritization* (as opposed to flashcards) was found — flagged "not found."

**The most directly actionable finding**: [Reddy & Challaram](https://arxiv.org/abs/2606.01435) show that asking a single LLM call to both identify matching facts *and* apply "newest wins" *and* phrase the answer scores at most 54%/7% (single/multi-hop) on MemoryAgentBench's FactConsolidation task — the LLM systematically overrides explicit recency rules with its own world-knowledge prior. **Splitting into (1) LLM evidence-extraction + (2) a separate deterministic policy-execution stage raised accuracy to 82–93%/27–41%**, a +10.8pp average gain from removing the conflict decision from free-text LLM reasoning. A concrete open implementation of exactly this split exists: [memore](https://github.com/bartkamphuis/memore) — deterministic write-time consolidation, no LLM in the recall or decision path, 0.980+ accuracy on the consolidation decision itself (remaining error is subject-name normalization, ~41.7% split-subject rate across paraphrases).

**Portability verdict**: every system above assumes the agent is the sole writer — none has a story for a human hand-editing markdown between agent runs. The one pattern that generalizes cleanly is the **evidence-extraction/policy-execution split** (Reddy & Challaram + memore), because it treats "what changed" as something to (re-)discover by diffing, agnostic to who produced the change.

**Concrete recommended design for the SQLite+markdown vault**:
1. Bitemporal fields per fact row: `valid_from`/`valid_to` (real-world validity, from Graphiti) + `observed_at`/`superseded_at` (when the vault recorded it, from Graphiti) + `source_path`/`source_kind` (`human_edit`|`agent_write` — from Eywa/TOKI's provenance insistence). This is the field that matters most here: set **human-edit-wins-regardless-of-timestamp** as the default, explicitly the opposite of Graphiti's recency-wins, since Anton's trust model is inverted (humans outrank the agent).
2. Never let an LLM decide supersession — deterministic `(subject_key, valid_from, source_kind)` comparator, LLM only for off-path extraction (memore/Reddy-Challaram pattern).
3. Nightly batch job, not real-time (Letta's sleep-time-compute shape): diff notes by mtime, re-extract only changed ones, run the comparator, flag (don't auto-resolve) genuine human-vs-human contradictions.
4. Optional Ebbinghaus-style decayed "strength" (MemoryBank) as a retrieval-ranking nudge only — never as a deletion trigger, since a hand-written note's mere existence is a deliberate human signal.

# Q5. Terminology: "second brain" vs "second memory"

**Traced lineage** (all primary/secondary sources fetched live):
- **Vannevar Bush's Memex** (1945, "As We May Think") — explicitly "an enlarged intimate supplement to [one's] memory": associative-trail storage/retrieval, not autonomous thought. [Wikipedia: As We May Think](https://en.wikipedia.org/wiki/As_We_May_Think), [Wikipedia: Memex](https://en.wikipedia.org/wiki/Memex).
- **Bell & Gemmell's MyLifeBits** (MSR, from 1998) — "a lifetime store of everything," MSR's own page states it "fulfills Vannevar Bush's 1945 Memex vision." Follow-on book *Total Recall* (2009) coins "e-memory" for digitally-recorded life data, explicitly complementary to "bio-memory," not a replacement for thinking. [MyLifeBits — Microsoft Research](https://www.microsoft.com/en-us/research/project/mylifebits/), [Total Recall — Goodreads](https://www.goodreads.com/book/show/6712783-total-recall).
- **Clark & Chalmers, "The Extended Mind"** (1998) — the Otto/notebook thought experiment: an external store that is reliably accessible, trusted, and habitually consulted is *literally part of the cognitive/memory system*, via the "parity principle." Directly supports calling a reliable external store genuine memory, without implying it does the thinking. [Paper PDF](https://wmit-pages-prod.s3.amazonaws.com/wp-content/uploads/sites/283/2022/06/12151103/extended.pdf).
- **Wegner's transactive memory** (1985) — groups externalize memory to other people via "who-knows-what" metamemory; a pre-digital precedent for legitimate memory externalization, weaker analogy than Clark & Chalmers since it's person-to-person, not person-to-machine. [Wikipedia](https://en.wikipedia.org/wiki/Transactive_memory).
- **Tiago Forte's "Building a Second Brain"/PARA** — Forte's own words: a "factory that helps you turn ideas into concrete results," **not** a warehouse for storage; assumes a healthy memory, targets project/creative output. Notably, **Forte himself renamed the discipline "Personal Context Management" in 2026**, reasoning the bottleneck moved from capture to context-curation for AI. [Forte Labs](https://fortelabs.com/blog/basboverview/), [PARA method](https://www.buildingasecondbrain.com/para), [rename discussion](https://amirelion.com/blog/what-is-second-brain-personal-context-management).
- **Zettelkasten** (Luhmann) — explicitly "a personal tool for thinking and writing," "emphasize connection, not a collection" — the clearest existing precedent for "thinking tool ≠ memory-storage tool." [zettelkasten.de](https://zettelkasten.de/introduction/).
- **"Exocortex"** — coined by Ben Houston (1999) as "a synthetic regulator of high-level thought... to keep goals stable while thought was happening" — more agentic than pure storage. Picked up as a literal 2025-2026 project name (e.g. [ghosoya/exocortex](https://github.com/ghosoya/exocortex), a 2026 PMC scientific-expedition paper), but usage genuinely spans "just a memory server" to "active thinking partner" — doesn't cleanly map to storage-only. [Origins of Exocortex — Ben Houston](https://ben3d.ca/blog/origins-of-the-term-exocortex).
- **"Memory prosthesis"/"cognitive prosthesis"** — a real, established clinical/HCI term for devices compensating for genuine memory impairment (dementia, TBI): CAPTAIN MEMO, CIRCA, [PubMed 23957379](https://pubmed.ncbi.nlm.nih.gov/23957379/), [2026 PMC paper](https://www.ncbi.nlm.nih.gov/pmc/articles/PMC12500313/). This is the etymologically most honest match to Anton's stated motivation (real biological gaps), but hasn't crossed into mainstream AI-agent branding.
- **"Personal knowledge graph"** — the term academic 2025-2026 papers ([PersonalAI, arXiv 2506.17001](https://arxiv.org/abs/2506.17001); [Memory in the Age of AI Agents survey, arXiv 2512.13564](https://arxiv.org/abs/2512.13564)) actually converge on as a precise architecture-level label, explicitly distinguished from "reasoning."
- **"Digital twin"/"AI clone"** (2025-2026) — denotes something categorically broader: voice/face/personality replication and autonomous action, per current usage ([Spectrum News](https://spectrumnews1.com/oh/columbus/news/2026/02/26/digital-doubles----the-promise-and-peril-of-ai-twins), [CES 2026 coverage](https://euronews.com/next/2026/01/07/ai-software-that-can-create-digital-clones-of-employees-unveiled-at-ces-2026)) — too broad, implies capabilities the system doesn't have.

**Synthesis**: "second memory" is the more precise, defensible term for Anton's system — it sits in a real, citable lineage (Bush → Bell/Gemmell → clinical memory-prosthesis literature → Clark & Chalmers' philosophical justification) that is specifically about storage+retrieval compensating for real gaps. "Second brain" (Forte's dominant usage) denotes an organizing/creative-production layer for someone with a *healthy* memory — a different, narrower problem than Anton's. **The field is genuinely not converged** on one term for LLM-based personal memory in 2025-2026: academic papers lean "agent memory"/"personal knowledge graph"; product marketing still overuses "second brain" loosely, though some 2026 practitioners are explicitly self-correcting (one source calls a system "more accurately described as a structured external memory layer" than a second brain — [orbitant.com, cited via terminology-agent research](https://amirelion.com/blog/what-is-second-brain-personal-context-management)); "exocortex" and "memory prosthesis" remain minority/niche terms with different connotations (too agentic, or too clinical/unfamiliar, respectively).

**Recommendation**: call it a **"second memory"** — or, more technically, a **"personal memory / knowledge-graph system"**; reserve **"memory prosthesis"** for contexts wanting maximum honesty about compensating a real impairment. Avoid "second brain" (overclaims organizing/creative agency it doesn't have) and "digital twin"/"exocortex" (both overclaim autonomous thinking/action) unless the system later grows a genuine decision-making layer.

## Russian glossary

1. **Вторая память (second memory)** — хранилище + ассоциативный поиск, компенсирует реальные провалы биологической памяти; не думает и не решает за тебя. Рекомендуемый термин.
2. **Второй мозг (second brain, Tiago Forte)** — методология организации проектов (PARA) для человека со здоровой памятью; сам Forte в 2026 переименовал это в «Personal Context Management».
3. **Экзокортекс (exocortex)** — термин трансгуманизма (Ben Houston, 1999): внешний регулятор мышления, претендует на бóльшую автономность, чем обычное хранилище.
4. **Протез памяти / когнитивный протез (memory/cognitive prosthesis)** — клинический термин для технологий, компенсирующих нарушенную память (деменция, ЧМТ) — самый честный аналог задачи Антона.
5. **Трансактивная память (transactive memory, Wegner, 1985)** — вынос памяти на другого человека/группу; предшественник идеи выноса памяти на машину.
6. **Расширенное сознание (extended mind, Clark & Chalmers, 1998)** — если внешнее хранилище так же надёжно и привычно, как биопамять, оно является частью когнитивной системы, а не просто инструментом.
7. **Персональный граф знаний (personal knowledge graph)** — актуальный технический термин 2025-2026 для архитектуры LLM+RAG+структурированное хранилище, без claims об автономном мышлении.
8. **Цифровой двойник / AI-клон (digital twin/AI clone)** — воспроизводит человека целиком (голос, манера решений) и действует от его имени; категорически больше, чем хранилище+поиск.

# Q6. What usually breaks in personal RAG, and cheap nightly diagnostics

| Failure mode | Citation | Nightly diagnostic |
|---|---|---|
| Chunking splits meaning across boundaries | ["retrieves step 6 without steps 1-5"](https://medium.com/@visrow/contextual-chunking-for-rag-solving-context-loss-and-anaphoric-reference-problems-ae45d3c21480); [2026 chunking playbook](https://www.digitalapplied.com/blog/rag-chunking-strategies-2026-retrieval-quality-playbook) | Fixed probe set of notes whose answer sentence sits near a heading/chunk boundary; compare recall@1 against a matched mid-chunk control set; flag if boundary set trails by >15pp |
| Stale index after edits | [Oracle blog: 90%→65% accuracy drop from silent staleness](https://blogs.oracle.com/developers/how-to-detect-rag-index-drift-deleted-docs-stale-chunks-and-duplicate-embeddings); [index-staleness gap](https://ranjankumar.in/rag-engineering-index-staleness-gap) | Compare file `mtime` vs `indexed_at` (flag >24h drift) **and** sha256 content-hash vs index-time hash (catches edits that don't bump mtime, e.g. git checkouts) — mirrors Anton's own `output_freshness.py` pattern |
| Duplicate/near-duplicate notes | [~80% of production RAG accuracy issues trace to data-quality/duplication](https://shelf.io/blog/10-ways-duplicate-content-can-cause-errors-in-rag-systems/); [byte-exact dedup analysis](https://arxiv.org/pdf/2605.09611) | Nightly pairwise cosine sim on existing e5 vectors (no re-embed cost); flag pairs >0.97; feed the >0.90 cluster set into the hard-negative eval from Q2 |
| Link rot | [Wikipedia: link rot](https://en.wikipedia.org/wiki/Link_rot); [obsidian-broken-links-cleaner](https://github.com/sarwarkaiser/obsidian-broken-links-cleaner) | Parse every `wikilink`, resolve against filename/alias index, flag unresolved targets and zero-incoming-link orphans |
| Mixed-language query/corpus mismatch | [Cross-lingual retrieval bias](https://zeroentropy.dev/concepts/cross-lingual-retrieval/); [measured bias in Arabic-English RAG](https://arxiv.org/pdf/2507.07543) | Fixed bilingual note-pairs (same fact in RU and EN); run RU query and EN-paraphrase query, log which language wins top-1/top-5; flag systematic same-language bias >20pp |
| Entity-seeking vs topic-seeking queries | [Dense retrievers underperform on entity-centric questions](https://www.researchgate.net/publication/354696323_Simple_Entity-Centric_Questions_Challenge_Dense_Retrievers); [entity retrieval formalization](https://arxiv.org/pdf/2408.02795) | Two fixed probe sets (exact names/tools vs broad topics); track recall@10 per slice separately; if entity-slice trails topic-slice by >20pp, add a BM25/exact-match fallback for entity-shaped queries (ties directly to Q1's mem0-style FTS5 fusion idea) |
| Graph over-expansion/noise | [GraphRAG multi-hop noise dilution](https://hidekazu-konishi.com/entry/graphrag_architecture_on_aws_neptune_bedrock.html); [query-aware spreading activation](https://arxiv.org/pdf/2606.30133) | Log per-query "graph-expansion survival rate" = survivors-into-final-top-12 / proposed-candidates (up to 40 cap); if chronically <10%, skip expansion through high-backlink "hub" notes rather than raising the cap |
| Reranker over-weighting titles | [Title-bias inconsistency across benchmarks](https://arxiv.org/pdf/2304.12904); [practitioner request for title-aware reranking](https://github.com/prasadtalasila/chitragupta/issues/786) | Run the reranker twice on known-good pairs (with vs without title/frontmatter in passed text); if stripping the title causes a large consistent rank drop, the reranker is leaning on title-matching — a specific risk given how many vault note titles are generic `reglament-*` slugs |

1. **Switch `e5-base` → `multilingual-e5-large` in `index_notes.py`, full reindex.** Highest-leverage single change: the current model cannot properly represent Russian text at all. Same MIT license, same prefix convention, drop-in.

4. **Migrate flat `.npy`/`.pkl` cosine search to `sqlite-vec`'s `vec0` virtual table.** Removes the scaling ceiling, keeps the single-SQLite-file architecture, ~4-8 hours.
5. **Add mtime+sha256 index-staleness diagnostic (Q6 #2) as a nightly job.** Directly analogous to the existing `output_freshness.py` pattern — cheap to build, catches silent 90%→65%-style accuracy decay before it's noticed by eye.
6. **Add the near-duplicate cosine-cluster diagnostic (Q6 #3), reusing existing embeddings.** Feeds both a nightly dedup-candidate list and the hard-negative eval set (Q2 test #3) from one computation.
7. **Reconsider the reranker: swap in `bge-reranker-v2-m3` (or benchmark `Qwen3-Reranker-4B` if latency budget allows) and re-run test #1 to see if recall changes.** Cheap to A/B since it only touches the top-40→top-12 step.
8. **Build the temporal gold set from existing `superseded_by`/`valid_from`/`valid_to` frontmatter (Q2 test #4) and score it.** The metadata convention already exists per CLAUDE.md §8.4-бис — this is pure scoring work, no new data collection.
9. **Add bitemporal fields (`valid_from`/`valid_to`/`observed_at`/`superseded_at`/`source_kind`) to the fact/edge schema, with human-edit-wins as the default conflict policy.** This directly extends the pipeline's own already-planned `docs/bitemporal.md` roadmap item, informed by Graphiti's schema and the human-edit-wins correction to its recency-wins default.
10. **Pilot HippoRAG-style Personalized PageRank as a replacement for the fixed 1-hop/40-cap entity-gate heuristic**, scored against test #2's baseline. Highest engineering cost on this list, so sequenced last — but has the clearest theoretical upside for the graph-expansion step specifically.
