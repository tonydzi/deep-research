# Insight (DR DR26-11-01-HUB-06-1441): Mixedbread mgrep как переносимый облачный fallback к CodeIndexer (Windows/Mac)

> Можно ли использовать @mixedbread/mgrep 0.1.13 / Mixedbread Search как ограниченный приватный облачный семантический fallback к CodeIndexer на Windows, Intel Mac и Apple Silicon, не ломая точность, свежесть, приватность и стоимость.

## Ключевые выводы
- Нативный mgrep CLI 0.1.13 привязан к абсолютному локальному пути: при загрузке absolute filePath идёт и в external_id, и в metadata.path, а поиск жёстко фильтрует metadata.path starts_with <process.cwd()/путь>. Хранилище, заполненное на Windows (C:\...), с macOS (/Users/...) вернёт пусто. Флага или env для отключения фильтра нет. Это подтверждено исходниками (search.ts, utils.ts), а не только наблюдаемым сбоем на Mac.
- Один приватный стор с переносимой схемой (repo_id, revision, relative_path, file_hash) возможен без форка, но только через официальный Mixedbread SDK/API, а не через CLI. API поддерживает произвольный external_id, метаданные, составные фильтры (eq/in/starts_with/regex, all/any/none); документация сама рекомендует path-подобные external_id вроде docs/api/authentication.md. Нужен тонкий адаптер в обычном shell, запрос фильтруется по repo_id==… AND revision==….
- Свежесть в нативном CLI ненадёжна: при локальном mtimeMs <= сохранённого хэш не считается, поэтому checkout/копия с изменённым содержимым без роста mtime оставляет облачную копию устаревшей. Нет измерения revision/repo_id: один абсолютный путь на разных ревизиях перезаписывает один объект стора; два клона на разных ОС выглядят разными файлами.
- Приватность не закрыта: Terms говорят, что данные Free Tier (запросы и входы) могут использоваться для обучения моделей и хранятся бессрочно, а Privacy Policy и страница Security утверждают, что данные Free Tier не используются для обучения (Security: «никогда, ни для какого плана»). Противоречие первоисточников зафиксировано в открытом issue #145 (с 2026-04-14). Приватный стор (is_public=false по умолчанию) этого не снимает; платный тир однозначно без обучения. Регион по умолчанию US, EU «скоро».
- Проект в режиме поддержки: v0.1.13 (2026-04-25, коммит 5c1ba62) совпадает с npm latest, новых релизов нет ~6 месяцев, при этом открыто 44 issue. Критичные: #149 (600+ осиротевших mgrep watch, ~8 ГБ RAM, своп), #148 (хук SessionStart пишет всё окружение с API-ключами в world-readable /tmp/mgrep-watch.log), #147, #151 (SIGKILL по переиспользованному PID), #132 и другие Windows-поломки (os.setsid), #27/#110 PR для Windows висят открытыми. Агентные установщики (install-claude-code/install-codex) и watcher использовать нельзя.
- Официальной матрицы ОС/архитектур нет, package.json без engines/os/cpu (в контрибьюторских доках Node 18+, pnpm 8+); поддержка Windows x64 / Intel Mac / arm64 формально не заявлена. Облачная часть закрытая, self-hosted сервера нет (issues #150, #138 без ответа), CLI онлайн-only.
- Цены (на 2026-11-01): семантический поиск $4/1K (+$3.50 rerank, rerank по умолчанию в mgrep → $7.50/1K), индексация fast $1.50/1M токенов (HQ $3), хранение $0.50/1M токенов в месяц; Starter $5 разово, Scale $20/мес с $20 кредитов. Метрики использования отстают до 10 минут, допускаются «небольшие овердрафты»; жёсткий лимит расходов не документирован (в changelog заявлены Spending Limits, поведение не проверено), поэтому нужны собственные дневные счётчики вызовов в адаптере.
- Пользы по ресурсам (RAM/CPU/GPU, латентность, точность, стоимость) не доказано: прежний прогон на 40 ответов невалиден (ноль успешных вызовов mgrep), заявление вендора о ~2x меньше токенов (50 задач, LLM-судья, самоизмерение) не независимое, а каждый вызов всё равно поднимает локальный Node-процесс. Чистая выгода доказуема только контролируемым бенчмарком.
- Вердикт ног расходится по градации, но сходится по сути: PARK для нативного CLI как кросс-ОС слоя; TRY только как SDK-адаптер-канарейка под предзаданными порогами и гейтами (приватность, свежесть, ревизия, польза). Если приватность аккаунта нельзя однозначно подтвердить без смены тира или аккаунта, статус PARK.

## Рекомендации / решения
- Не принимать нативный mgrep CLI как общий кросс-ОС fallback; оставить установленным, но не использовать как слой переносимости.
- Если идти дальше: тонкий адаптер на официальном SDK, пишущий relative_path, repo_id, revision, file_hash и запрашивающий с обязательным repo_id==… AND revision==…; исходник читать обратно из локального git-объекта revision:rel_path.
- Не запускать mgrep install-claude-code / install-codex и не держать постоянные watcher'ы; вызывать только как обычную shell-команду с триггером при явной неудаче или неоднозначности CodeIndexer (CodeIndexer первым), с жёсткими лимитами topK, размера сниппета, таймаута, ретраев и числа вызовов на задачу.
- Перед загрузкой проприетарного кода пройти гейт приватности: подтвердить, что организация под Paid-тиром или контрактом, снимающим противоречие Terms/Privacy; иначе PARK.
- Канарейка обратимая: одноразовый (disposable) стор, ключ API с правами только на поиск, жёсткие дневные счётчики вызовов, токенов и расходов, закрепление версии (npm-хэш или git-тег v0.1.13, а не main).
- Закрепить пороги KEEP/TRY/PARK заранее и провести контролируемый бенчмарк, учитывающий реально доставленный контекст, успешные вызовы и атрибутируемые списания; перенос нагрузки между своими хостами экономией не считать.
- На одноразовых копиях протестировать неразобранные случаи: Unicode, регистр, разделители путей, одинаковые basename, чужие клоны и ревизии, rename/delete без удаления по одному лишь локальному отсутствию файла.

- Какие именно условия (Free или Paid/контрактные) действуют для существующей организации и как первоисточники разрешают противоречие Terms/Privacy в реальной практике.

- Реальное поведение на Unicode, регистре, разделителях, одинаковых basename и мульти-клонах не проверено публично.
- Работают ли заявленные Spending Limits и нет ли жёсткого лимита расходов; насколько велики овердрафты и лаг метрик.
- Даст ли облачный fallback реальную экономию RAM/CPU/GPU с учётом локальной синхронизации и Node-процесса, и сохранится ли точность на RU/EN; цифры вендора независимо не подтверждены.
- Формальная поддержка Windows x64, Intel Mac и Apple Silicon для версии 0.1.13 не опубликована; минимальная версия Node неясна (нет engines).
