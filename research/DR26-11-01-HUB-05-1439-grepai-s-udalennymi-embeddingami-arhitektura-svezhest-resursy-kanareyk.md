# Insight (DR DR26-11-01-HUB-05-1439): grepai с удалёнными эмбеддингами: архитектура, свежесть, ресурсы, канарейка

> Стоит ли добавить grepai v1.2.0 (yoanbernabeu/grepai) с удалёнными облачными эмбеддингами как опциональный инструмент по запросу в рабочий процесс CodeIndexer-first на Windows Hub, Intel Mac Pro и Mac Studio.

## Ключевые выводы
- Идентичность подтверждена: продукт yoanbernabeu/grepai (Go CLI с MCP, лицензия MIT), 'GroupEye Cloud' не найден ни в одном поиске и считается ошибкой диктовки. Актуальный стабильный релиз v1.2.0 от 2026-10-30, коммит релиза d86397d5f0c94ea31b96d1bb8b4da6966e26f5ef, требуется Go 1.25.5. Вендоры расходятся в SHA (Gemini называет dd38459, GLM называет HEAD main 9cf58bf), это нужно сверять через git ls-remote. Документация частично устарела: на одной странице написано v1.2.0, на другой v1.1.0.
- Официального хостед-сервиса grepai нет. «Облако» означает только сторонние API эмбеддингов (OpenAI, OpenRouter, Synthetic, Requesty). Фрагменты кода (с префиксом 'File: <path>') и каждый поисковый запрос уходят провайдеру. Векторы, символы и граф вызовов остаются локально в .grepai/index.gob и symbols.gob, если не подключить свой Postgres/pgvector или Qdrant.
- Удалённые эмбеддинги снимают CPU/GPU-нагрузку от Ollama/LM Studio, но не RAM и диск: GOB-бэкенд при каждом поиске загружает и сканирует весь индекс. Автор измерил около 1.2 ГБ пика RAM и ~0.5 с на поиск при 54 610 чанках (индекс 494 МБ, 768 измерений). Модель с 1536 измерениями по умолчанию у OpenAI удваивает размер, 3072 даёт ×4. Источник замера один (автор).
- Стоимость эмбеддингов ничтожна: text-embedding-3-small стоит $0.02 за 1M токенов ($0.01 в Batch), то есть 1M токенов кода около $0.02. Но это измеряемый API-расход. ChatGPT Plus кредитов на API не даёт, Pro и Business дают ($100/$200/$500 в месяц). Подписки Claude, Cursor, Codex эмбеддинг-кредитов не включают. Synthetic заявляет эмбеддинги без доплаты внутри платной подписки. Без существующего баланса или подписки нулевого нового расхода нет, и решение превращается в PARK.
- Режим 'precise' (tree-sitter) никогда не был подключён к индексации, релизные бинарники собираются без CGO, запрос на его включение закрыт как 'not planned' 2026-10-30. Граф вызовов строится регулярками и объединяет одноимённые символы. Пример: в PHP issue #212 для 'execute' найдено 640 посторонних callee. Это синтаксическое приближение, не уровень LSP. PowerShell (.ps1/.psm1) не индексируется и не трассируется, Python/JS/TS поддерживаются полноценно.
- Секреты не защищены по умолчанию: .env входит в индексируемые расширения, список ignore содержит только каталоги сборки, сканера секретов нет. Защищают только .gitignore, .grepaiignore, список ignore и лимит файла 1 МБ. С облачным эмбеддером всё неисключённое уходит наружу. В v1.2.0 исправлена уязвимость: ключи из окружения теперь отправляются только на официальные эндпоинты, а в доках добавлено предупреждение об индексации недоверенных репозиториев. В pkg.go.dev у v1.2.0 есть пометка GO-2026-6125 (unreviewed, CVE-2026-11479, связана с перезаписью общей Qdrant-коллекции) и GO-2026-6128, актуальность для v1.2.0 не проверена.
- Свежесть: однократный 'grepai index' существует с v0.39.0 (2026-10-25), вотчер не обязателен. Неизменённые чанки переиспользуют векторы с v1.0.0, переименования заново эмбеддят с v1.2.0. Ретраи с экспоненциальным backoff, token-bucket по TPM и настраиваемый parallelism есть в OpenAI-адаптере (parallelism 4, таймаут 60 с, до 5 попыток, лимит батча 2000 входов), а у OpenRouter, Synthetic и Requesty такой же устойчивости не подтверждено.
- Заявленное автором сокращение токенов на 97% не годится как доказательство для нашего флота. Это бенчмарк мейнтейнера на одном TypeScript-репозитории с пятью вопросами автора. Он мерил только свежие input_tokens (около 3.8% стоимости), реальная экономия стоимости составила 27.5%, cache-read вырос на 30%, качество ответов не измерялось. Для подписочных планов долларовой экономии нет.
- Проект очень молодой и быстро меняется: v0.38.0 (24.10), v0.39.0 и v1.0.0 (25.10), v1.1.0 (26.10), v1.2.0 (30.10), около 1.9k звёзд, 46 контрибьюторов. Открытые на Windows проблемы: скачки RAM на несколько ГБ при индексации (#361) и взаимная блокировка вотчера при backpressure эмбеддера (#355), оба не исправлены в v1.2.0. Они относятся к вотчеру и Ollama и ослабляются режимом one-shot.
- Вердикты вендоров разошлись: GPT и Claude рекомендуют TRY только как узкую канарейку с бюджетным гейтом (иначе PARK), GLM рекомендует TRY на двух macOS-машинах и PARK для Windows Hub. На практике канарейка заблокирована: живой ключ OpenRouter на 17:16Z имел остаток 0 при дневном лимите $15, измерения продукта не проводились. Это операционная блокировка, а не провал продукта. Кворум источников 4 из 6 принят с поправками (GPT, Claude, Mistral, Grok), Gemini отклонён, у GLM поиск не подтверждён, хотя технически 6/6 ног собраны.

## Рекомендации / решения
- Решение TRY только как узкая предрегистрированная канарейка: однократный 'grepai index', без вотчера, без MCP, без глобальных конфигов, один запечатанный снимок Python/JS/TS, на Windows Hub для Claude Code с чтением результата на Mac Studio. GLM советует начать на двух macOS-машинах и держать Windows Hub в PARK до исправления #361 и #355.
- Закрепить в канарейке релиз v1.2.0 (SHA d86397d5…), а не движущийся main, и перед установкой проверить тег через 'git ls-remote https://github.com/yoanbernabeu/grepai refs/tags/v1.2.0'.
- Не запускать канарейку, пока не доказан существующий разрешённый остаток: предоплаченный кредит API, ChatGPT Pro/Business API-кредиты, подписка Synthetic или явная авторизация небольшого капнутого баланса. Без этого автоматически PARK. Не поднимать капы, не заводить новые ключи и не искать обходов.
- Использовать модель text-embedding-3-small и OpenAI-адаптер как наиболее устойчивый вариант, оценить риск с Synthetic (нативный провайдер есть в config.go v1.2.0, но Gemini ошибочно утверждал обратное).
- Для корпуса использовать новый общий публичный набор из 5 файлов (v0.5 DRAFT, без JS/TS) с cloud_upload_allowed=false до принятия методики; старый корпус из 15 файлов остаётся только локальным (privacy BLOCK). Исключить .env и секреты через .grepaiignore, никакие реальные секреты, куки, ключи и конфиденциальные данные третьих лиц в облако не отправлять.
- Не использовать утверждение о 97% как аргумент, а измерять локально: полные входные токены, качество ответов, RAM/CPU/диск/сеть, с фиксированными 24 задачами и независимыми акторами. Для оценки графа вызовов взять запечатанные фикстуры с неоднозначными символами и динамической диспетчеризацией и сравнить с LSP.
- Перед установкой проверить, касаются ли GO-2026-6125 и GO-2026-6128 версии v1.2.0, и не индексировать недоверенные репозитории.

## Открытые вопросы
- Какой именно SHA у тега v1.2.0 и что сейчас в HEAD main: вендоры называют d86397d5…, 9cf58bf4… и dd38459, тег напрямую не прочитан.
- Касаются ли GO-2026-6125 (unreviewed, без фиксированной версии) и GO-2026-6128 версии v1.2.0, содержимое второй записи не прочитано.
- Есть ли у нас реальный разрешённый остаток эмбеддингов: у существующего ключа OpenRouter остаток 0, состояние других провайдеров, ChatGPT Pro API-кредитов и подписки Synthetic неизвестно.
- Как grepai ведёт себя на практике по RAM, CPU, диску, сети и токенам: независимых замеров в источниках нет, есть только единичный замер автора (около 1.2 ГБ на 55k чанков).
- Подтверждаются ли на Windows проблемы #361 (скачки RAM) и #355 (deadlock вотчера) в режиме one-shot без Ollama.
- Покрывает ли OpenRouter ZDR эмбеддинг-запросы: прямого заявления об исключении нет, трактуется как inference.
- Применимы ли RAM и размер GOB-индекса при реальных размерах наших репозиториев и при 1536 измерениях, где индекс удваивается.
- Насколько качество поиска и графа вызовов (regex вместо LSP) достаточно для наших задач, и каков реальный выигрыш по сравнению с CodeIndexer, сравнение не проведено.
- Остаётся открытой ограниченность методики канарейки: границы запросов (R5 request bounds), метод v0.4, формулировка общего корпуса v0.5 не приняты, статус REVISE.
- Часть ног отклонена или не подтверждена: Gemini отклонён, у GLM поиск не подтверждён, остались расхождения (инверсия переименования, непроверенный вывод по статусу issue, конфликт протоколов, дрейф дат).
