# Insight (DR DR26-06-26-HUB-03): Сравнение каналов связи и надёжность межагентной коммуникации между машинами Антона

> Какой канал связи (Syncthing, Telegram, SMTP, Gmail API) выбрать как основной/резервный между агентами-Claude на разных машинах, и как обеспечить надёжность (heartbeat, идемпотентность, безопасность) при минимальной сложности.

## Ключевые выводы
- Syncthing — быстрый локальный P2P-канал, но отказывает при разрыве сети между машинами или конфликте папок; зависит от корректной работы самого демона.
- Telegram-бот — хороший резервный канал через интернет, удобен для человека (видна переписка агентов), но зависит от доступности сервиса Telegram и имеет ограничения на размер/скорость сообщений.
- SMTP через Gmail (App Password) — самый простой email-канал: лимит 500 писем/сутки, минимум внешних компонентов, легко диагностировать; рекомендован как стартовый вариант (AK-47).
- Gmail API — более мощный (до 2000 писем/сутки для Workspace, OAuth2 без статического пароля), но требует настройки Google Cloud проекта и OAuth-согласия — избыточная сложность для семейной установки из 4 машин.
- Рекомендуемая цепочка автопереключения: Syncthing → Telegram → email, с таймаутами значительно больше периода heartbeat, чтобы избежать ложных срабатываний.
- Идемпотентность через уникальный message_id (UUID/nonce): получатель хранит историю обработанных ID и отбрасывает дубликаты, что защищает от двойного исполнения команд при переключении каналов.
- Heartbeat/dead-man-switch: агенты шлют 'alive' каждые N секунд (пример: 2 мин), таймаут отказа = 2–3× интервала (пример: 6 мин), нужно 2–3 подряд пропущенных пинга перед эскалацией сбоя.
- Безопасность: Ed25519-подпись сообщений + nonce/timestamp защищают от подделки и replay-атак; для 4 доверенных машин в локальной сети полноценный PKI/mTLS и постоянная ротация сертификатов признаны избыточными.
- AK-47 чек-лист внедрения: (1) резервные каналы + автопереключение, (2) уникальные ID/идемпотентность, (3) heartbeat-мониторинг, (4) тестирование отказа канала, (5) опционально — простая подпись/sender_id/nonce.

## Рекомендации / решения
- Начать с SMTP+App Password (smtp.gmail.com, порт 587) как самого простого резервного email-канала; переходить на OAuth2/Gmail API только если Google отключит App Password для аккаунта.
- Не разворачивать n8n или полноценный Gmail API ради простой отправки почты между 4 семейными машинами — это overhead без необходимости.
- Настроить цепочку автопереключения Syncthing → Telegram → email с таймаутами, заметно превышающими интервал heartbeat.
- Реализовать генерацию UUID/message_id для каждого сообщения и хранить историю принятых ID для дедупликации.
- Настроить heartbeat каждые ~2 минуты с таймаутом отказа ~6 минут (3× интервала) и требованием 2–3 подряд пропущенных пингов перед эскалацией.
- На старте можно опустить полноценные подписи, но минимально сравнивать sender_id в каждом сообщении; при наличии времени — добавить Ed25519-подпись и nonce-защиту от replay.
- Не внедрять PKI/mTLS, VPN/TOR и сложные схемы ротации ключей — признано избыточным для локальной сети из 4 доверенных машин.
