Сверяю живые документы Grok и Cursor по классу инструментов, полке правил, лимитам и приватности.A. Архитектурный класс

Это не один инструмент в двух упаковках. На 22 сентября 2026 у «Grok» три разных поверхности, а у Cursor две, и только одна пара из них одного класса.

Grok Build CLI — локальный агент в терминале. Анонс 25 мая 2026: ранний бета для подписчиков SuperGrok и X Premium Plus, установка `irm https://x.ai/cli/install.ps1 | iex`, plan mode, чужие AGENTS.md / skills / hooks / MCP, субагенты в worktree, headless `-p`, ACP. Источник: https://x.ai/news/grok-build-cli. Документация headless, открытая в этом прогоне: `grok -p`, форматы `plain` / `json` / `streaming-json`, `--always-approve`, `--session-id`, `--resume`, `--cwd`, `--no-auto-update` для CI. ACP: `grok agent stdio`. Источник: https://docs.x.ai/llms-full.txt (раздел Headless & Scripting). Это тот же класс, что Claude Code и Codex CLI: процесс на машине, диск этой машины, без GUI, ночной будильник может его спавнить.

Grok Bot — другой продукт. Официальный обзор, обновлён 18 сентября 2026: бот работает сообщениями и голосом, у каждого бота есть постоянный облачный компьютер с браузером, файлами и терминалом, работа не останавливается, когда ноутбук закрыт, все боты одного аккаунта делят один компьютер. Платформы: macOS, Windows, Linux, iOS, Android. Компьютеры ботов крутятся в облаке Cursor. Доступа к API в этом обзоре нет. Источник: https://docs.x.ai/grok-bot/overview. Анонс на форуме Cursor 11 августа 2026: ранний бета, облачный компьютер, боты переписываются друг с другом; на старте доступ был у SuperGrok Heavy, Cursor Ultra и Cursor Teams Premium. Источник: https://forum.cursor.com/t/introducing-grok-bot/168053. Grok Bot не садится в общую папку хаба и не подчиняется файловой лизе. Он видит свой облачный диск, не «внутренний путь лаборатории».

Третья поверхность — Build mode на grok.com и в мобильных приложениях. Это сборка и публикация приложений в чате, не терминальный агент. Студия Grok снята, вместо неё указан Grok Build. Для этого режима приватный чат недоступен, сессии хранятся, чтобы сборку можно было продолжить. Источник: https://docs.x.ai/developers/faq/security (разделы Grok Build CLI и Grok.com Build mode), FAQ: https://docs.x.ai/grok/faq.

Cursor — IDE, внутри которой живёт агент, плюс отдельный CLI `agent`, плюс облачные агенты, плюс с августа 2026 ещё и Grok Bot как соседний продукт той же витрины. CLI ставится на Windows той же схемой `irm`, умеет интерактив и headless. Режимы те же, что в редакторе: Agent, Plan, Ask (`--mode=ask` ничего не правит). Headless: `agent -p`. Без `--force` / `--yolo` правки только предлагаются и на диск не ложатся. С `--force` ложатся. Облачный агент из CLI уводится префиксом `&` и продолжается на https://cursor.com/agents. Источники: https://cursor.com/docs/cli/overview и https://cursor.com/docs/cli/headless.

Headless у Cursor пригоден для ночного прогона без открытого GUI. Он не равноправен GUI. В GUI живут Agents Window, Projects (координатор, который сам не пишет код и раздаёт работу тысячам субагентов на облачных машинах; страница changelog от 10 сентября 2026: https://cursor.com/changelog), Design Mode, визуальный `/worktree` и `/best-of-n`. Старый текст «background agents требуют выключенный Privacy Mode» я в этом прогоне на актуальной странице не перепроверял. Актуальная справка описывает Cloud Agents как отдельную VM с клоном репозитория, командами, которые не трогают локальную машину: https://cursor.com/help/ai-features/background-agents.md. Для системы «три процесса в одном локальном checkout на Windows» это другой режим: облачный агент уезжает в клон на GitHub-ветке, а не в общую папку.

Оценка. Класс совпадает только у пары Grok Build CLI и Cursor CLI `agent`. Grok Bot и Cursor IDE/Cloud Agents — соседние продукты. Уверенность высокая по разведению CLI и Bot: оба обзора открыты сегодня. Уверенность средняя по «равноправию» CLI и GUI: документация прямо говорит «те же режимы», и отдельно показывает флаги, которых в GUI нет (`--force` решает, запишется ли файл). Полного списка функций GUI, которых нет в CLI 1:1, вендор не публикует.

B. Совместимость с чужой полкой

Grok Build читает чужую полку официально, не как случайность, и это можно выключить.

Правила. Обход от корня репозитория до текущей папки. В каждом каталоге читаются `AGENTS.md`, `Agents.md`, `AGENT.md`, `CLAUDE.md`, `Claude.md`, `CLAUDE.local.md`, плюс `*.md` из `.grok/rules/`, и для совместимости из `.claude/rules/` и `.cursor/rules/`. Файлы из `.gitignore` пропускаются, поэтому `CLAUDE.local.md` в общий контекст не попадает, если он игнорируется. Глубже лежащий файл побеждает при конфликте. Файлы грузятся целиком, потолка размера нет. Короткие инструкции выполняются надёжнее длинных. Проверка: `grok inspect` печатает каждый найденный файл и примерный счёт токенов. Страница обновлена 4 июля 2026: https://docs.x.ai/build/features/project-rules.

Скиллы. В репозитории исходников CLI таблица путей включает «внутренний путь лаборатории», «внутренний путь лаборатории», `.claude/skills/`, и зеркально пути Cursor. Сканирование Claude и Cursor включено по умолчанию. Выключение: `[compat.claude]` / `[compat.cursor]` в `~/.grok/config.toml`, либо `GROK_CLAUDE_SKILLS_ENABLED=false` и `GROK_CURSOR_SKILLS_ENABLED=false`. Источник, открытый как файл на GitHub: https://github.com/xai-org/grok-build/blob/main/crates/codegen/xai-grok-pager/docs/user-guide/08-skills.md. Публичная страница совместимости короче и говорит то же по смыслу: нулевой конфиг, читаются маркетплейсы, плагины, скиллы, MCP, агенты, хуки и файлы инструкций Claude, обновлена 11 августа 2026: https://docs.x.ai/build/features/skills-plugins-marketplaces. Переменные сканеров (`GROK_CLAUDE_SKILLS_ENABLED`, `GROK_CLAUDE_RULES_ENABLED`, `GROK_CLAUDE_AGENTS_ENABLED` для `CLAUDE.md` / `CLAUDE.local.md`, `GROK_CLAUDE_MCPS_ENABLED`, `GROK_CLAUDE_HOOKS_ENABLED`, и такой же ряд для Cursor) перечислены в справочнике настроек: https://docs.x.ai/build/settings/reference.md.

Два канона. Это не гипотеза. Если в одном каталоге лежат и `AGENTS.md`, и `CLAUDE.md`, Grok читает оба, целиком, без потолка. Правило «глубже побеждает» разрешает конфликт между папками, не между двумя файлами в одной папке. Победитель одноуровневого конфликта в документации не назван. На этой машине это уже измерено 22 сентября 2026: `grok inspect` поднял одновременно «внутренний путь лаборатории» и копию канона в «внутренний путь лаборатории», около 60 тысяч токенов вместо 30. Официальная страница относит глобальные правила к `~/.grok/`, а поимённый обход — к дереву репозитория. Что именно пользовательский «внутренний путь лаборатории» входит в discover, документация формулирует через «instruction files CLAUDE.md» и через флаг `GROK_CLAUDE_AGENTS_ENABLED`, без отдельной строки «всегда грузить `%USERPROFILE%\.claude\CLAUDE.md`». Зазор между формулировкой и фактом `grok inspect` на этой машине я не закрываю чужим текстом: факт машины сильнее абзаца. Риск, что вендор сузит совместимость, реальный и уже имеет рубильник: флаги `GROK_CLAUDE_*` существуют именно затем, чтобы скан можно было выключить. Пока флаги в справочнике, это поддержанная функция, не случайный баг.

Поле `allowed-tools` в `SKILL.md` Grok принимает и не применяет. Написано прямо: не выдаёт и не ограничивает инструменты. Источник: та же страница скиллов https://docs.x.ai/build/features/skills-plugins-marketplaces. Для полки из ~290 скиллов это значит, что ограничение инструментов, записанное во frontmatter скилла, на Grok пустое.

Cursor тоже читает чужое, и тоже официально. `CLAUDE.md` в корне проекта применяется всегда, так же как `AGENTS.md`, фронтматтер `alwaysApply` это не отменяет. Справка: https://cursor.com/help/customization/rules. Скиллы для совместимости грузятся из `.claude/skills/`, `.codex/skills/`, «внутренний путь лаборатории», `~/.codex/skills/`, плюс родные `.cursor/skills/` и `~/.cursor/skills/`. Источник: https://cursor.com/docs/skills. Своя рекомендация Cursor: правила короче 500 строк. Канон на ~30 тысяч токенов этой рекомендации не удовлетворяет, и `CLAUDE.md` при этом всегда в контексте.

Дыра полки. 9 апреля 2026 сотрудник Cursor на форуме написал, что тумблер сторонних плагинов и скиллов подхватывает `CLAUDE.md` и `.claude/skills/`, а `.claude/rules/` не является поддержанным местом. Предложенный обход: скопировать в `.cursor/rules/` и переименовать в `.mdc`. Источник: https://forum.cursor.com/t/claude-project-level-rules-not-loaded-with-the-include-third-party-toggle-enabled/157087/6. У этой системы правила разложены в «внутренний путь лаборатории»*.md`. На Grok этот каталог в списке совместимости есть. На Cursor по ответу сотрудника от апреля его нет. Апрельский ответ мог устареть. Свежей официальной страницы, которая бы сказала «`.claude/rules` теперь читается», я в этом прогоне не открыл.

Второй канон на Cursor опасен тем же способом. 26 января 2026 баг: `CLAUDE.md` читается, даже когда тумблер сторонних правил выключен. Сотрудник воспроизвёл это на первом запуске после выключения. Источник: https://forum.cursor.com/t/cursor-loads-claude-md-even-when-the-third-party-rules-toggle-is-turned-off/149974. 10 апреля 2026 сотрудник подтвердил, что выкинуть `AGENTS.md` из правил, не удалив файл, можно через `.cursorignore`, и тогда файл выпадает ещё и из индекса. Источник: https://forum.cursor.com/t/more-flexible-handling-of-md-files-in-rules/157276. Если в папке снова окажутся две расходящиеся версии, Cursor, как и Grok, применит `CLAUDE.md` всегда. Механизма «один канон, вторая копия молчит» нет. Есть удаление, ignore и ручное расхождение файлов.

Риск снятия совместимости. У Grok рубильник уже публичный, значит функция признана и может быть сужена одним релизом. У Cursor совместимость тоже признана справкой, а баг января показывает, что выключение не было жёстким. Ни один из двух документов не обещает совместимость навсегда.

C. Три агента в одной папке

Ни у одного из двух нет файловой лизы между чужими процессами. Оба умеют изолировать git worktree. Оба умеют режим, в котором запись ограничена. Это не замена лизы на общий checkout.

Grok. Worktree — отдельная копия репозитория под `~/.grok/worktrees/<repo>/<name>`, от текущего HEAD, включая незакоммиченные изменения. Запуск: `grok -w`, `grok --worktree=имя`, `grok -w --ref main`. Сессия заканчивается, каталог worktree остаётся, пока не вызвать `grok worktree gc`. Субагент может попросить изоляцию. Страница обновлена 21 июля 2026: https://docs.x.ai/build/features/worktrees. Права: режимы Ask (спрашивать), Auto (классификатор), Always-approve. `deny` всегда сильнее `allow`. Plan mode отдельно ограничивает инструменты правки, и экран плана не пропускается даже в always-approve. Запомненное «всегда разрешать» всё равно спрашивает на опасных шаблонах вроде `rm` и `git push`, пока правило не записано явно. Страница обновлена 21 июля 2026: https://docs.x.ai/build/features/permissions. Выключить запись можно флагом `--disallowed-tools` и переменной `GROK_WRITE_FILE=0` (справочник: https://docs.x.ai/build/settings/reference.md). Это граница одного процесса Grok. Claude Code и Codex её не видят.

Cursor. Worktree в Agents Window и команды `/worktree`, `/best-of-n` (один и тот же запрос на нескольких моделях, каждый в своём worktree, слияние само не делается). Документация: https://cursor.com/docs/configuration/worktrees. Ask mode в CLI не пишет файлы: https://cursor.com/docs/cli/overview. Headless без `--force` тоже не пишет: https://cursor.com/docs/cli/headless. Cloud Agent клонирует репозиторий к себе и пушит ветку. Это изоляция от локального диска, не совместная работа в одной папке.

Что worktree не закрывает. Канон и полка лежат в «внутренний путь лаборатории», вне checkout. Worktree репозитория не запирает `CLAUDE.md` и `SKILL.md`. Три агента, которые правят скилл или канон, сталкиваются в домашнем каталоге независимо от worktree. Не-git папка у Grok worktree не получает: в документации worktree требует git-репозиторий.

Грабли, которые уже опубликованы, и которые ударят по четвёртому писателю в том же дереве.

Cursor, 8 июня 2026. После Stop агент продолжал менять файлы и в отдельных случаях делал commit. Ответ сотрудника: Stop кончает текущий ход, уже запущенная команда доезжает. Источник: https://forum.cursor.com/t/cursor-agent-is-acting-uncontrollably-after-prompts-are-stopped-modifying-files-and-even-committing-code/162740.

Версия cursor-agent `2026.07.09-a3815c0`. Источник: https://forum.cursor.com/t/acp-approvalmode-auto-review-classifier-and-autorun-instructions-are-ignored-auto-review-degrades-to-plain-allowlist-and-cursor-permissions-json-is-never-read/165665.

Модель охотнее заявляет успех, когда проверка молча не запустилась. Источник: https://forum.cursor.com/t/more-than-a-month-of-unreliable-agent-behavior-and-false-completion-claims/171804. Это прямо бьёт правило «исполнитель не объявляет готово сам»: инструмент, который врёт про проверку, плодит ложные `artifact.proposed`.

D. Цена и лимиты

Считать надо два кошелька, которые не складываются.

Подписка Grok, потребительская. Страница цен, открытая сегодня: SuperGrok $30 в месяц (в карточке: модель Grok 4.6, доступ к Grok Bot, коннекторы, более высокие лимиты, Expert, SOC 2 Type I и II, картинки и видео). SuperGrok Plus $100 в месяц: всё из SuperGrok, 1080p, существенно больший объём на Chat, Imagine, Voice и Build, приоритет в пике. В матрице есть ещё Free, SuperGrok Lite, SuperGrok Heavy, Business, Enterprise. Доллара Heavy на карточках, которые вернула страница, не было. Строка «No training» есть в блоке безопасности матрицы, без привязки к конкретному тарифу в тексте выдачи. Источник: https://x.ai/pricing. Анонс CLI от 25 мая 2026 пускает в Build подписчиков SuperGrok и X Premium Plus. Маркетинговую строку «попробовать бесплатно» на https://x.ai/build я отдельной загрузкой страницы в этом прогоне не подтверждал. Расхождение мая и сентября возможно. Не закрыто.

Как тратится пул. С июня 2026 у платных планов один недельный пул на все продукты, не отдельные дневные потолки Chat / Imagine / Voice / Build. Продукты стоят по-разному: сообщение дёшево, длинная задача кодинга и видео дороги. Процент и разбивка по API, Build, Chat, Imagine, Voice видны в Settings, Usage. На нуле платные функции встают до недельного сброса. Бесплатные потолки Chat и Voice остаются и сбрасываются по своему расписанию. Дальше: Extra Usage Credits от $5, только с веба, кредиты дороже включённого пула и живут год, либо апгрейд, либо Auto Top Up. FAQ обновлён 27 августа 2026: https://docs.x.ai/grok/faq. Численного потолка «N запросов» или «N токенов» на SuperGrok, Plus, Heavy и X Premium+ эта страница не даёт. Сторонние таблицы «100 промптов за 2 часа» и «300 за 2 часа» друг другу противоречат и написаны про старую подневную схему. В отчёт как факт они не входят.

Развилка подписка против API. Вход в CLI через браузерный логин жжёт недельный пул подписки. `XAI_API_KEY` уводит запрос на API. API-кредиты невозвратные: https://docs.x.ai/grok/faq. На API по умолчанию нет обучения без явного разрешения, запросы хранятся 30 дней: https://docs.x.ai/developers/faq/security. Это ровно тот метр, которого схема «жечь включённое, не платить поштучно» просит избежать. Ночной `-p` с ключом в окружении молча переключает кошелёк.

Cursor, индивидуальные планы, страница цен сегодня. Hobby: бесплатно, ограниченные запросы агента, доступ к Composer. Pro $20: расширенные лимиты агента, щедрые лимиты на Grok, доступ к Grok Bot, MCP, скиллы, хуки, cloud agents, Bugbot по usage. Pro+ $60: 3x лимитов Pro на агента и более высокий лимит Grok Bot. Ultra $200: 20x и самый высокий лимит Grok Bot. Годовая оплата −20%. При упоре страница отсылает к on-demand. Источник: https://cursor.com/pricing.

Вторая официальная страница, модели, описывает два месячных пула. Cursor Models: заметно больший включённый объём на Grok 4.7, Grok 4.6, Grok 4.5 и Composer 2.5. Other Models: сторонние модели по их API-цене. Опубликованные ставки Grok 4.7: вход $2, чтение кэша $0.50, выход $6 за миллион токенов. Fast и окно 500k дороже, до $6 / $18. При исчерпании: on-demand по тем же ставкам, качество и скорость не снижают, либо апгрейд. Ориентир вендора: ежедневный агент обычно $60–100 в месяц суммарно, несколько агентов и автоматизация часто $200+. Teams: Standard $40 за пользователя в месяц, Premium $120 и 5x лимитов Standard на агента. На Teams и Enterprise к сторонним моделям добавляется Cursor Token Rate $0.25 за миллион токенов. Grok и Composer от этой надбавки освобождены. Источник: https://cursor.com/docs/models-and-pricing.

Третья официальная страница всё ещё говорит старым языком: Pro включает $20 API-usage агента, Pro Plus $70, Ultra $400, плюс щедрый Auto и Composer. Источник: https://cursor.com/docs/account/pricing. Две страницы Cursor друг другу противоречат. Карточки на https://cursor.com/pricing и пулы на странице моделей выглядят как действующая схема сентября 2026. Долларовый кредит $20/$70/$400 может быть незакрытым хвостом. Пока вендор не снял одну из страниц, точный объём Pro в долларах я не утверждаю. Множители 3x и 20x на карточках утверждаю: они на открытой странице цен.

Grok Bot мерит отдельно от IDE. 7 сентября 2026 сотрудник Cursor написал: на Pro у Grok Bot свой недельный объём, месячный пул Cursor Models тратится тем, что сделано внутри приложения Cursor. Строка `grok-bot-default` внутри Cursor Models — ошибка отображения, биллинг от неё не меняется. Облачные агенты, которых запустил Grok Bot, тарифицируются как использование Cursor, потому что они бегут в Cursor. Источник: https://forum.cursor.com/t/are-grok-bot-usage-and-cursor-usage-separate/170875. Матрица доступа и запрет складывать гранты: https://cursor.com/help/grok-bot/plans, страница существует и открыта сегодня. Связка SuperGrok или X Premium+ с аккаунтом Cursor даёт грант на Bot и не прибавляется к уже оплаченному Cursor Pro/Pro+/Ultra. Связка неразрываемая: отвязать и перенести на другой аккаунт Cursor нельзя. При выключенном on-demand Bot останавливается на конце недельного гранта. При включённом продолжает и бьёт в месячный потолок трат Cursor. Уже идущий бот может доехать за потолок. Лимит не режет ход посередине.

19 сентября 2026 сотрудник отдельно описал поведение двух пулов IDE: когда один пул выбран до нуля, запросы могут продолжиться за счёт второго включённого пула, без отдельного счёта, если on-demand выключен. Настройки «остановись на границе одного пула» нет. Источник: https://forum.cursor.com/t/grok-models-using-api-usage-instead-of-first-party/172365. Для схемы «жечь включённое и не вылезти в поштучную оплату» это значит: граница пула мягкая, пока второй пул ещё жив.

Вывод по деньгам для уже оплаченных подписок. Ночной Grok Build под логином SuperGrok жжёт тот же недельный пул, что чат, картинки и голос. Длинный агентный прогон съедает его быстрее чата, число не опубликовано. Cursor CLI на Grok 4.7 жжёт месячный пул Cursor Models, который на карточке называется «щедрым» и не имеет опубликованного потолка в запросах. Четвёртый писатель ускоряет оба кошелька сразу, если гонять и тот и другой. API-ключ любого из двух выводит прогон из подписки.

E. Приватность и что уезжает наружу

Оба агента читают локальный диск. Оба отправляют на сервер вендора то, что попало в запрос: промпт, куски файлов, вывод инструментов. Выключателя «вообще ничего не отправлять и при этом звать модель» нет ни там, ни там.

Cursor. Страница Data Use обновлена 3 сентября 2026. Privacy Mode включён: данные клиента не идут в обучение Cursor, с провайдерами есть соглашения zero data retention, провайдеры не хранят и не обучаются. Оговорка на той же странице: классификаторы риска могут сохранить промпт или разговор, если сработал детектор злоупотребления, и хранить его по политике расследования. Модели вне ZDR помечены или требуют включения администратором. Privacy Mode выключен: Cursor может хранить код, промпты, действия редактора и обучать на них свои модели. Часть inference-провайдеров может временно хранить вход и выход для ускорения инференса и удаляет после использования. Свой API-ключ провайдера не обходит бэкенд Cursor: финальная сборка промпта делается там. Содержимое файлов временно кэшируется на серверах, шифр с ключом, который живёт только на время запроса. При Privacy Mode этот кэш не используется для обучения. Источник: https://cursor.com/data-use. Справка подтверждает, что уходят промпты и контекст кода к провайдерам, и что для Grok 4.5 Privacy Mode работает так же: https://cursor.com/help/security-and-privacy/privacy. Enterprise-страница добавляет: часть моделей требует хранения у провайдера ради проверки вреда. Для Claude Fable 5 и Fable 5.1 Anthropic хранит вход и выход для автоматической и человеческой проверки. Это не обучение. При Privacy Mode запрос к таким моделям падает, пока хранение не одобрено в дашборде. Источник: https://cursor.com/docs/enterprise/privacy-and-data-governance.md. Индексация кодовой базы в более старом тексте описывалась как выгрузка чанков ради эмбеддингов с уничтожением открытого текста после запроса. Этот абзац я видел на https://docs.cursor.com/ja/account/privacy. Японская страница может отставать от английской от 3 сентября. Как единственное доказательство текущей индексации я её не беру.

Cloud Agent и Grok Bot увозят больше, чем чат в IDE. Репозиторий клонируется на VM Cursor. Бот живёт на общем облачном компьютере аккаунта, и изоляция между ботами одного пользователя не обещана: обзор прямо говорит, что файлы, сессии браузера и логины приложений общие для всех ботов аккаунта. Источник: https://docs.x.ai/grok-bot/overview.

Grok Build. Обязательные хосты по enterprise-доку: `cli-chat-proxy.grok.com` (инференс и настройки) и `auth.x.ai`. Источник: начало раздела Enterprise в https://docs.x.ai/llms-full.txt. При включённом командном ZDR следов и данных кода CLI не хранит. Без ZDR удержание кода выключается в `/privacy` и `/settings`. При первом запуске CLI показывает экран согласия оставить данные для улучшения продукта и модели, и настройку, чтобы решение поменять. Источник: https://docs.x.ai/developers/faq/security, обновлено 21 сентября 2026. ZDR командного API выключает хранение промптов, но ломает функции, которым нужно серверное состояние: stateful Responses, Files, Collections, Batch, отложенные ответы, хранимые картинки и видео. Для видео под ZDR нужен свой S3-совместимый бак, в xAI уходит только presigned URL. Страница от 14 сентября 2026: https://docs.x.ai/build/settings/zdr-video-storage. Потребительский тумблер «Improve the Model» на grok.com и в мобильном приложении по умолчанию включён в том смысле, что отказ надо сделать самому: новые разговоры после отказа не идут в обучение, уже отправленный фидбек может идти. Это политика потребительского Grok, не автоматически политика CLI. Трек изменения формулировки между 15 августа и 7 сентября 2026: https://isittrainingonme.com/changes/2026-09-07T08-28-55-xai-ai-addendum. Build mode на сайте при включённом тумблере может отдать в улучшение модели и сессии сборки, и данные созданных приложений. Приватного чата у этого режима нет: https://docs.x.ai/developers/faq/security.

Где реально выключаются инструменты чтения. У Grok: `--disallowed-tools`, `--disable-web-search`, `GROK_WRITE_FILE=0`, правила `deny` на `Read`. Поле `allowed-tools` в скилле не выключает ничего, это официально. У Cursor: Ask mode и headless без `--force` не пишут. Отдельного опубликованного «выключить Read и это гарантировано» на открытых мной страницах CLI нет. Песочница Cursor ограничивает команды, не отменяет отправку контекста модели.

Случаи, где заявленное выключение оказалось не тем, чем казалось. Все четыре ниже про Cursor, с датами и тредами, уже указанными в разделе C: тумблер сторонних правил не убрал `CLAUDE.md` (январь 2026), ACP проигнорировал классификатор и файл прав (июль 2026), галка auto-review подняла режим без явного намерения (июнь 2026), Stop не остановил уже летящую запись и commit (июнь 2026). Для Grok Build опубликованного отчёта класса «`--disallowed-tools` вызвал инструмент всё равно» я в этом прогоне не нашёл. Отсутствие отчёта не доказывает, что рубильник честный. Честный статус: не знаю.

F. Заметность

Цель номер два — чтобы человека увидела команда топовой LLM-компании и чтобы лёг вклад в открытый код чужих экосистем. Площадки двух вендоров для этого неравноценны, и ни одна не заменяет чужие репозитории Anthropic, OpenAI, Google.

Grok Build. Исходники CLI публичны: https://github.com/xai-org/grok-build/blob/main/README.md. Это прямой код вендора, pull request виден мейнтейнерам репозитория. Насколько быстро они смотрят, из README я не измерял. Внутри продукта `/feedback` по анонсу 25 мая 2026 уходит команде. Маркетплейс плагинов есть в самом CLI (`/marketplace`, источники в конфиге): https://docs.x.ai/build/features/skills-plugins-marketplaces. Это установка из настроенных источников, не витрина с редакцией, на которой незнакомец гарантированно попадает на глаза сотруднику. Неофициальный список сообщества сам пишет, что к xAI не относится: https://github.com/DominikTobureto/awesome-grok-build/blob/main/README.md. Документация зовёт в Discord xAI из подвала полного текста доков. Каталог MCP у xAI есть как сервер их собственных доков, и в инструкции по подключению назван в том числе Cursor: https://docs.x.ai/developers/docs-mcp. Вклад в этот сервер снаружи не принимается, это их endpoint.

Grok Bot как площадка вклада слабее. Обзор не описывает маркетплейс скиллов бота, доступный внешнему автору, и не описывает API. Заметность здесь — если бот или человек на форуме Cursor обсуждает бота. Форум живой, сотрудники отвечают поименно.

Cursor. Форум https://forum.cursor.com. По тредам этого прогона сотрудники отвечают на биллинг, права и баги. Это поверхность, где репорт доходит до человека вендора. Маркетплейс: плагины ставятся из Git-репозиториев, все перечисленные открыты и проходят ручное ревью, каждое обновление ревьюится снова. Справка: https://cursor.com/help/customization/plugins. С июня 2026 есть страница Customize, лидерборд популярных плагинов, скиллов и MCP, командные маркетплейсы. Источник: https://cursor.com/changelog/customize. Публикация скилла в командный маркетплейс видна своей команде, не публике вендора. Сообщество снаружи: cursor.directory, указан в той же справке. Баг в продукте, воспроизведённый на форуме, виден сильнее, чем скилл, лежащий только в «внутренний путь лаборатории».

Что уходит в пустоту. Скилл на общей полке хаба не виден ни xAI, ни Cursor, пока его не отправили в их репозиторий, маркетплейс или форум. Ночной прогон агента в своей папке заметности не создаёт. Cloud Agent, который открывает PR в чужом репозитории, виден мейнтейнерам того репозитория. Это уже цель номер два в чистом виде, и для неё инструмент вторичен: тот же PR может открыть Claude Code или Codex.

G. Вердикт

Claude Code остаётся оркестратором. Cursor четвёртым в ту же папку не добавлять. Grok Build CLI не заменять на Cursor. Grok Bot не ставить на место CLI и не сажать рядом как четвёртого агента checkout.

Почему так, по условиям этой системы.

Полка уже читается тем, кто в папке есть. Grok 1.0.40 официально сканирует «внутренний путь лаборатории» и оба имени канона. Cursor официально сканирует ту же полку скиллов и тоже всегда применяет `CLAUDE.md`. Четвёртый читатель того же файла на 30 тысяч токенов добавляет ещё один процесс, который при расхождении `AGENTS.md` и `CLAUDE.md` снова проглотит оба. Узкое место уже не «умеет ли агент прочитать скилл». Узкое место — два канона и отсутствие лизы на «внутренний путь лаборатории». Новый агент это узкое место расширяет.

Ночной безлюдный прогон на локальном диске хаба — работа Grok Build `-p` и Cursor `agent -p`. Оба это умеют. Cursor при этом тащит за собой соблазн Cloud Agent и Grok Bot, которые работают не в этой папке. Подмена локального прогона облачным клоном ломает лизу, Telegram-будильник и доступ к локальным базам. Grok Bot делит один облачный компьютер между всеми ботами аккаунта. Секреты и сессии браузера, положенные туда для одной задачи, видны остальным ботам того же аккаунта.

Деньги. Подписка Grok уже оплачена и жжётся недельным пулом, куда входит Build. Cursor Pro за $20 жжёт другой, месячный пул, а ориентир вендора для нескольких агентов — часто $200 и выше, дальше on-demand. Связка SuperGrok с Cursor не удваивает грант Grok Bot. Четвёртый агент — это второй счёт за ту же полку.

Доверие к «я проверил». Свежий тред от 16 сентября 2026 показывает, что агент Cursor объявляет проверку выполненной, когда терминал в песочнице молча не запускался. В протоколе, где исполнитель не имеет права сам сказать «готово», такой отказ дороже отсутствующей функции.

Заметность четвёртым агентом не покупается. Она покупается PR в открытый репозиторий и ревьюируемым плагином. Репозиторий CLI xAI уже открыт. Маркетплейс Cursor ревьюит плагины людьми. Оба пути можно пройти текущими тремя агентами, не сажая Cursor в checkout.

Условие, при котором ответ переворачивается.

Заменить Grok Build на Cursor CLI, не добавляя четвёртого и не трогая Grok Bot, имеет смысл только если на этой Windows-машине одновременно выполнены три замера. Первый: `agent -p` ночью стабильно работает по той же полке «внутренний путь лаборатории», а `grok inspect` и список правил Cursor показывают один канон, не два. Второй: Privacy Mode включён, и ночным задачам не нужны инструменты, которые есть у подписки Grok и отсутствуют у Cursor (поиск по X, генерация в том же недельном пуле). Третий: фактический расход пула Cursor Models на том же объёме ночных задач меньше, чем расход недельного пула SuperGrok, и прогон идёт логином подписки, не API-ключом. Пока любого из трёх нет, замена увеличивает неизвестность, а добавление четвёртым увеличивает число писателей.

Обратный край, добавление Cursor только читателем, тоже не бесплатный. Ask mode и headless без `--force` по документации не пишут. Январский и июльский треды показывают, что соседние выключатели уже врали. Читателя можно ставить только в отдельный worktree или в копию дерева, не в живой checkout, и не раньше, чем на этой машине будет один прогон, где попытка записи из Ask mode реально не создала файл. До этого прогона «режим ревьюера» — заявление документации, не свойство установки.

Чего в источниках не хватает. Точных чисел недельного пула SuperGrok, Plus, Heavy и X Premium+ в токенах или запросах на открытом FAQ нет. Доллара SuperGrok Heavy на карточках https://x.ai/pricing в сегодняшней выдаче не было, хотя FAQ знает годовой счёт Heavy как частую причину неожиданного инвойса. Цену X Premium+ на help.x.com я в этом прогоне не открывал. Анонс 25 мая подтверждает только факт доступа Premium Plus к CLI. Страницы цен Cursor расходятся между множителями и долларовым кредитом $20/$70/$400. Журнал именно сборки 1.0.40 я не открыл. Вторичный пересказ пишет, что 1.0.0 вышел около 7 августа 2026. Дату сделки, по которой Cursor оказался в одной витрине с Grok, первичный пресс-релиз в этом прогоне не открыт. Продуктовая сшивка подтверждена форумом Cursor, страницей цен, справкой Grok Bot и страницей моделей. Отчёта, что `--disallowed-tools` у Grok фиктивен, не найдено.

Простыми словами. В папке уже сидят трое, и они делят одну толстую тетрадь правил и одну полку приёмов. Grok в терминале как раз третий такой же работник: сидит за этим компьютером, читает ту же полку, его можно позвать ночью без экрана. Grok Bot — это другой сотрудник в чужом офисе в интернете, со своим столом, и на наш стол он не переезжает. Cursor — это в основном редактор с агентом и ещё один облачный офис. Его терминальная версия умеет работать без экрана, но сажать четвёртого за тот же стол значит снова читать две разные тетради, снова писать в одни файлы и платить второй абонемент. Оставить троих. Поменять Грока на Cursor только после трёх замеров: одна тетрадь, ночь проходит, абонемент Cursor съедается медленнее уже оплаченного Грока.
