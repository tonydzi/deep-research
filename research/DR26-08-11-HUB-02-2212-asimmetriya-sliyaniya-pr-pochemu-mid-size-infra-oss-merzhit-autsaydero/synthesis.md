# 4. ПРИЗНАКИ РЕПО, КОТОРОЕ МЕРЖИТ

До написания PR должны выполняться большинство пунктов:

- репо является работающим продуктом, SDK, протоколом, runtime, eval или observability, а не брендовой галереей;
- есть свежая человеческая активность в issues и PR;
- виден named owner, CODEOWNERS или регулярно отвечающие maintainers;
- похожие PR незнакомых авторов недавно получали содержательный review и merge;
- задача уже существует в issue, roadmap или подтверждена maintainer;
- результат уменьшает баг, совместимость, CI, безопасность или поддержку;
- изменение мало, детерминированно проверяется и не создаёт постоянную редакционную обязанность;
- CONTRIBUTING даёт ясный путь, а не только best-effort без владельца;
- нет старой очереди похожих PR без человеческих ответов;
- у нас не лежат уже два молчащих PR в этом репо.

Для cookbook исключение: явно community-модель с названными ревьюерами либо заранее согласованная тема. Для awesome-list: объективные критерии, живой куратор и отсутствие запрета на такой тип вклада.
