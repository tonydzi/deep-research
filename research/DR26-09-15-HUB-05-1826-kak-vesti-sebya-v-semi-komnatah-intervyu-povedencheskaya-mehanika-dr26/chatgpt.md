3. Паузы и думание вслух

“I see two approaches. The hash-map version is linear but uses O(n) memory; sorting costs O(n log n) but bounds memory differently. Given this constraint, I’ll use the map and first test duplicate inputs.”

Пауза полезна, когда кандидат реально сравнивает варианты, вспоминает точный пример или проверяет инвариант. Пауза губительна, когда интервьюер не понимает, думает кандидат или потерялся. Точного опасного порога не найдено.

Сильный поток:

“The invariant is X. I see approaches A and B. B fails on duplicates, so I’ll use A. I’m coding the base case first; then I’ll test empty input and repeated values.”

Слабый поток:

“Maybe… perhaps… no… let’s type this… actually wait…”

4. Давление

[I] Практикующие интервьюеры описывают подсказки как лестницу возврата кандидата к проблеме; сильный кандидат проверяет контрпример и интегрирует сигнал. [Holloway](https://www.holloway.com/g/technical-recruiting-hiring/sections/best-practices-for-interviewers)

- Ошибка: “Yes, that input breaks my invariant. I’ll fix the state transition and rerun it.”
- Намёк: “I think the hint points to repeated work. I’ll quantify it before changing the algorithm.”
- Застрял: “The blocker is choosing X versus Y. I’ve ruled out X because Z. Does constraint W apply?”

5. Уточнения

[C] Вопросы должны снимать неоднозначность входа, ограничений и ожидаемой обработки ошибок. [Microsoft technical interviewing](https://careers.microsoft.com/v2/global/en/hiring-tips/technical-interviewing)

Спросить:

- допустимы ли пустые/повторные значения;
- насколько велик вход;
- важнее память или latency;
- ожидается ли обработка invalid input.

Не спрашивать о деталях, которые можно безопасно объявить допущением.

6. Незнание

[C] Anthropic разрешает lookup в собственных технических интервью, но предупреждает, что поиск расходует ограниченное время; политика других компаний может отличаться. [Anthropic careers](https://www.anthropic.com/careers)

Фраза:

“I don’t recall the exact method name. The operation I need is X. I’ll implement it with the basic construct unless lookup is allowed.”

Не притворяться, что несуществующий API реален.

7. Последние 60 секунд

[C] Microsoft просит тестировать boundary, error и security cases до объявления готовности. [Microsoft technical interviewing](https://careers.microsoft.com/v2/global/en/hiring-tips/technical-interviewing)

Если решение закончено: прогнать normal case, edge case, complexity.

Если не закончено:

“The baseline works through X. The unresolved case is Y. The next patch is Z, followed by test W. Current complexity is…”

Слабый кандидат до последней секунды молча печатает и оставляет интервьюеру угадывать, что он понимал.

E. Комната 4: system design LLM/agent

1. Первые 60 секунд

[C] Meta требует определить требования и критичные ограничения до high-level architecture; Amazon также ожидает уточнения, завершающие и проверяющие дизайн. [Meta engineering leadership guide](https://d3no4ktch0fdq4.cloudfront.net/public/course/files/SWE_engineering_leadership_-_onsite_guide.pdf), [Amazon SDE III preparation](https://www.amazon.jobs/content/en/how-we-hire/sde-iii-interview-prep)

[speculation] Первый пакет:

- кто пользователь;
- какой наблюдаемый результат;
- scale и latency/SLO;
- safety/trust boundary;
- три главных приоритета;
- план разговора.

Фраза:

“I’ll first pin down the user outcome, scale, and failure boundary; then I’ll propose the smallest architecture and pressure-test one success and one failure path.”

Слабый кандидат сразу рисует agent swarm, vector database и queue.

2. Темп и длина реплик

[speculation] Рамка — 30–60 секунд. Затем разделы по 2–3 минуты с коротким check-in. Это репетиционный бюджет, не научный оптимум.

“Would you like me to stay on retrieval quality, or move to rollout and incident recovery?”

3. Паузы и think-aloud

[C] Meta хочет решения, trade-offs, bottlenecks и изменение проекта при feedback. [Meta engineering leadership guide](https://d3no4ktch0fdq4.cloudfront.net/public/course/files/SWE_engineering_leadership_-_onsite_guide.pdf)

Сильный пакет:

“Requirement X makes A preferable to B. The cost is C. I contain it with D. This still fails under E, so the rollback boundary is F.”

Для LLM/agent-дизайна вслух различать:

- модельную способность;
- детерминированный контракт;
- eval;
- runtime failure;
- человеческую/политическую границу.

4. Давление

При новом условии:

“That invalidates assumption X. Components A and B survive; C does not. I’ll replace C and re-check latency, eval coverage, and rollback.”

Слабая реакция — защищать прежнюю схему или молча выбросить всё, не показав, что именно изменилось. Это [speculation], основанная на rubrics адаптации Meta. [Meta guide](https://d3no4ktch0fdq4.cloudfront.net/public/course/files/SWE_engineering_leadership_-_onsite_guide.pdf)

5. Уточнения

[speculation] Спрашивать только decision-changing facts:

- допустимая ошибка;
- стоимость false positive/false negative;
- data/privacy boundary;
- нагрузка и latency;
- что разрешено автоматизировать;
- какой rollback считается безопасным.

Остальное объявлять предположением и двигаться.

6. Незнание

[C] Meta отдельно пишет, что кандидат не обязан быть экспертом во всех design-областях, но должен понимать, когда нужна дополнительная экспертиза. [Meta engineering leadership guide](https://d3no4ktch0fdq4.cloudfront.net/public/course/files/SWE_engineering_leadership_-_onsite_guide.pdf)

“I haven’t operated that database at this scale. I would not choose it from memory alone. I’d isolate the dependency behind X and validate throughput, recovery, and cost with benchmark Y.”

7. Последние 60 секунд

[speculation] Вместо новых коробок пройти:

- один end-to-end success path;
- один failure path;
- bottleneck;
- eval/rollout;
- главный остаточный риск.

“The architecture meets X under assumptions Y. The unresolved risk is Z; the first production gate would be W.”

Вопрос:

“Which production failure currently determines architecture decisions on this team?”

F. Комната 5: decomposition / ambiguous case

1. Первые 60 секунд

[C] Deloitte и BCG рекомендуют повторить цель, снять необходимые неоднозначности, назвать assumptions, взять короткую паузу и показать структуру рассуждения. [Deloitte case guidance](https://www.deloitte.com/us/en/careers/join-deloitte/recruiting-tips/case-and-scenario-interview-tips.html), [BCG preparation](https://careers.bcg.com/global/en/case-interview-preparation)

“Let me confirm the decision, success criterion, and two assumptions. Then I’ll take twenty seconds to structure the branches.”

Слабый кандидат немедленно выдаёт решение либо вопросами заставляет интервьюера решить задачу за него.

2. Темп и длина реплик

[speculation] Задать один вопрос, получить ответ, кратко синтезировать его влияние, перейти к следующему узлу. Не выдавать очередь из восьми вопросов без объяснения, зачем они нужны.

3. Паузы и think-aloud

[C] BCG советует не исчезать в молчании и показывать ход рассуждения; Deloitte хочет видеть, как кандидат соединяет факты. [BCG](https://careers.bcg.com/global/en/case-interview-preparation), [Deloitte](https://www.deloitte.com/us/en/careers/join-deloitte/recruiting-tips/case-and-scenario-interview-tips.html)

Сильный think-aloud:

“My current hypotheses are A and B. This datum discriminates between them better than the revenue total, so I’ll test it first.”

Слабый — длинный список возможных идей без ранжирования и следующего действия.

4. Давление

При противоречащих данных:

“This lowers A and raises B. The overall decomposition survives, but I’ll change the order and test B first.”

При невозможных условиях:

“These constraints cannot all hold simultaneously because X. The smallest relaxation is Y; under that assumption the bounded solution is Z.”

5. Уточнения

[C] Deloitte говорит задавать вопросы “as needed”, но не использовать их как crutch. [Deloitte case guidance](https://www.deloitte.com/us/en/careers/join-deloitte/recruiting-tips/case-and-scenario-interview-tips.html)

Граница:

- хороший вопрос меняет решение или порядок проверки;
- слабый вопрос лишь откладывает начало;
- если ответ не меняет следующий шаг, назвать assumption и идти.

Оптимального числа вопросов не найдено.

6. Незнание

“The evidence does not distinguish A from B. The cheapest discriminating test is X. Until then I would take reversible default Y.”

Это [speculation], а не измеренная формула.

7. Последние 60 секунд

[C] Deloitte рекомендует завершать recommendation, findings, next steps и expected impact. [Deloitte case guidance](https://www.deloitte.com/us/en/careers/join-deloitte/recruiting-tips/case-and-scenario-interview-tips.html)

Формат:

“Recommendation: X. Reasons: A and B. Biggest risk: C. Next test: D.”

Не пересказывать всё дерево.

G. Комната 6: customer simulation

Здесь качество доказательств хуже всего. Peer-reviewed исследований поведения кандидата именно в FDE/customer-role-play не найдено; большинство подробных материалов публикуют продавцы sales-подготовки.

1. Первые 60 секунд

[C] Актуальное описание OpenAI FDE связывает роль с discovery, technical scoping, deployment, customer needs и спокойным суждением под давлением. HubSpot подтверждает использование role play как work sample, но не публикует причинных данных о лучших репликах. [OpenAI FDE](https://openai.com/careers/forward-deployed-engineer-%28fde%29-sf-san-francisco/), [HubSpot candidate experience](https://www.hubspot.com/careers/candidate-experience)

[speculation] Остаться в роли и начать с клиента:

“Before I propose anything, what outcome is blocked, who feels it, and which constraint cannot move?”

Слабый кандидат выходит из роли, объясняет интервьюеру свой framework или сразу питчит продукт.

2. Темп и длина реплик

Оптимальная доля речи не найдена. Правило «клиент говорит 70%, кандидат 30%» не подтверждено.

[speculation] Реплики короче, чем в deep dive: примерно 20–45 секунд, затем вопрос или playback. Это не научный оптимум.

“What I’m hearing is X, caused by Y, with deadline Z. Is that accurate?”

3. Паузы и think-aloud

[speculation] Не надо транслировать клиенту внутренний технический поток. Переводить выбор в последствие:

“Option A reaches pilot sooner but leaves manual review. Option B removes that step but requires latency validation.”

4. Давление

[V/C; заинтересованный корпоративный sales-контент] В role-play-примерах HubSpot рекомендует сначала выяснить конкретную причину возражения и избегать combative tone. Это sales advice, не исследование отбора. [HubSpot role-play guidance](https://blog.hubspot.com/sales/sales-negotiation-role-play-exercises)

Сильная реакция:

“You’re right that the current plan does not protect your latency SLO. We can narrow scope this week or validate full scope before launch. Which outcome matters more?”

Слабая:

- спорить с переживанием клиента;
- обещать неподтверждённую способность;
- принимать ложную предпосылку только ради согласия.

5. Уточнения

[speculation] Порядок discovery:

1. нужный outcome;
2. текущий workflow;
3. кто испытывает боль и кто решает;
4. срок;
5. неизменяемое ограничение;
6. данные, доступ и риск;
7. лишь затем технология.

6. Незнание

“I don’t want to invent that in front of you. I’ll confirm X with owner Y by checkpoint Z. Meanwhile the safe reversible action is W.”

Сильное незнание содержит владельца, способ проверки и безопасный промежуточный шаг. Прямой эксперимент этой формулы не найден.

7. Последние 60 секунд

[speculation] Закрывать не продажей, а mutual action record:

- customer outcome;
- что решили;
- кто владелец;
- срок;
- открытый риск.

“To confirm: I own X by Tuesday; you will provide Y; we will not expand beyond Z until the latency test passes. What have I missed?”

H. Комната 7: values / culture

1. Первые 60 секунд

[C] Anthropic публично описывает low-ego/high-trust работу, kind and direct disagreement, эмпиризм, простые работающие решения и личную ответственность. Компания говорит, что нетехнические интервью являются conversational и оценивают clarity, judgment и ход мысли. [Anthropic careers](https://www.anthropic.com/careers)

[speculation] Начать с тезиса и реального конфликта ценностей:

“My default is X, but in this case X conflicted with Y. I chose Z because…, and evidence A would have made me choose differently.”

Слабый кандидат цитирует сайт компании или заявляет, что согласен со всеми ценностями без контрпримера.

2. Темп и длина реплик

[C] Meta советует в behavioral answer ограничить ситуацию одним-двумя предложениями, затем показать личные действия, результат и learning. [Meta SWE guide](https://d3no4ktch0fdq4.cloudfront.net/public/course/files/Meta_SWE_full_loop_guide.pdf)

[speculation] Первичный ответ — 60–120 секунд, затем дать интервьюеру исследовать противоречия. Не закрывать историю моралью, которую нельзя проверить.

3. Паузы и think-aloud

[speculation] Полезно остановиться ради подбора правдивого случая:

“I want a real example rather than a polished principle. Give me a moment.”

Думать вслух здесь означает показать критерий решения и условие обновления позиции, а не читать философскую лекцию.

4. Давление и спор

[C] Kind/direct disagreement и low ego являются явными сигналами Anthropic. [Anthropic careers](https://www.anthropic.com/careers)

“I see the competing value. My choice depends on X. If evidence Y changed, I would update to Z.”

Слабые крайности:

- капитулировать при первом возражении;
- защищать позицию как идентичность;
- изображать абсолютную моральную уверенность там, где есть trade-off.

5. Уточнения

[speculation] Уточнять поведение, ставку и конфликт:

“Are you asking about the decision itself, how I handled disagreement, or what I learned afterward?”

Не спрашивать: “Which value do you want me to demonstrate?”

6. Незнание

“I haven’t formed a confident view. The uncertainty is X; before an irreversible decision I would seek evidence Y and input from Z.”

7. Последние 60 секунд

Сильный вопрос:

Поэтому безопасный синтез: STAR можно держать как скрытый каркас, но не превращать ответ в заученный монолог. [Anthropic careers](https://www.anthropic.com/careers)

I. Видеозвонок как среда

1. Камера или лицо

[single-source; R; 2024] В малом эксперименте 12 студентов произносили одинаковую речь, а 38 работников оценивали версии со взглядом в камеру, вниз и audio-only. Устойчивый взгляд вниз оценивался хуже; переносимость на живое интервью очень ограничена. [Эксперимент со взглядом](https://pubmed.ncbi.nlm.nih.gov/38821979/)

[emerging; R; 2024] В двух более крупных async-video экспериментах естественное вертикальное отклонение примерно на 15°, возникающее при взгляде на лицо под камерой, не ухудшило оценки, competence или warmth. Горизонтальный взгляд на боковой экран снизил perceived hirability и social presence. [Исследования camera placement](https://link.springer.com/article/10.1007/s10869-024-09981-4)

Решение:

- окно лица держать прямо под камерой;
- обычно смотреть на лицо, чтобы видеть реакции;
- коротко смотреть в объектив при приветствии и финальной фразе;
- не вести разговор с лицом на боковом мониторе.

Точный процент «зрительного контакта с объективом» не найден. Постоянное смотрение в объектив — фольклор.

2. Задержка и перебивания

[established для видеодиалога, не hiring outcome] В контролируемых разговорах переход между репликами занимал в среднем 297 мс локально и 976 мс через Zoom; видеосреда заметно нарушала обычный turn-taking. [Исследование Zoom turn-taking](https://pubmed.ncbi.nlm.nih.gov/34748361/)

[single-source] В эксперименте с 56 участниками задержка от 600 мс увеличивала перебивания и снижала naturalness/comfort, причём люди часто не осознавали источник проблемы. [CHI latency study](https://www.cs.cmu.edu/~jdtam/Documents/Tam-CHI2012-DelayNaturalness.pdf)

[emerging; R; 2025] Серия экспериментов показала, что небольшие AV glitches способны ухудшать социальную связь и последующие суждения, включая виртуальный hiring. [Исследование аудиовизуальных glitches](https://pubmed.ncbi.nlm.nih.gov/41339556/)

Практика:

- после вопроса оставлять естественный короткий beat;
- при collision немедленно уступать: “Sorry—go ahead”;
- не интерпретировать overlap как агрессию;
- если связь систематически рвёт реплики, назвать проблему и перейти на резервный канал.

Оптимальная задержка кандидата перед ответом не измерена.

3. Звук, свет и фон

[single-source; R] В медицинском mock-исследовании choppy internet, muffled audio, backlighting и off-center gaze ухудшали 15-секундные оценки; обычная домашняя комната не отличалась от conference room. Ограничения: три mock-кандидатки, медицинские интервью и response rate 13,6%. [Virtual-interview experiment](https://pmc.ncbi.nlm.nih.gov/articles/PMC9559552/)

[C] Google, Amazon и Microsoft советуют заранее проверять звук, видео, платформу и резервный телефон, а также находиться в тихом освещённом месте. Это операционная профилактика, не доказательство повышения score. [Google virtual guide](https://services.google.com/fh/files/misc/general_virtual_interviews_candidate_resource.pdf), [Amazon remote interview](https://www.amazon.jobs/content/en/how-we-hire/remote-interview), [Microsoft virtual interviewing](https://careers.microsoft.com/v2/global/en/hiring-tips/virtual-interviewing)

Приоритеты:

1. чистый синхронный звук;
2. стабильная сеть и резерв;
3. лицо не в контровом свете;
4. нейтральный неотвлекающий фон.

Ring light, точная цветовая температура и «правильный книжный шкаф» не имеют надёжного доказанного эффекта на живое tech-интервью.

4. Руки и жесты

[emerging; R; 2026] В двух экспериментах широкий кадр показывал больше телесной информации, но не дал прямого прироста performance или hirability по сравнению с кадром «голова-плечи». [Исследование framing](https://onlinelibrary.wiley.com/doi/10.1111/ijsa.70052)

Данных за обязательную видимость рук нет. Естественно жестикулировать можно; специально держать ладони в кадре весь час не требуется.

Контролируемого исследования влияния кандидатских заметок на hiring score не найдено.

- Google отдельно советует шарить релевантную вкладку и сообщать интервьюеру об использовании бумаги. [Google technical virtual guide](https://services.google.com/fh/files/misc/technical_virtual_interviews_candidate_resource.pdf)

7. Влияет ли video сам по себе

[emerging; R; 2026] Мета-анализ technology-mediated interviews не нашёл средней разницы в interview ratings относительно face-to-face, но гетерогенность была большой и rating studies было только восемь. Поэтому «video автоматически снижает score» не подтверждено. [Мета-анализ video interviewing](https://link.springer.com/article/10.1007/s12144-025-08946-x)

J. Речь неносителя английского

1. Bias существует

[established; R; 2025] Мета-анализ 41 независимого эффекта, N=7 596, нашёл преимущество стандартного акцента d=.46. Оно сохранялось при одинаковых ответах на структурированные вопросы. Сила акцента, субъективная понятность, формат audio/video и speaking demands не объяснили эффект надёжно; авторы связывают значительную часть разницы со стереотипами competence и warmth. [Accent-bias meta-analysis 2025](https://onlinelibrary.wiley.com/doi/10.1111/ijsa.12519)

[established; R; 2024] Другой мета-анализ 22 исследований, N=3 615, получил штраф для non-standard speech по competence δ=-.70, warmth -.17 и hirability -.51. Но все исходные исследования были лабораторными — high-stakes field study не было. [Applied Psychology meta-analysis](https://iaap-journals.onlinelibrary.wiley.com/doi/10.1111/apps.12528)

Вывод: bias реален, но точную потерю шанса для Антона или конкретной компании из этих эффектов вычислить нельзя.

2. Что компенсировать

[single-source; косвенное speech research] Высококвалифицированные неносители могли переходить в clear-speech mode — говорить несколько медленнее и усиливать артикуляционные и просодические различия; понятность росла, хотя акцент не исчезал. [Clear-speech study](https://pmc.ncbi.nlm.nih.gov/articles/PMC3253601/)

[single-source; R] В программе с 27 EAL-кандидатами персонализированный feedback после mock interview улучшил второй результат. Комментарии интервьюеров чаще всего касались clarity/coherence, связи опыта с ролью, concision, completeness, specificity и relevance. [Applied Linguistics study](https://academic.oup.com/applij/article-abstract/42/4/641/6007975)

[emerging/inference] Компенсировать следует processing load, а не пытаться стереть акцент:

- умеренный темп;
- одна мысль на клаузу;
- явное ударение на выводе;
- короткая пауза между пунктами;
- вывод впереди доказательства.

Сигнальные фразы:

- “Short answer: yes. There are two reasons.”
- “The trade-off is X versus Y.”
- “What I personally owned was…”
- “The result was X; the remaining failure mode was Y.”
- “I’ll answer the architecture first, then the rollout risk.”

Оптимального WPM для интервью не найдено. Доказательств, что краткий accent coaching убирает hiring bias, нет.

3. Если вопрос не понят

[single-source; R] В исследовании EAL-интервью кандидаты просили повторить или перефразировать 10 из 81 основных вопросов. Негативные комментарии иногда сопутствовали эпизоду, но относились не к самой просьбе; один интервьюер прямо назвал паузу разумной стратегией. Частые общие просьбы всё же создают дополнительную нагрузку интервьюеру. [Диссертационный корпус EAL-интервью](https://dspace.library.uvic.ca/bitstream/handle/1828/8539/Travers_Nicholas_PhD_2017.pdf?isAllowed=y&sequence=1)

Просить повторить стоит. Локализовать потерянное место:

- “I caught the latency constraint, but missed the last clause. Could you repeat just that part?”
- “Just to check: are you asking for the production architecture or the rollout plan?”
- “I heard fifty or fifteen—could you repeat the number?”

Слабее: молча ответить на предполагаемый вопрос или несколько раз сказать только “What?”

Если после двух попыток неясен термин, попросить написать его в chat — [speculation]; прямого hiring-исследования этой тактики нет.

K. Как звучит founder и почему это может читаться плохо

[established только для application stage; R] В полевом эксперименте с 2 400 рандомизированными заявками на SWE-позиции founder-профили получили 13,6% callbacks против 24,0% у сопоставимых nonfounder-профилей. Ограничения: фиктивные early-career кандидаты, США и этап заявки, а не senior interview. [Organization Science field experiment](https://pubsonline.informs.org/doi/10.1287/orsc.2022.1592)

[single-source; R] В 20 интервью рекрутёры объясняли founder-discount опасениями fit и commitment: будет ли человек принимать руководство, работать с документацией и структурой, делить ownership, не заскучает ли и не уйдёт ли снова строить компанию. Одновременно founders воспринимались как creative, driven и adventurous. [Та же Organization Science работа](https://pubsonline.informs.org/doi/10.1287/orsc.2022.1592)

[single-source; I/V] LinkedIn Talent Blog учит интервьюеров останавливать повторяющееся “we” вопросами о личном вкладе. Автор занимается interview training, поэтому это практическое свидетельство с коммерческим интересом, не академическое кодирование речи. [LinkedIn Talent Blog](https://www.linkedin.com/business/talent/blog/talent-acquisition/what-did-candidate-actually-do)

Не найдено исследования или публичного scorecard Anthropic/OpenAI/Google, где отдельно фиксируются:

- visionary register;
- “we built”;
- превосходные степени;
- закрытие темы;
- выражение “I orchestrate models”.

Следующие замены — [speculation], основанная на подтверждённых рисках неясного ownership, fit и commitment:

1. Визионерский регистр

Было:

“We built the world’s first category-defining multi-agent platform.”

Стало:

“The observed result was X over period N. My decision was Y, and I personally verified Z. Generalization beyond those conditions remains untested.”

2. Размытое “we”

Было:

“We built and deployed the fleet.”

Стало:

“The team deployed five machines. I personally owned decomposition, interface contracts and acceptance tests; A was implemented by B, and I verified it through C.”

3. Продажа вместо исследования

Было:

“This changes how all companies will work.”

Стало:

“In this environment it changed X. The next test of whether the result transfers is Y.”

4. «Я оркестрирую, модель делает»

Было:

“I orchestrate models rather than coding.”

Стало:

“I own the engineering outcome: decomposition, interfaces, evals, failure handling, review and incident response. Models produced some components under tests; here is a failure I caught and corrected.”

5. Закрытие темы

Было:

“That proves the architecture works.”

Стало:

“That is the evidence and its boundary. Which assumption would you like me to unpack?”

Важно: честная самопрезентация сама по себе не вредна. Мета-анализ impression management нашёл положительную связь честного self-promotion с ratings; риск появляется при неподтверждённых превосходных утверждениях и неясном личном вкладе. [Мета-анализ impression management](https://pmc.ncbi.nlm.nih.gov/articles/PMC5309241/)

L. Нервы и подготовка тела

1. Сон

[established; R] Экспериментальные и популяционные данные связывают ограничение сна до шести часов и менее с ухудшением vigilant attention, processing speed и working memory. Интервью-специфичного RCT «сон → score» не найдено. [AASM/SRS evidence review](https://aasm.org/resources/pdf/adultsleepdurationmethods.pdf)

Решение: обычная полная ночь; не менять сон на последний mock. Специально «пересыпать» доказанного преимущества нет.

2. Кофеин

[established; R; 2025] Мета-анализ 31 двойного слепого RCT, N=1 455, нашёл небольшое улучшение скорости и точности, но зависимость точности от дозы была нелинейной. [Caffeine cognition meta-analysis](https://link.springer.com/article/10.1007/s00213-025-06775-1)

[established; R; 2024] Мета-анализ 14 исследований, N=546, нашёл рост тревоги и особенно большой эффект при дозах от 400 мг; гетерогенность была очень высокой. [Caffeine and anxiety](https://www.frontiersin.org/journals/psychology/articles/10.3389/fpsyg.2024.1270246/full)

Решение: обычная уже проверенная доза; не удваивать её, не добавлять энергетик и не экспериментировать в день интервью. Точной interview-optimal dose нет.

3. Принятие нервозности

[emerging; R] В рандомизированном simulated job interview, N=82, reappraisal и acceptance снижали тревогу сильнее контроля; suppression не помогло. Другой RCT перед стрессовым выступлением также дал лучшие физиологические и речевые результаты для acceptance/reappraisal относительно suppression. [Simulated interview RCT](https://pubmed.ncbi.nlm.nih.gov/25930079/), [stress-test RCT](https://pubmed.ncbi.nlm.nih.gov/33839209/)

Внутренняя формула [speculation]:

“This is activation, not an emergency. It may remain. My next observable action is to state the constraint and test one hypothesis.”

4. Движение и дыхание

[emerging; R] Систематический обзор острых упражнений нашёл снижение тревоги только в части условий; оптимальные вид, интенсивность и длительность не установлены. [Acute exercise review](https://www.tnu.ethz.ch/fileadmin/user_upload/documents/Publications/2023/2023_Connor_Hargreaves_Scanlon_Harrison.pdf)

[emerging/mixed; R] Breathwork meta-analysis нашёл небольшие эффекты, но крупный placebo-controlled RCT, N=400, не обнаружил преимущества медленного дыхания над matched attention control. [Breathwork meta-analysis](https://pmc.ncbi.nlm.nih.gov/articles/PMC9828383/), [placebo-controlled breathing RCT](https://www.nature.com/articles/s41598-023-49279-8)

Решение: знакомая лёгкая разминка и 1–3 минуты дыхания допустимы как ритуал переключения внимания, но не как доказанный способ поднять score.

5. Голос и пробный звонок

[emerging; косвенное] Малое исследование голосовой разминки обнаружило изменение некоторых акустических параметров, но не измеряло hiring, понятность или тревогу и не установило оптимальный протокол. [Voice warm-up study 2024](https://dergipark.org.tr/en/download/article-file/3800833)

[C] Google советует заранее проверить Meet, звук, камеру, интернет, screen sharing и резервный телефон. Это снижает техническую неопределённость, но причинного исследования влияния test call на score нет. [Google general virtual guide](https://services.google.com/fh/files/misc/general_virtual_interviews_candidate_resource.pdf), [Google technical guide](https://services.google.com/fh/files/misc/technical_virtual_interviews_candidate_resource.pdf)

Практика [speculation]: один раз вслух произнести opener, проверить микрофон и сделать тест screen share. Не репетировать ответ ещё двадцать раз перед входом.

6. Время суток

[mixed; R] Исследование 818 реальных структурированных интервью не нашло заметного эффекта времени или порядка. Одноцентровое ophthalmology-исследование обнаружило более высокие оценки утром, но не значимую разницу в match. Обзор 2025 года также не поддерживает универсальный chronotype effect. [818 structured interviews](https://journals.sagepub.com/doi/abs/10.1177/009102609302200404), [ophthalmology cohort](https://www.thieme-connect.com/products/ejournals/html/10.1055/s-0042-1744272), [chronotype review 2025](https://pubmed.ncbi.nlm.nih.gov/40293205/)

Правила «только вторник в 10:00» нет. Выбирать слот, который не отнимает сон и совпадает с собственным стабильным окном бодрости.

7. Power posing

[established: не считать доказанным] Первоначальный mock-interview результат не воспроизвела целевая репликация; RCT структурированного устного экзамена также не нашёл повышения оценки. [Исходное исследование](https://www.insead.edu/faculty-research/publications/journal-articles/preparatory-power-posing-affects-job-interview), [репликация](https://www.tandfonline.com/doi/abs/10.1080/23743603.2016.1248080), [RCT 2023](https://pmc.ncbi.nlm.nih.gov/articles/PMC10291955/)

M. Если понял, что проваливаешь раунд

[C] OpenAI прямо предупреждает, что интервью могут намеренно выводить кандидата за пределы комфорта и оценивают подход, решения и объяснение reasoning, а не только завершённый ответ. Ощущение трудности само по себе не доказывает провал. [OpenAI Interview Guide](https://openai.com/interview-guide/)

[C; I] Microsoft требует уточнять допущения и тестировать решение; один практикующий инженер-интервьюер пишет, что самостоятельно замеченная и исправленная ошибка часто не штрафуется и может стать положительным сигналом. Второй источник — свидетельство одного интервьюера, не статистика. [Microsoft technical interviewing](https://careers.microsoft.com/v2/global/en/hiring-tips/technical-interviewing), [Jeff Carpenter](https://www.jeffcarp.com/posts/2018/its-ok-to-make-mistakes-in-interviews/)

Протокол восстановления [speculation]:

1. Остановить отравленную ветку.
2. Назвать конкретную ошибку и контрпример.
3. Сохранить корректный инвариант.
4. Выбрать минимальную корректную замену.
5. Назвать следующий тест.
6. При дорогой развилке задать один directional question.

Точная реплика:

“I found a flaw in assumption X: it breaks on Y. I’m stopping this branch. Requirement Z still holds. The smallest correct recovery is A; I’ll test it on B. Unless you want the diagnosis, I’ll pivot now.”

Сильный кандидат делает ошибку наблюдаемой и исправляет модель мира. Слабый защищает sunk cost, скрытно переписывает, блефует или многократно извиняется.

Если времени мало:

“The baseline that works is A. The unresolved failure mode is B. My next test would be C.”

Данных о доле кандидатов, которые таким способом превратили отрицательный раунд в положительный, не найдено.

N. Между раундами, после интервью и team matching

1. Между раундами в один день

Прямого исследования оптимального поведения в 5–10-минутной паузе не найдено.

[speculation] Делать:

- записать только три факта: где был сбой, что перенести в следующий раунд, что забыть;
- вода, туалет, 1–2 минуты движения;
- проверить звук/заряд;
- входить в следующую комнату с нуля.

Не делать:

- проводить полный посмертный разбор;
- писать рекрутёру, что предыдущий раунд провален;
- менять всю стратегию из-за одного холодного интервьюера.

2. Благодарственное письмо

[emerging, слабая переносимость; R] В исследованиях медицинского matching часть руководителей сообщала, что thank-you note мог повлиять на rank, но более свежая работа нашла для большинства минимальное влияние applicant-initiated communication. Это self-report, медицина, а не causal tech evidence. [Emergency-medicine study](https://pmc.ncbi.nlm.nih.gov/articles/PMC6948692/), [critical-care fellowship study 2023](https://pubmed.ncbi.nlm.nih.gov/37977268/)

[C] Microsoft разрешает отправить thank-you email, но не утверждает, что он влияет на решение. [Microsoft interview tips](https://careers.microsoft.com/v2/global/en/hiring-tips/interview-tips.html)

Вывод: в tech не найдено причинного доказательства, что письмо меняет оффер.

Низкорисковый вариант [speculation]:

“Thank you for the discussion. The constraint around X made the role especially concrete for me. I remain strongly interested and would be glad to continue.”

Добавить одну строку коррекции можно только при существенной фактической ошибке. Не отправлять apology essay, незапрошенный redesign или второе решение задачи. Правило «обязательно в течение 24 часов» в основном поддерживают job boards и coaches, а не эксперименты. [Indeed — заинтересованный job board](https://www.indeed.com/career-advice/interviewing/how-long-to-wait-after-interview)

3. Пауза 5–10 дней

[C] OpenAI сообщает, что обычно отвечает примерно в течение недели после assessment/final interview; Microsoft советует заранее спросить timeline и допускает контакт с рекрутёром. [OpenAI Interview Guide](https://openai.com/interview-guide/), [Microsoft interview tips](https://careers.microsoft.com/v2/global/en/hiring-tips/interview-tips.html)

Решение:

- срок назван — ждать до него плюс небольшой рабочий буфер;
- срок прошёл — один короткий status check;
- есть competing offer — сообщить сразу, с точной датой;
- не посылать ежедневные «value-add»;
- тишину не интерпретировать как доказанный отказ.

Оптимального пятого или десятого дня исследования не нашли.

4. Team matching

[single-source; C] Atlassian описывает matching как встречи с hiring managers открытых команд, где важны вопросы кандидата и взаимное соответствие; доступность команд меняется вместе с business priorities. Нельзя автоматически переносить эту механику на Google, OpenAI или Anthropic. [Atlassian interview guide](https://wac-cdn.atlassian.com/dam/jcr:c0aa929a-3391-4e9c-9202-3f3ba0eeb859/P30-P50-Frontend-Interview-Guide.pdf?cdnVersion=1437)

Текущего публичного первоисточника Google/OpenAI/Anthropic, подтверждающего конкретную headcount-механику или вероятность match, не найдено. Подробные интернет-гайды в основном опираются на coaches и форумы; например, I Got An Offer продаёт подготовку и должен считаться (V), а не подтверждённой процедурой. [I Got An Offer — vendor](https://igotanoffer.com/en/advice/google-team-matching)

[speculation] Поведение на matching:

- не повторять общий founder pitch;
- сначала выяснить bottleneck команды;
- связать с ним один конкретный личный опыт;
- показать, что именно проверите в первые 30–90 дней;
- снять риск fit/commitment.

Фраза:

“You said X is limiting the team. In Y, I personally owned Z. In the first month here I would test A before proposing a larger change.”

Вопросы:

- “What concrete problem is this approved headcount meant to solve?”
- “What would make the first 90 days successful?”
- “Where does this role have decision rights, and where does it work through interfaces?”
- “What changed recently that created this opening?”
- “Is there any concern about my background that I can address with a concrete example?”

O. Три привычки, которые Антону надо сознательно подавлять

1. Founder pitch вместо локального доказательства

Риск: визионерский регистр и превосходные степени могут усиливать подтверждённые recruiter concerns о fit, commitment и «cockiness», хотя сами слова напрямую не кодировались в исследованиях. [Organization Science founder experiment](https://pubsonline.informs.org/doi/10.1287/orsc.2022.1592)

Подавлять:

“We built a category-defining system that changes everything.”

Заменять:

“Under conditions X, we observed Y over period N. My personal decision was Z. The result has not yet been tested outside A.”

Телесный триггер: когда хочется произнести “world-class”, “first”, “revolutionary”, сначала назвать число, период и границу переноса.

2. «Я оркестрирую, модель исполняет»

Риск: собеседник может услышать отсутствие engineering ownership, даже если реальность обратная. Официальные технические руководства требуют наблюдаемых решений, качества кода, проверки и реакции на ошибки. [Microsoft technical interviewing](https://careers.microsoft.com/v2/global/en/hiring-tips/technical-interviewing), [Meta SWE guide](https://d3no4ktch0fdq4.cloudfront.net/public/course/files/Meta_SWE_full_loop_guide.pdf)

Подавлять:

“I’m an orchestrator rather than a coder.”

Заменять:

“I own the engineering outcome: decomposition, interfaces, evals, failure handling, review and incident response. Models produced some components under tests; here is one failure I detected and fixed.”

После каждого “we” автоматически добавлять:

“My personal ownership was…”

3. Закрывать тему декларацией вместо возвращения хода

Риск: опубликованные employer-rubrics ценят адаптацию к follow-up и снижают оценку за rambling либо игнорирование смены темы. [Stripe engineering guide](https://stripe.com/gb/guides/atlas/scaling-eng), [Meta engineering leadership guide](https://d3no4ktch0fdq4.cloudfront.net/public/course/files/SWE_engineering_leadership_-_onsite_guide.pdf)

Подавлять:

“That proves the architecture works.”

Заменять:

“That is the decision, evidence, and boundary. Would you like me to unpack the architecture, the failure, or the rollout?”

Внутреннее правило: «тезис → одно доказательство → граница → вернуть ход».

P. Решение: экранная шпаргалка по семи комнатам

Все точные формулировки ниже — [speculation], собранная из исследований и company rubrics выше; это не научно найденные скрипты.

1. Recruiter screen

Первая минута:

- Звук.
- 30–60 секунд: кто я → релевантная нить → почему эта роль.
- Стоп; не биография.

Середина:

- Факт 15–30 секунд, fit 45–90.
- Тезис → доказательство → пауза.
- Ограничения говорить прямо; не продавливаться.

Последняя минута:

- “What separates candidates who advance?”
- Спросить timeline.
- Одна строка интереса, без нового питча.

2. Project deep dive / HM

Первая минута:

- Проблема → моя ответственность → результат → главный trade-off.
- Предложить интервьюеру выбрать глубину.

Середина:

- Блоки: решение → почему → альтернатива → результат.
- После “we” назвать личный вклад.
- Перебили — поставить закладку и идти за вопросом.

Последняя минута:

- Результат.
- Самый дорогой trade-off.
- Что сделал бы иначе.
- Спросить текущий failure mode команды.

3. Coding

Первая минута:

- Прочитать.
- Пересказать контракт.
- Уточнить decision-changing constraints.
- Пример, план, затем код.

Середина:

- Инвариант → варианты → выбор → тест.
- Не озвучивать каждый символ.
- Ошибку назвать, исправить, перепроверить.

Последняя минута:

- Normal case, edge case, complexity.
- Не закончил: что работает → где разрыв → следующий patch/test.
- Не молча печатать до обрыва.

4. System design LLM/agent

Первая минута:

- Пользователь и outcome.
- Scale/SLO.
- Safety/failure boundary.
- Только затем компоненты.

Середина:

- Requirement → выбор → цена → mitigation → failure.
- Новое условие: что сломалось, что сохранилось.
- Явно разделять модель, контракт, eval и rollback.

Последняя минута:

- Success path.
- Failure path.
- Bottleneck.
- Главный остаточный риск и production gate.

5. Decomposition / ambiguous case

Первая минута:

- Решение, success criterion, assumptions.
- Короткая объявленная пауза.
- Дерево и начальная гипотеза.

Середина:

- Один вопрос → ответ → синтез.
- Проверять гипотезы по информационной ценности.
- Новые данные должны видимо менять приоритет.

Последняя минута:

- Recommendation.
- Две причины.
- Главный риск.
- Следующий различающий тест.

6. Customer simulation

Первая минута:

- Остаться в роли.
- Outcome → workflow → человек → constraint.
- Не начинать с продукта.

Середина:

- Короткая реплика → playback → вопрос.
- Возражение: признать риск, уточнить, предложить trade-off.
- Не обещать неизвестное.

Последняя минута:

- Решение.
- Владелец.
- Срок.
- Открытый риск.
- “What have I missed?”

7. Values / culture

Первая минута:

- Тезис.
- Реальный конфликт ценностей.
- Собственное решение и его цена.

Середина:

- Контекст коротко; действия, reasoning и learning подробно.
- При споре назвать competing value и update condition.
- Не декламировать сайт компании.

Последняя минута:

- Что изменилось в собственном поведении.
- Какой контрфакт изменил бы решение.
- Спросить о реальном недавнем конфликте ценностей.

🧒 Простыми словами: не надо звучать самым громким человеком в комнате. Надо сделать своё мышление проверяемым: коротко назвать решение, показать улику, признать границу и отдать собеседнику следующий ход.
