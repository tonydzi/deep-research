# DR26-10-02-HUB-02 — GitHub-шина, ядро/склад, пробуждение. Синтез (кворум 4 рельсы + 2 ломателя)

Заказ: голосовая Антона 02.10 (tg:<chat-id>:7719). Прошлый prior art: DR26-07-10 (Syncthing 180k → разнести склад/конфиг/рацию), DR26-07-29 (доставка сообщения в идущую сессию). Rail #5 (git_bus.py + репо tonydzi/machine-bus) построен 28.06, одно сообщение, мёртв.

## Сошлись (grok + gemini + оба ломателя)
1. **Разделение волта на ядро-в-git и мега-склад — ДА, у всех.** Это самая ценная часть идеи, и она не зависит от выбора шины. Паттерн уже доказан у нас конфигом `.claude` (git, снимок 15 мин). Sparse checkout/partial clone не заменяют физический сплит.
2. **Git-репо как высокочастотная шина сообщений — НЕТ, у всех.** Git не CRDT, параллельный push = конфликты; GitHub AUP прямо запрещает «excessive automated bulk activity»; рекомендация GitHub ≤6 пушей/мин; секреты в истории недоудаляемы (клоны/форки/SHA-кэш). Плюс red-flag в нашем же коде: git_bus.py на read делает `reset --hard origin` при сбое rebase — молча стирает локально закоммиченное незапушенное сообщение.
3. **Низкочастотная (2×/сутки) GitHub-синхронизация ядра — законно**, шум и лимиты не страшны на таком темпе.
4. **Событийное пробуждение — строить поверх существующего (Telegram doorbell / локальный флаг), не поверх новой шины.** GitHub webhooks: ответ за 10 с, без retry при таймауте — спящий хаб теряет событие навсегда.

## Разошлись
- **gemini: S5 максимальная жизнеспособность** (NATS JetStream на VPS-якоре + Tailscale, leaf nodes для офлайна, ~$5/мес) — «золотой стандарт».
- **ломатель-1: S5 = «правильный по учебнику, сломается по-нашему»**: брокер на Маяке = шина умирает вместе с ним (сегодня TG и Syncthing независимы); новый демон на 6 машинах × 3 ОС; июльский ДР это уже советовал — флот не взял, повтор без ответа «почему не взяли» = труп.
- **gemini: S4 (Issues) средне-высокая** как slow task queue; **ломатель-1: S4 убить первым** — ноль офлайн-копии, секреты в issue-истории не вычищаются вообще, ToS-риск.

## Рекомендация (моя, кофаундерская, с учётом панели)
Гибрид **S3-минус + S1**, AK-47:
1. **Ядро-репо без messages/**: отдельный приватный репо, генерация ИЗ волта В ОДНУ сторону (волт = истина, репо = витрина/дубль), ~300-1000 файлов (канон, регламенты, реестры, машинные JSON, OnAir-доска). Темп 2×/сутки + по событию «канон изменился».
2. **Пробуждение поверх существующего**: демон не «будит сессию», а поднимает локальный `wake.flag`; inbox-робот пиров = 2×/сутки + по флагу, cooldown ≥15 мин, кап 10/сутки, fail-closed в polling; будит только адресное (dst=я) со строгим WAKE-глаголом; разбуженный отвечает только SLEEP-глаголом (анти-петля). Переиспользовать WAKE/SLEEP_VERBS из tg_doorbell.
3. **Вынести из Syncthing-скана 7.4 ГБ черновиков + 3 ГБ оригиналов** — самая дешёвая починка реальной боли, GitHub не нужен вообще.
4. **S5 (NATS) не хоронить, а положить в parked** с условием пробуждения: если после пилота 1-3 замер покажет, что лаг доставки всё ещё болит.
Пилот 2 недели: ядро-генератор + счётчик чтений ядра пирами (§5.8). Ноль чтений = убить.

## ПОПРАВКА 02.10 вечер — ПЕРЕСИНТЕЗ по кворуму 4/6 (пришли glm и mistral)

**Единогласно у 4 вендоров + 2 ломателей:** ядро-репо — да (пилот уже построен: tonydzi/vault-core); messages/ внутри git — нет; S2 (реанимация rail #5 как есть) — убить; S4 (Issues) — не транспорт (годен максимум как слой «обращение к оператору», IssueOps-паттерн).

**Критерии вендоров разошлись (не усредняем):**
- gemini судил по АРХИТЕКТУРНОЙ правильности → S5 максимум (NATS JetStream, Leaf Nodes для офлайна, ~$5/мес);
- glm судил по ЦЕНЕ ПЕРВОГО МЕСЯЦА → S5 «❌ краткосрочно», рекомендует S3→S5 эволюцию + свежая идея «почтальон»: если git-шина, то ЕДИНСТВЕННЫЙ писатель на хабе (пиры кладут в Syncthing-папки, хаб коммитит от себя) — снимает конфликты by design;
- mistral судил по СЕМАНТИКЕ ДОСТАВКИ → S5 высшая: JetStream = ordering + ACK + offline catch-up + exactly-once дедуп, чего нет ни у одной нашей рельсы; наблюдаемость человеком лечится мостом в Telegram (он уже есть); пилот ~$0 с kill-критериями: латентность не лучше TG · >1% сообщений без ACK · >2 ложных пробуждений/нед · сопровождение >1 ч/нед → откат к S1;
- grok дал первички лимитов: ≤6 пушей/мин, push >2 ГБ режется, webhook-провалы GitHub НЕ перепосылает, их инцидент 13.09 (28 сервисов, один кластер БД) = GitHub сам SPOF.
- mistral про пробуждение: за NAT вебхуки не дотягиваются, единственный продакшен-push к пирам = Telegram long polling getUpdates → wake-flag строить на TG-рельсе (подтверждает дизайн ломателя-2).

**Прямое опровержение внутри веера:** gemini «NATS внедряется за 2 часа» vs glm «высокая цена первого месяца». Mistral разрешает спор kill-критериями: не спорить, а замерить за 2 недели и $0.

**Моя рекомендация обновлена (панель 3/4 против моего раннего parked — их сильнейший довод: JetStream даёт ordering+ACK+offline, которых нет ни у TG, ни у Syncthing, ценой одного Go-бинарника на уже оплаченном Маяке):** S5-пилот ПОДНЯТЬ из parked в shadow-пилот с kill-критериями mistral, параллельно ядру-репо (не конфликтуют). Возражение ломателя-1 (SPOF Маяка) закрыто: TG-рельса остаётся как было, NATS добавляется, не заменяет. Решение о пилоте = Антона (новый сервис на Маяке).
