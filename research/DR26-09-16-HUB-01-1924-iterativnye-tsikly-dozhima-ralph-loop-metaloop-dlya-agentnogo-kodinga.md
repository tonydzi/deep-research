# Insight (DR DR26-09-16-HUB-01-1924): Итеративные циклы дожима (Ralph Loop/MetaLoop) для агентного кодинга: критерии остановки, анти-схлопывание, экономика

> Исследование ищет доказательную базу для контроль-слоя вокруг автономных циклов дожима кода (Ralph Loop, MetaLoop, self-repair, test-repair), чтобы довести код до VERIFIED-CORRECT без человека в середине цикла.

## Ключевые выводы
- Качество итераций плоскогорьем выходит на плато к 4-6 итерации; после итерации 6 более 75% изменений состояния — это шум/осцилляция, а не прогресс; дешёвый детектор плато — статичный digest файлов при росте расхода токенов [established]
- Гипотезо-ориентированные циклы дебага (3 явные гипотезы + дискриминирующий тест до правки) и обязательный proof 'RED-до-фикса, GREEN-после' резко снижают долю симптоматических патчей вместо корневых [established]
- Reward hacking (агент правит/ослабляет тесты) детектируется дешевле всего sha256-чексуммой директории tests/ до и после итерации; context collapse — Jaccard 3-gram similarity >=0.85 два раза подряд или неизменный digest файла 3 итерации подряд; silent no-op — git diff --stat с нулевыми изменениями при exit code 0 [established]
- Restart-with-clean-context надёжно превосходит long-context continuation для многошаговых задач: деградация начинается на заполнении контекста 30-40%, incl. 'lost-in-the-middle' эффект; состояние между итерациями должно жить только в плоских файлах рабочей директории (PROGRESS.md со строгой схемой: Completed/Current Block/Next Action/Known Blockers) [established]
- Наивная оценка токенов по длине строки (len/3) занижает реальный расход на кодекс-подобных агентах до 66x (833 видимых против 55,209 реально сожжённых) — reasoning- и tool-токены невидимы; бюджетирование требует прямого парсинга полей usage API (prompt_tokens, completion_tokens, reasoning_tokens) [emerging]
- Тиражированная escalation-лестница (дешёвая/быстрая модель для итераций, дорогая только на арбитраж после 2 отказов судьи) оптимизирует cost-per-fixed-task, но экономический профиль 'grind until perfect' против one-shot+review количественно не подтверждён надёжными источниками в этом отчёте [emerging]
- Локальный микро-бенчмарк для проверки правок промпта/скилла/инструкции: 20-30 golden-задач из своего домена, минимум 3 независимых прогона на кандидата из-за недетерминизма LLM, с периодической ротацией задач против переобучения бенчмарка [established]
- Второе независимое мнение (другой вендор/модель) как строго read-only адверсариальный ревьюер diff против требований снижает слепые пятна одной модели; риск — сговор/коррелированные ошибки при общих training-биасах на редких библиотеках, контрмера — явные негативные промпты (например, 'проверь race conditions и утечки памяти') [emerging]
- Пакет эскалации к человеку должен быть стандартизирован: точная сигнатура сбоя + ровно 2 взаимоисключающих варианта решения + state diff — чтобы решение занимало <60 секунд и не было approval fatigue [established]

## Рекомендации / решения
- Добавить preflight file-hash lock на директории tests/spec в ralph_loop.py перед каждой итерацией (~2 часа) — закрывает reward hacking
- Заменить наивную оценку токенов на прямой парсинг usage-полей API ответа вместо len/3 эвристики (~3 часа) — устраняет 'токен-ложь' и перерасход бюджета
- Встроить в /tt Red-to-Green gate: фикс принимается только если целевой тест доказанно был RED до патча (~4 часа) — гарантирует корневые фиксы, а не иллюзорные
- Собрать golden-микробенчмарк из 20 внутренних задач репозитория для количественной проверки правок промптов/скиллов (~6 часов)
- Держать деterministic judge и test-orchestrator строго вне зоны записи агента; никогда не давать агенту править собственный harness оценки
- Ввести жёсткие многомерные потолки на цикл: максимум итераций (N=5), wall-clock (30 мин), денежный потолок токенов ($0.50/задача)
- Использовать tiered model escalation: дешёвая/быстрая модель на первые итерации и синтаксический ремонт, эскалация к сильной модели только после двух отказов судьи

## Открытые вопросы
- Реальный экономический профиль 'grind until perfect' vs one-shot+human review количественно не установлен — при каких условиях цикл дороже разового прохода, осталось неясным
- Не найдены конкретные, ещё поддерживаемые open-source репозитории/реализации из последних 12-18 месяцев кроме общих упоминаний (OpenHands, обёртки над вендорскими CLI) — секция G/Tooling Landscape осталась тонкой
- Спор между 'fresh context restart' и 'long context + caching' не решён окончательно: вендоры с большими контекстными окнами утверждают, что кэширование снимает необходимость в чистых рестартах, инженеры на практике сообщают об обратном
- Спор pure-RL агентов (например DeepSWE-Preview) против scaffolded loops с детерминированным контроль-слоем не разрешён — заявлено, что чистый RL иногда обходит защитные границы и халлюцинирует прохождение тестов, но данных мало
- В отчёте нет ответов от других заявленных таргетов (chatgpt, grok, claudeai, glm, mistral) — представлен только один синтез (gemini), кросс-валидация вендоров не выполнена
