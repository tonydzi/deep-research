# DR26-08-16-MACANTON-01-0731 · Codex+Claude над одним волтом — синтез 4 рельс

Связано: [[multi-agent-role-discipline]] · [[one-system-propagate]] · [[ak47-simplicity]] · [[prichina-kak-claim]] · [[coverage-and-docs-every-part]]

## 🧒 Простыми словами
Codex читает свои правила стопкой: сначала общий файл из `~/.codex`, потом файлы из папок проекта — сверху вниз. Стопка влезает в маленький рюкзак (32 КБ по умолчанию). Наш общий файл — 54 КБ, он один больше рюкзака. Значит часть правил в рюкзак не влезает, и никто об этом вслух не говорит. Ещё: Codex ищет «корень проекта» по папке `.git`. У волта `.git` нет — поэтому, если Codex запустить из подпапки волта, он ГЛАВНЫЙ файл правил волта просто не увидит. Оба сломанных места чинятся настройкой за час.

## Вердикт одной строкой
**Option A: сериализуем волт (лизы) / параллелим код (git worktree) + один источник инструкций + идемпотентные хуки.** Консенсус 4/4, уверенность [established]. Ни один вендор за июнь–август НЕ выпустил кросс-вендорный файловый лок — наша SQLite-доска с лизами остаётся единственным механизмом для волта.

## Консенсус (совпало на 3–4 рельсах)

1. **Порядок инструкций Codex** [4/4, established]: глобальный `$CODEX_HOME/AGENTS.md` грузится ПЕРВЫМ, затем проектные файлы от project-root вниз до cwd, всё КОНКАТЕНИРУЕТСЯ. Более глубокий файл стоит позже и «выигрывает» позицией в промпте — это мягкий override порядком, НЕ структурный merge и НЕ «ближайший файл побеждает» (правило agents.md.org). Глобальный текст из промпта не исчезает никогда.
2. **`AGENTS.override.md`** [4/4, established]: замена ТОЛЬКО файла в СВОЁМ каталоге. Не стирает ни глобальный слой, ни родителей, ни детей. ⛔ Использовать его как «выключатель 54-КБ глобала» нельзя — не сработает.
3. ⭐ **`project_root_markers` по умолчанию = `[".git"]` — ГЛАВНАЯ МИНА ДЛЯ ВОЛТА** [4/4, established]: волт не под git ⇒ Codex, запущенный из `06-Concepts/foo/`, project-root не находит и смотрит ТОЛЬКО текущий каталог. Защищённый 150-строчный `AGENTS.md` в корне волта в этом случае НЕ ЗАГРУЖАЕТСЯ ВООБЩЕ. Лечение: файл-маркер в корне волта + `project_root_markers` в `~/.codex/config.toml`.
4. **`project_doc_fallback_filenames` по умолчанию `[]`** [3/3]: `CLAUDE.md` Codex НЕ читает, пока не впишешь. ⛔ Все рельсы советуют НЕ вписывать: затащит огромный Claude-канон в 32-КБ бюджет Codex.
5. **approval/sandbox** [3/3, version-pinned]: `on-failure` не «недокументированный режим», а **DEPRECATED**. Для безлюдного `codex exec` — `sandbox_mode="workspace-write"` + `approval_policy="never"`. `codex exec --full-auto` **УДАЛЁН в 0.147** (PR #36054) → `--sandbox workspace-write`. В 0.147 добавлен `--approve-for-me` (авто-ревью, НЕ обход песочницы). 0.146.1 требует явного доверия каталогу: `[projects."/abs"] trust_level = "trusted"`.
6. **Конкурентность** [4/4, established]: кросс-вендорного лока НЕТ. Индустрия сошлась на git-worktree (Claude `--worktree`, Copilot `/worktree` 03.08, Meta Muse 05.08). Worktree **не помогает волту** (он не git). Главная опасность — тихий last-writer-wins: конфликта не возникает, поздняя запись молча стирает раннюю. ⇒ волт сериализуем, код параллелим.
7. **Хуки двоятся** [4/4]: все совпавшие хуки запускаются, несколько хуков одного события стартуют ПАРАЛЛЕЛЬНО, один не может остановить другой. Общий скрипт обязан быть идемпотентным, брать контекст из stdin-JSON (не из env), жить на кодах выхода 0/2.
8. **Массовую генерацию AGENTS.md/докстрингов — НЕ делать** [chatgpt+claudeai, established]: Gloaguen et al., arXiv:2602.11988 (ETH SRI) — прироста успеха нет, стоимость +20%; контр-результат Lulla, arXiv:2601.20404 — рантайм −28.6%, токены −16.6%. Примирение: считали разное (полная стоимость с чтением файла vs эффективность ПОСЛЕ чтения). Вывод обеих сторон один: файлы должны быть КОРОТКИЕ и написанные человеком.

## ⚠️ Противоречия между рельсами (не замазывать)

**A. `project_doc_max_bytes` — на файл или на всю цепочку?**
- `claudeai`: **однозначно кумулятивный** бюджет, вычитано ИЗ ИСХОДНИКА (`agents_md.rs`: `remaining = project_doc_max_bytes`, затем `saturating_sub` по каждому файлу; `config/mod.rs`: `PROJECT_DOC_MAX_BYTES = 32*1024`). Глобальный файл входит в тот же счётчик ПЕРВЫМ ⇒ **режется самое глубокое и самое специфичное**.
- `grok`: официальные страницы OpenAI **противоречат друг другу** — guide говорит «combined size», config-advanced говорит «how much to read from EACH file». «Из документации нельзя понять, в каком мире ты живёшь. Измерь.»
- `chatgpt`: точная граница обрезки — `[no source found]`.
- **Как читать:** чтение исходника у claudeai — сильнейшая улика, но проверять надо на СВОЕЙ версии. ⭐ И это неважно для решения: **54-КБ глобальный зеркальный файл больше 32-КБ дефолта при ЛЮБОМ прочтении** — либо он сам обрезан, либо он съедает бюджет у вложенных. Действие одинаковое.

**B. Симлинки в скиллах — можно ли один каталог на два харнеса?**
- `claudeai`: пользовательские скиллы под `~/.codex/skills` ПРОПУСКАЮТСЯ, если `SKILL.md` или каталог — симлинк (#17344, #8943); «одна общая папка скиллов через симлинк» отвергнута.
- `grok`: официальная build-skills говорит «Symlinked skill folders are followed», а правильный путь — `~/.agents/skills`, тогда как `~/.codex/skills` помечен как unverified.
- **Похоже, речь о РАЗНЫХ путях** (легаси `~/.codex/skills` против текущего `~/.agents/skills`). Не разрешено → перед ставкой измерить.
- Формат `SKILL.md` при этом совместим у всех рельс; расходятся именно ПУТИ поиска.

**C. Качество рельсы GLM низкое.** Даёт цифры («докстринги 69%→90% за один проход», «llms.txt ускоряет загрузку контекста на 40–60% в A/B») со ссылками-обрубками (`github`, `community.openai`) без URL и дат. chatgpt и claudeai по этим же вопросам честно пишут `[no source found]`. ⇒ цифры GLM в решения НЕ берём.
