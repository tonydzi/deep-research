## Вердикт (исправлен 26.10)
1. Роли: **универсального победителя нет.** Практики расходятся: Grok «самая частая рабочая схема: Claude пишет, Codex read-only ревьюит» (`grok.md:70`), ChatGPT ставит Claude оркестратором, claude.ai и Mistral выводят «Codex пишет» из одного замера. 4 из 4 «Codex пишет» не было.
2. Единственный контролируемый замер (arXiv 2607.21656, n=116 задач LiveCodeBench, статическое ревью, проверен Claude напрямую 25.10): Claude один 91,4%; Codex один 71,6%; Claude ревьюит Codex → 89,7% (ниже, чем Claude один); Codex ревьюит Claude → 82,8% (ревью вредит); самоконтроль Codex → 84,5%, Claude → 91,4% без изменений. На этом узком бенчмарке лучший расклад = **Claude пишет, ревью Codex только советом, не правкой**. На реальных репозиториях и бытовых задачах 001 не измерено.
3. Транспорт внутри машины: прямой вызов CLI + обратный звонок; страховка Stop-хук `asyncRewake`. Журнал задач SQLite `aibus_lite`; мьютекс записи файлов = `workspace_write_lease.py` (не aibus_lite). Telegram между машинами и для оповещений. ⚠️ `codex-claude-notify` по README только macOS/Linux, Windows не поддержан (находка Codex).
3а. Живое доказательство (25.10, после ДР): Stop-хук `asyncRewake` будит Claude после конца хода на нашем Windows-хабе (проба 68 с; живая задача 001 be65ff4b: 2 разбуженных раунда и ACCEPT за 3 мин). Сокет `crossSessionInbound` НЕ доказан живым прогоном.
3б. Кворум: 4 ноги в очереди, но НЕ в максимальном режиме (ChatGPT `deep-research-mini`, Grok Expert вместо Heavy, Mistral Think вместо DR). Пятый вендор Gemini a2 собран Codex без нового запуска (`_scratch/DR26-10-25-HUB-02-1107-gemini-a2-full.txt`, sha FFACB1C0…); в нём 41,7/19,8 из arXiv 2607.04697 ошибочно названы обнаружением багов, это КОНФЛИКТЫ мёржа. Вывод о транспорте держится; вывод о ролях = гипотеза для эксперимента S3.
4. «Claude отвечал в 3 из 17» по версии claude.ai почти наверняка про механику пробуждения (bypass-permissions держит входящее 5 минут), а не про роли. Это гипотеза, проверяется экспериментом, не факт.
5. Слабое место: сама ревью-петля (ложный консенсус, выдуманные замечания), второе: RAM от MCP в каждой сессии.
6. Протокол раундов: 1 ревью + максимум 1 повтор (claude.ai), до 3 (Mistral, Grok: 2). Дальше человек.

## Прямое опровержение внутри веера
ChatGPT: «независимых измерений кросс-ревью нет». claude.ai, Grok и Mistral привели arXiv 2607.21656 с цифрами. ChatGPT-нога слабее (mini-модель, `resolved_model_slug: deep-research-mini`, список цитат без названий и URL, одиночные утверждения без источников, Agent Teams назван «облачным подсервисом», что не сходится с документацией по версии claude.ai). Считается в кворум, веса не имеет.

## Уникальное у каждого
- claude.ai: механизм пробуждения без демона и MCP (cross-session inbox v2.1.224+, `crossSessionInbound`, `asyncRewake` с кодом 2, Codex hooks стабильны с 0.124.0), конверт с типизированными несогласиями AGREE/DISAGREE EVIDENCE/DISAGREE CONCERN, RAM-замеры (17 ГБ на 5 сессий, kernel panic на 15×34 MCP), эксперимент на 10 задачах с метрикой reply rate (база 3/17, цель ≥9/10).
- Grok: перепись 30+ случаев, матрица внутренние файлы против внешнего канала, «не плодить MCP в каждой сессии».
- Mistral: открытый issue openai/codex#54991 (idle-сессию Codex будит только очередь, приходит как user-роль), ссылка на $200 за ночь на 91 Codex-ревью как довод за кап раундов.
- ChatGPT: Baton Pass (передача эстафеты с коммитом перед передачей), Sendbird cc-plugin-codex.

## Сильнейший довод против выбранной связки
Замер сделан на олимпиадных задачах LiveCodeBench с одним проходом без запуска тестов; на реальных репозиториях результат может быть другим (прямо сказано авторами и claude.ai). Кроме того, цифры «версия сокета 2.1.224» и поведение `crossSessionInbound` я не проверял у нас: это вторичный пересказ документации, а не наш прогон. Если эксперимент на 10 задачах не даст reply rate заметно выше 3/17, вывод «причина в пробуждении» отпадает, и корень в ролях или промптах.
