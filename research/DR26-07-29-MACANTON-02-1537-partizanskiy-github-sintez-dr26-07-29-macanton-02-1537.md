## 1. Сошлись (две независимые линзы → берём как основу)

1. **Issue-исследование дороже PR.** Оба поставили «reproducer + root cause + минимальный тест» на 1-е место, PR — ниже. Отдача выше, ответ быстрее (1–7 дней), и мейнтейнеру не надо думать за нас.
2. **Code review чужих PR — самый дешёвый вход с самым быстрым ответом** (тот же день–7 дней). У нас 0 за всё время. Обе линзы независимо назвали это недоиспользованным каналом.
3. **Холодный шаблонный PR — трата.** Не рекламный баннер. Наши 0/7 — не невезение, а ожидаемый результат.
4. **Цель не выбирается по звёздам.** Мерить надо time-to-first-**human**-response (боты исключить), долю внешних PR с ответом человека, число решений в месяц. Большой репо с мёртвой очередью хуже среднего с живой.
5. **Contribution graph веса почти не имеет.** Он кодирует наличие активности, не качество и не принятие.
6. **Личный аккаунт = слой доверия, организация = слой артефактов.** Входящее пишут человеку. Безликая лаборатория доверия не собирает.
7. **Одна узкая ниша, 1–2 репо.** Заход в 10–15 экосистем убивает шанс стать узнаваемым хоть в одной.
8. **Раскрытие «писал агент» само по себе не решает** — работает только в паре с доказательством человеческого владения (какие команды прогнал, какие инварианты проверил, чего не проверял).
9. **Курируемые списки, templates, Pages, Sponsors, релизы без пользователей — не канал привлечения.** Обе линзы — в самый низ.
10. **Срок до входящего — месяцы, не недели.** Независимые наборы кейсов дали один паттерн: 6–9 месяцев сфокусированной работы в ОДНОЙ подсистеме.

## 3. Уникальное у ChatGPT (Grok этого не принёс)

- **🔴 Платформа изменилась в 2026 — объём стал ОТРИЦАТЕЛЬНЫМ сигналом.** GitHub 17.06.2026 дал мейнтейнерам лимит на число одновременных открытых PR от авторов без write-доступа, а 13.02.2026 — возможность вовсе отключить внешние PR. Godot (30.06.2026) и tldraw (17.01.2026) ужесточили правила из-за review overload. То есть «много активности» больше не нейтрально.
  - https://github.blog/changelog/2026-06-17-limit-open-pull-requests-for-users-without-write-access/
  - https://github.blog/changelog/2026-02-13-new-repository-settings-for-configuring-pull-request-access/
  - https://godotengine.org/article/contribution-policy-2026/ · https://tldraw.dev/blog/stay-away-from-my-trash
- **Протокол проверки цели ДО первого вклада:** снять последние 30 внешних PR + 30 issue, посчитать p50/p90 первого человеческого ответа, долю с ответом за 7 дней, merged/closed, число уникальных живых ревьюеров. **Kill-критерий: <30% внешних вкладов получили человека за 14 дней → цель отложить.** Метрики по CHAOSS (боты исключаются отдельно).
- **Именованный ранжир целей под нашу нишу:** `modelcontextprotocol/python-sdk` 5/5 · `pydantic/pydantic-ai` 5/5 (формализованный путь issue → champion → PLAN.md → assignment → PR; их же фраза, что несогласованный PR может не попасть в очередь независимо от качества кода) · `openai/openai-agents-python` 5/5 · `huggingface/transformers` 3/5 · `vllm` 2.5/5 · **`tldraw` и `godot` — не цель** (внешние PR закрыты/ограничены).
- **Статистика по агентским PR:** 1,7% PR с расхождением описания и кода имели acceptance 28,3% против 80,0% (arxiv 2601.04886); немерженные агентские PR чаще больше по размеру и не проходят CI (2601.15195); фронтир-модели находят лишь 15–31% проблем, отмеченных людьми на ревью (2603.26130) → **демонстрация человеческого high-context ревью сейчас дифференцирует сильнее, чем демонстрация генерации кода.**
- **Готовый шаблон disclosure** с блоком «что именно проверил человек» — и антипример «This PR was generated by an agent. Please review» (перекладывает стоимость на мейнтейнера).

## 5. Что противоречит НАШИМ замерам (мы были неправы)

1. **«36–57 клонов при 0 просмотров = роботы-зеркала» — перебор.** GitHub-аналитика не раскрывает природу клона. Корректно: *клоны не являются доказательством человеческой аудитории*. Утверждение «все клоны — роботы» сильнее данных. → правим формулировку в скилле.
2. **«3 своих репо не получили трафика → свои репо бесполезны» — неверный вывод.** Репо пытались быть пунктом назначения, не будучи встроенными в чужой инженерный граф. Строить надо репо, **без которого нельзя компактно доказать upstream-находку**.
3. **«Холодные PR не работают → PR не нужен» — неверное обобщение.** Не работает несогласованный шаблонный PR. Assigned PR, PR после research-issue, regression-test PR — другой класс, и наши 3 успеха ровно из него.
4. **n=17 слишком мал для точной цифры.** 3/17 = 17,6%, но 95% интервал Уилсона ≈ 6,2–41,0%. Направление сигнала сильное, величина — нет. 0/7 не доказывает нулевую вероятность, но для stop-решения уже достаточно.
5. **3 недели — срок остановить PR-веер, но НЕ срок проверить путь** issue → повторное взаимодействие → доверие ревьюера → входящее.
