# Insight (DR DR26-07-28-HUB-10-2339): Grok Coding (Grok 4.5 / Grok Build) от SpaceXAI: возможности, слияние с Cursor, сравнение с Claude Fable 5 и ChatGPT

> Отчёт разбирает, что такое Grok Coding (Grok 4.5 + Grok Build CLI) после покупки Cursor компанией SpaceX за $60 млрд, его архитектуру, цену, бенчмарки и практическую пользу в сравнении с Claude Fable 5 и ChatGPT.

## Ключевые выводы
- Grok Coding — это Grok 4.5 (MoE, ~1.5T параметров, фреймворк V9 xAI) + Grok Build CLI, вышедший в июле 2026 от SpaceXAI (бывшие Twitter/X и xAI под управлением Илона Маска)
- 16 июня 2026 SpaceX купил Cursor (Anysphere) за $60 млрд акциями; данные о поведении разработчиков Cursor вошли в обучающую выборку Grok 4.5, инженеры Cursor перешли в xAI/SpaceX
- Цена Grok 4.5: $2/$6 за 1М входных/выходных токенов (ускоренная Grok Code Fast 1 — $4/$18) — вдвое дешевле Claude Fable 5 ($10/$50) и близко к ChatGPT ($1/$6)
- По бенчмаркам Grok 4.5 немного уступает конкурентам: DeepSWE pass@1 ~62% против Fable 66.1% и GPT-5.5 ~64.3%; Terminal Bench 83.3% против Fable 84.3%
- Контекстное окно Grok 4.5 — 500K токенов (у Fable 5 — 1М, у GPT-5 — 400K)
- Функционал Grok Build: режим планирования (plan mode с одобрением плана), diff-ревью изменений, параллельные субагенты для подзадач, маркетплейс плагинов (GitHub, Jira/Linear, БД, браузер), поддержка AGENTS.md
- Ключевые риски: независимых сторонних бенчмарков Grok 4.5 практически нет (оценки только от SpaceXAI), юридические риски лицензий на сгенерированный код, вопросы приватности данных при отправке в облако SpaceXAI, риск вендор-лока из-за вертикальной интеграции (SpaceX владеет данными, платформой Cursor и моделью)
- На момент релиза (июль 2026) Grok Build в ранней бета-версии, доступен только подписчикам высокого уровня (SuperGrok/X Premium Plus)

## Рекомендации / решения
- Внедрять Grok Coding поэтапно: начать с пилота на некритичных компонентах (юнит-тесты, вспомогательные скрипты, документация), заранее определив метрики (время разработки, % пройденных тестов, снижение ошибок)
- Настроить AGENTS.md под свой стек и проверить работу плагинов (GitHub, CI/CD) перед масштабным использованием
- Обязательно сопровождать сгенерированный код проверкой лицензий (GPL/MIT конфликты) и статическим анализом безопасности (SAST) — ответственность за код остаётся на компании
- Для перехода с Cursor миграция почти бесшовна — Grok 4.5 уже встроен в Cursor нативно, старые настройки (AGENTS.md, вебхуки) продолжают работать
- Использовать низкую цену Grok как аргумент для дешёвых массовых задач (генерация шаблонов, тесты), а не как замену более точным моделям (Fable) в критичных участках

## Открытые вопросы
- Реальная точность и качество Grok 4.5 не подтверждены независимыми бенчмарками — все цифры пока от самой SpaceXAI
- Как именно SpaceXAI обрабатывает конфиденциальность/хранение запросов (нет прозрачной политики, требуется юридическая проверка)
- Нет ясности по политике лицензионной чистоты сгенерированного кода (риск попадания GPL-фрагментов)
- Неясно, когда Grok Build выйдет из беты и станет доступен шире текущей узкой подписочной аудитории
