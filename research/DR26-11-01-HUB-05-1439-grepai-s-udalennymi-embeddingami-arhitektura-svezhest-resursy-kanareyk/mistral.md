The <code>--mode</code> flag … is deprecated … A tree-sitter extractor exists in the source tree behind the <code>treesitter</code> build tag (CGO required) … Release binaries are built without it."</strong> (<a target="_blank" rel="noopener noreferrer nofollow" href="https://github.com/yoanbernabeu/grepai/blob/9cf58bf41dcd45813ec697b2fcda43cbabb08c84/docs/src/content/docs/trace.md">trace docs</a>; confirmed by the v1.0.0 changelog deprecation entry: "the flag never changed symbol extraction (always the regex extractor)").</p><p>So: <strong>precise mode does not participate in indexing, in query resolution, or in release binaries at all.</strong> Syntax-level precision ≠ semantic LSP resolution, and grepai has neither in shipped form.</p><p><strong>Documented and issue-verified limits for ambiguous/dynamic code</strong> (all source-linked):</p><ul><li><p><strong>Same-name symbols</strong>: <code>LookupCallees</code> ignored its file argument and merged callees across files; MCP picked <code>symbols[0]</code> while the CLI disambiguated differently — "silent wrong call graphs for agents" (<a target="_blank" rel="noopener noreferrer nofollow" href="https://github.com/yoanbernabeu/grepai/issues/372">issue #372</a>, fixed in v1.2.0 by deterministic file-then-line ordering; <strong>"Callees of same-name definitions are still merged"</strong> remains true even after the fix — <a target="_blank" rel="noopener noreferrer nofollow" href="https://github.com/yoanbernabeu/grepai/blob/9cf58bf41dcd45813ec697b2fcda43cbabb08c84/CHANGELOG.md">v1.2.0 changelog</a>).</p></li><li><p><strong>Class/method scoping</strong>: unsupported (<code>Class::method</code> syntax rejected); in PHP-style OOP codebases, <code>trace callees "execute"</code> returned <strong>"640 results across completely unrelated classes"</strong>, and targeting a class name returns 0 callees (<a target="_blank" rel="noopener noreferrer nofollow" href="https://github.com/yoanbernabeu/grepai/issues/212">issue #212</a>).</p></li><li><p><strong>Imports/aliases/overloads/dispatch/inheritance/callbacks/decorators</strong>: no import resolution or alias tracking is documented anywhere in the trace docs — edges are name matches between call sites and definitions. Ruby bare calls (<code>route 'GET', path</code>) are explicitly undetectable (<a target="_blank" rel="noopener noreferrer nofollow" href="https://github.com/yoanbernabeu/grepai/blob/9cf58bf41dcd45813ec697b2fcda43cbabb08c84/docs/src/content/docs/trace.md">trace docs</a>). Overload resolution, dynamic dispatch, and decorator indirection are therefore <strong>not modeled</strong> [no source found claiming they are]; treat trace as "who syntactically mentions this name inside a call shape", not "who invokes this definition".</p></li><li><p><strong>Python</strong>: a <code># don't</code> comment used to hide every later call in the file; <code>//</code> floor division was treated as a comment; docstring handling was broken — fixed in v1.0.0 (<a target="_blank" rel="noopener noreferrer nofollow" href="https://github.com/yoanbernabeu/grepai/blob/9cf58bf41dcd45813ec697b2fcda43cbabb08c84/CHANGELOG.md">changelog</a>). This history shows the regex extractor's failure modes are real and recent.</p></li><li><p><strong>Correctness drift CLI vs MCP</strong>: fixed in v1.2.0 (shared disambiguation code) — but only in v1.2.0, i.e. two days old at research time.</p></li></ul><p><strong>[established] A fair fixture protocol (proposed, runnable without any cloud spend — trace never calls the embedding provider).</strong> Build a fixture repo with: (a) two same-name symbols in different files (<code>Init</code> in <code>a.py</code>, <code>Init</code> in <code>b.py</code>); (b) import + alias (<code>from x import Init as I; I()</code>); (c) overloaded functions; (d) class methods with inheritance and <code>super()</code> dispatch; (e) callbacks and decorators (Python <code>@wraps</code>, JS higher-order); (f) dynamic dispatch (Python duck typing, TS union types); (g) dynamic feature-detect calls (<code>getattr(obj, name)()</code>, <code>obj[name]()</code>); (h) PowerShell modules calling functions (expected: no trace output). Oracle: run <code>pyright --outputjson</code>, <code>gopls</code>/<code>gopls callhierarchy</code>-equivalent (Go fixture), and <code>tsserver</code>/<code>tsserver.findreferences</code> on the same tree; seal the source-truth answer set (by symbol: exact caller/callee file:line lists) from the independent answerers. Score grepai trace against the oracle with precision/recall per category (a)–(h), and separately record what it <em>displays</em> (its caller/callee lists) versus what is <em>correct</em>. Do not equate a pretty call-graph printout with resolution correctness — the #212/#372 history shows display and correctness have diverged in this product.</p><hr contenteditable="false"><h2>E. Freshness</h2><p><strong>[established] Watcher is optional.</strong> <code>grepai index</code> performs the same full synchronization (vector + symbol + optional RPG) and <strong>exits without starting a watcher or daemon</strong>; it takes the same writer lock, so it fails while a watcher runs. Recommended by the docs for git hooks (<code>.git/hooks/pre-commit</code>) and CI (<a target="_blank" rel="noopener noreferrer nofollow" href="https://github.com/yoanbernabeu/grepai/blob/9cf58bf41dcd45813ec697b2fcda43cbabb08c84/docs/src/content/docs/watch-guide.md">watch docs</a>, <a target="_blank" rel="noopener noreferrer nofollow" href="https://github.com/yoanbernabeu/grepai/blob/9cf58bf41dcd45813ec697b2fcda43cbabb08c84/CHANGELOG.md">v0.39.0 changelog</a>). This matches our "on-demand, no background watchers" constraint exactly: index on demand (or pre-commit), search on demand, no resident processes between commands.</p><p><strong>[established] Event handling.</strong> Debounce 500 ms; create/modify → re-index; delete → remove from index; rename-over-original (atomic editor saves!) — a delete/rename event for a file still on disk is re-qualified as a modification; this was a major bug class (editors and <code>git checkout</code> writes silently emptied the index) fixed in v0.36.1 (<a target="_blank" rel="noopener noreferrer nofollow" href="https://github.com/yoanbernabeu/grepai/blob/9cf58bf41dcd45813ec697b2fcda43cbabb08c84/docs/src/content/docs/watch-guide.md">watch docs</a>, <a target="_blank" rel="noopener noreferrer nofollow" href="https://github.com/yoanbernabeu/grepai/blob/9cf58bf41dcd45813ec697b2fcda43cbabb08c84/CHANGELOG.md">v0.36.1 changelog</a>). <strong>Folder moves/deletes and ignore-rule changes leave results stale while a watcher runs — issue #310 is still open</strong> (<a target="_blank" rel="noopener noreferrer nofollow" href="https://github.com/yoanbernabeu/grepai/issues/310">#310</a>); the one-shot <code>index</code> path reconciles at each run, which is another argument for one-shot over watcher in our pilot.</p><p><strong>[established] Rename/move and embedding reuse.</strong> As of <strong>v1.2.0, renamed/moved/copied files are re-embedded</strong> (previously they silently reused vectors computed under the old path header, skewing search; fix #366). Identical files at the same project-relative path (worktrees) still share vectors; unchanged chunks of an edited file are reused from the content-hash cache (<a target="_blank" rel="noopener noreferrer nofollow" href="https://github.com/yoanbernabeu/grepai/blob/9cf58bf41dcd45813ec697b2fcda43cbabb08c84/CHANGELOG.md">v1.2.0 changelog</a>). So: <strong>rename does NOT reuse embeddings — budget a re-embed of the whole file per rename.</strong></p><p><strong>[established] Crash/restart/concurrency.</strong> Index saved every 30 s while watching + on clean shutdown; atomic temp-file-then-rename writes; corrupt GOB quarantined to <code>index.gob.corrupt</code> and rebuilt (self-healing); one writer per project enforced by <code>.grepai/writer.lock</code> (lock released on crash); readers (search/trace/MCP) run concurrently with the writer. v1.2.0 additionally fixed: chunks kept until new embeddings succeed (no data loss on failed OpenAI batch), document chunk-lists cleared on delete (crash window no longer hides files), and the daemon PID lock held for the daemon's whole life (<a target="_blank" rel="noopener noreferrer nofollow" href="https://github.com/yoanbernabeu/grepai/blob/9cf58bf41dcd45813ec697b2fcda43cbabb08c84/CHANGELOG.md">v1.2.0 changelog</a>). Additive Isolated Canary (preregistered protocol)</h2><p><strong>Design principles:</strong> additive to CodeIndexer (baseline owner supplies the common protocol; its baseline is never mutated), isolated (snapshot copies only), zero-new-spend (only existing-credit API orgs), no shared config changes, fully reversible.</p><ol><li><p><strong>Snapshot.</strong> Take immutable copies (zip + SHA-256 manifest) of representative <strong>owned</strong> Python, JS/TS (and, to quantify the known gap, one PowerShell module) trees from the Hub. Include only extensions actually present in those trees. <strong>Secret scan first</strong>: run a credential scanner (e.g. gitleaks) over the snapshot before grepai ever sees it; any hit → file goes into <code>.grepaiignore</code> (Section E) or is redacted. Record the manifest; record <code>grepai --version</code> = v1.2.0.</p></li><li><p><strong>Preregister thresholds (before any measurement):</strong> e.g. — proceed to fleet discussion only if: (a) grepai+CodeIndexer ≥ CodeIndexer alone on ≥ 80% of RU <strong>and</strong> EN navigation/exact/known-symbol tasks (semantic recall@5 ≥ 0.7 with precision ≥ 0.8); (b) no-answer correctness: zero confident wrong-file answers on the no-answer task set; (c) one-shot search wall time ≤ 3 s and peak RAM ≤ 2 GB on the Hub snapshot; (d) incremental churn ≤ 10% of full-index cloud tokens over a scripted 50-edit session; (e) zero secrets in provider payload (verified by counting requests + a canary token planted in a decoy <code>.env</code> that must NOT appear in results or in a proxy capture). Thresholds are set by Anton before runs; they are not adjusted after results are seen.</p></li><li><p><strong>Task set (RU + EN):</strong> known-symbol lookup, exact-string lookup (hybrid on), intent/semantic navigation, call-graph navigation (<code>trace callers/callees/graph</code>), and no-answer questions (code the snapshot does not contain). Source truth sealed (hash-committed answer file) from the independent answerers.</p></li><li><p><strong>Arms &amp; order:</strong> baseline (CodeIndexer alone) vs baseline+grepai, same snapshot, same question order, counterbalanced across answerers; ≥ 2 independent answerers (different operators) + 1 judge blind to arm. <strong>Count ALL serialized delivered context</strong> — wrappers, echoes, tool-call frames, everything the agent consumes — not just grepai stdout; record actual grepai invocations (expect ≥ 1 per task in the +grepai arm) and accuracy/misses/false answers.</p></li><li><p><strong>Metrics:</strong> per task: correct (y/n), miss, false answer, delivered context bytes/tokens, wall time, cloud tokens (from provider usage dashboard), requests; per arm: peak RAM, CPU-seconds (machine + per-process), disk writes (<code>.grepai/</code> size delta), network bytes; index build time; <strong>1-shot / cold</strong> (the production profile) recorded separately from warm (watcher running — measured only for reference, not as the target profile).</p></li><li><p><strong>Mutation tests on copies only:</strong> create/edit/rename/move/delete files in the snapshot copy; verify index behavior (re-embed volume from usage dashboard; rename must trigger file re-embed per v1.2.0), then <code>grepai index</code> again and re-run 10% of tasks to detect staleness (folder-move staleness, #310).</p></li><li><p><strong>Functional use vs comparative benefit:</strong> separately record (a) does grepai work at all per its own docs (functional), and (b) does the fleet answer better/faster/cheaper with it than CodeIndexer alone (comparative). A functional PASS is <strong>not</strong> a fleet PASS — no PASS from install/ACK/exit-0.</p></li><li><p><strong>Abort/rollback:</strong> at any point — <code>grepai watch --stop</code> (if ever started), delete the snapshot copy's <code>.grepai/</code> directory, remove the <code>## grepai - Semantic Code Search</code> marker section from any agent files (agent-setup is marker-scoped and reversible), unset env keys, <code>brew uninstall grepai</code> / remove the binary. Nothing else was touched: no system config, no shared stores, no MCP registration.</p></li><li><p><strong>Second-OS readback:</strong> after the primary run on the Windows Hub, repeat the readback sequence (index → 20-task subset → mutation subset) on the Apple Silicon Mac Studio from the same zip: confirm identical file counts/chunks via <code>grepai status</code>, confirm the backslash/separator fixes hold (v1.0.0 Windows path fixes), record per-OS RAM/wall-time deltas. A GOB index is not portable across machines — reindex per machine (expected, not a bug).</p></li></ol><hr contenteditable="false"><h2>H. Skeptical Recommendation</h2><p><strong>Verdict: PARK.</strong> Do not add grepai with remote embeddings to the CodeIndexer-first fleet workflow at this time. Run the Section G canary <strong>only</strong> under the narrow exception below.</p><p><strong>Decision options:</strong></p><div class="tableWrapper"><table style="min-width: 75px;"><colgroup><col style="min-width: 25px;"><col style="min-width: 25px;"><col style="min-width: 25px;"></colgroup><tbody><tr><th colspan="1" rowspan="1"><p>Option</p></th><th colspan="1" rowspan="1"><p>What it means</p></th><th colspan="1" rowspan="1"><p>Trade-offs / risks</p></th></tr><tr><td colspan="1" rowspan="1"><p><strong>KEEP (adopt)</strong></p></td><td colspan="1" rowspan="1"><p>Fleet-wide rollout with cloud embeddings</p></td><td colspan="1" rowspan="1"><p>Cheapest embeddings in the market ($0.02/1M); but: maintainer-only project 4 days into 1.x; PowerShell invisible; RU quality unknown; 1536-dim GOB RAM conflicts with the fleet's resource goal; benefits evidenced only by a self-run, quality-blind benchmark. <strong>Not supported by current evidence.</strong></p></td></tr><tr><td colspan="1" rowspan="1"><p><strong>TRY (narrow canary)</strong></p></td><td colspan="1" rowspan="1"><p>Single repo, CLI-only, one-shot, zero-spend, preregistered thresholds (Section G)</p></td><td colspan="1" rowspan="1"><p>Directly resolves the biggest unknowns (RU/EN quality on our code, real RAM on Hub/Mac Studio, delivered-context effect vs CodeIndexer) for ≈ $0.02–0.50 of embeddings <em>if</em> an existing-credit API org exists; otherwise it is blocked by the budget gate. Confidence tier: <strong>[established]</strong> for the architecture, cost and language facts driving the decision; <strong>[speculative]</strong> that grepai+cloud embeddings would beat CodeIndexer alone on our mixed RU/EN, Python/JS/TS/PowerShell fleet — that is exactly what the canary would settle.</p><p><strong>Strongest argument against adoption (steelman of the other side):</strong> grepai is genuinely cheap per token, architecturally daemon-free, MIT, actively fixed (the v1.2.0 fixes are substantive and responsive), and its Claude-Code-facing claim — that ranked chunks replace dozens of greps and file reads — matches a real, widely-reported pain (the launch thread's 280k views). If our agents routinely burn context re-reading large TS/Python repos in English, a $0.02/1M-index tool with trace as a free local bonus could plausibly pay for itself in agent context alone, and parking forgoes that for months. The counter: pain ≠ this tool; the evidence for <em>this</em> tool is self-produced, and its resource profile and language gaps land exactly on our fleet's weak points — which is why the cheap, reversible canary (not adoption, not dismissal) is the rational middle.</p><p><strong>Unresolved gaps (each mapped to its settling experiment):</strong></p><ol><li><p>RU query quality with <code>text-embedding-3-small</code> (and with <code>dimensions: 768</code>) — canary task set, RU/EN counterbalanced.</p></li><li><p>Real peak RAM / wall time on Windows Hub + Intel Mac Pro at our corpus sizes — canary resource capture (docs numbers are author-provided).</p></li><li><p>Delivered-context effect vs CodeIndexer baseline — canary's count-everything serialized-context accounting.</p></li><li><p>PowerShell invisibility — confirmed in docs; settling experiment: custom_extensions semantic-only test to quantify what (if anything) search recovers without trace.</p></li><li><p>No-answer behavior (no threshold exists) — canary no-answer task set; a "confident miss" rate above preregistered ceiling is a hard stop.</p></li><li><p>Provider retention for Synthetic/OpenRouter/Requesty — read their terms before any confidential code is embedded; OpenAI's 30-day abuse-log default with ZDR-by-approval is the current official position.</p></li><li><p>Independent benchmarks — none exist; if the project publishes none and the canary is never run, the decision stays PARK by default.</p></li></ol><p><strong>Fleet-PASS rule (explicit):</strong> a fleet PASS requires the canary's preregistered thresholds to be met on both OS readbacks with all serialized context counted and zero secret-leak canary tokens observed — install success, tool ACKs, and exit code 0 prove nothing.</p><hr contenteditable="false"><h2>Open Questions</h2><ul><li><p>Does OpenAI bill failed/retried embedding requests (429/5xx) beyond
