## 2. Расхождения и противоречия

### 2.1 Есть ли отдельные японские каталоги

- ChatGPT называет **AgentSkills.tokyo** и **claude-skills.jp** живыми японскими каталогами.
- Grok прямо пишет: dedicated JP skill directory не найден; японский каталог фактически равен Qiita/Zenn.
- Claude и Gemini тоже строят основной японский маршрут через Qiita/Zenn и не подтверждают эти два домена.

Вердикт: **AgentSkills.tokyo** и **claude-skills.jp** являются неподтверждёнными площадками `1/4`; не включать их в первую волну без ручной проверки. Уверенность: high в наличии противоречия, low в реальном статусе площадок.

### 2.2 Какая главная китайская дверь

- Grok считает **ModelScope Skills** самой сильной новой дверью с документированной загрузкой.
- ChatGPT делает ставку на `agentskills.market`, CCJK и Claude Skills Hub.
- Claude ставит выше GitHub awesome-lists, V2EX и статьи.
- Gemini предлагает Gitee Featured, Trae Market, `phodal/awesome-cursor-rules` и WaytoAGI.

Ни одна из этих «главных» marketplace-дверей не подтверждена вторым отчётом в той же роли. Поэтому **ModelScope Skills**, **agentskills.market**, **CCJK Marketplace**, **Gitee Featured**, **Trae Market как открытая внешняя подача**, **WaytoAGI submission** и **phodal/awesome-cursor-rules как цель для SKILL.md** являются неподтверждёнными рекомендациями `1/4`. Первая китайская волна должна опираться на пересечение: README, GitHub, Juejin, CSDN, Zhihu, Gitee/GitCode как зеркала и проверенные несколькими отчётами awesome-lists. Уверенность: high.

### 2.3 `laolaoshiren/claude-code-skills-zh`: каталог или соседний продукт

- Claude называет его активным списком, принимающим PR в `skills/`, и приводит требования из `MAINTENANCE.md`.
- Grok пишет, что это собственный bundle из 100+ китайских skills, а не submit-target.
- Остальные два отчёта его не подтверждают.

Вердикт: площадка и активность подтверждены только частично; механика внешней подачи противоречива. Перед PR надо вручную проверить `CONTRIBUTING`, недавние принятые внешние PR и фактическую структуру. Уверенность: low.

### 2.4 Требования Gitee и GitCode к иностранцам

- Gemini утверждает обязательные китайский телефон и паспорт/ID для Gitee, а также международные номера для GitCode.
- Grok считает поддержку иностранных номеров Gitee недокументированной и называет GitCode более простой дверью.
- Claude и ChatGPT прямо говорят, что актуальные требования к иностранному телефону и real-name verification не удалось подтвердить.

Вердикт: точные требования аккаунтов **не установлены**. Нельзя планировать паспорт, китайский номер или беспроблемную регистрацию как факт. Сначала пробный вход без публикации; если доступ есть, создать зеркало и проверить реальный sync. Уверенность: high в неопределённости, low в любой конкретной схеме регистрации.

### 2.5 Что переводить

- Все 4 отчёта согласны не переводить тела всех 101 `SKILL.md`.
- ChatGPT предлагает локальные индексы всех 101 skills и полные README для четырёх языков.
- Grok предлагает в Китае описать только 10–15 выбранных skills, в Японии 5–8, а корейский README считать необязательным до появления спроса.
- Gemini требует полный inventory в локальных README; Claude занимает промежуточную позицию: README и карточки, без перевода инструкций skills.

Вердикт: общий минимум ясен, глубина локализации нет. Безопасный компромисс: четыре README с кратким индексом категорий и 8–15 флагманскими skills; полный машинно-поддерживаемый индекс 101 добавить только если он генерируется из одного источника и не создаёт ручной drift. Уверенность: med-high.

### 2.6 Какой формат статьи лучше

- Grok и Claude считают долговечным формат top-N/listicle, обычно с отбором 8–20 позиций.
- ChatGPT сильнее настаивает на одном skill или одном workflow для Qiita и на benchmark для Zenn.
- Gemini предлагает заголовки и каталоги на все 101 skills, что противоречит предупреждениям остальных о рекламном дампе.

Вердикт: не публиковать «101 ссылка». Для Qiita и Zenn безопаснее один workflow или 5–12 skills с результатами; для Juejin/CSDN допустима более широкая подборка, но только с собственной методикой тестирования. Уверенность: high.

### 2.7 Региональные каналы Anthropic

- Grok утверждает существование японского канала в Anthropic Discord с 26.07.2025.
- ChatGPT подтверждает глобальный Discord и региональные community/ambassador routes.
- Claude пишет, что официального регионального Anthropic-хаба не найдено.
- Gemini перечисляет японские user-run сообщества и китайские независимые группы, но не даёт проверяемой общей двери подачи skills.

Вердикт: глобальный Discord/community route можно считать возможным каналом общения, но отдельный официальный JP/KR/CN skill-submission hub не подтверждён. Не использовать его как registry. Уверенность: med.

### 2.8 Испанский, португальский и русский контуры

- ChatGPT и Grok не находят отдельного ES/LatAm marketplace; Claude и Gemini тоже ведут Испанию через статьи/сообщества.
- Claude один называет `kursku/skills` рабочим PT-BR каталогом; Gemini один предлагает TabNews; Grok и ChatGPT не подтверждают отдельную португальскую дверь.
- По России Grok предлагает `claude-code-handbook-ru`, Claude предлагает `claudeskills.ru`, а Habr подтверждают три отчёта.

Вердикт: Испания через DEV Español; Россия через Habr. `kursku/skills`, TabNews, `claudeskills.ru` и `claude-code-handbook-ru` являются неподтверждёнными площадками `1/4` и требуют проверки перед затратами. Уверенность: med-high.

## 3. Что делать потребителю: раскладка наших skills

Ниже только действия, вытекающие из пересечения отчётов. Любая публикация, PR, загрузка или сообщение наружу является отдельным внешним действием и здесь не выполнялась.

### Шаг 0. Подготовить один канонический комплект

1. Оставить GitHub единственным источником истины для всех 101 skills.
2. На главной показать: число **101**, лицензию, поддерживаемые агенты, команду установки, дату последнего реального теста, provenance и security note.
3. Добавить переключатель языков.
4. Создать `README.zh-CN.md`, `README.ja.md`, `README.ko.md`, `README.es.md`.
5. В каждом README дать: что решает набор, быстрый старт, категории, 8–15 флагманских skills, риски и ссылку на полный английский перечень.
6. Не переводить команды, код, YAML-ключи и тела всех 101 `SKILL.md`. Перевод `description` делать только после теста точности автосрабатывания на соответствующем языке.

Уверенность: **high**.

### Шаг 1. Китай: максимальный приоритет

1. Сделать `README.zh-CN.md` и китайское описание репозитория с неизменёнными токенами `Claude Code`, `Agent Skills`, `SKILL.md`.
2. Создать по одному pull-зеркалу всего репозитория на Gitee и GitCode только после пробной регистрации. На зеркале явно написать, что GitHub является каноном. После релиза сверять SHA.
3. Подготовить PR/Issue в `shishirui/awesome-claude-skills-zh`; до отправки проверить свежие merge и правила. Параллельно проверить `helloianneo/awesome-claude-code-skills`.
4. Опубликовать одну оригинальную китайскую статью на Juejin: установка, методика отбора, 8–15 флагманских skills, реальные результаты и ограничения.
5. Сделать отдельную адаптацию для CSDN, не слепую копию.
6. На Zhihu отвечать в существующей релевантной теме или публиковать полезную колонку, не рекламный пост.
7. После этого вручную проверить неподтверждённые registry-двери: ModelScope Skills, agentskills.market, CCJK, Claude Skills Hub, SkillHub.cn. Подавать только туда, где реально видны правила внешней загрузки и свежие сторонние карточки.

Уверенность: **high** для README, зеркал и статей; **med** для двух awesome-lists; **low** для registry-дверей последнего пункта.

### Шаг 2. Япония

1. Сделать `README.ja.md` с естественным японским quick start и 5–12 выбранными skills.
2. Опубликовать Qiita tutorial: один сильный workflow или компактная проверенная подборка, с установкой, демонстрацией и ограничениями.
3. Опубликовать на Zenn инженерный benchmark или переносимость набора между агентами; промо оставить в конце.
4. Только после ручной проверки рассматривать AgentSkills.tokyo и claude-skills.jp.

Уверенность: **high** для Qiita/Zenn; **low** для двух отдельных каталогов.

### Шаг 3. Корея

1. Сделать `README.ko.md` минимум с установкой и краткими summaries.
2. Опубликовать один воспроизводимый workflow на Velog.
3. Отправить ссылку на эту статью в GeekNews/Hada с коротким корейским summary.
4. OKKY использовать только после проверки правил и как форум, не как marketplace.

Уверенность: **high** для Velog; **med** для Hada; **low-med** для OKKY.

### Шаг 4. Испанский

1. Сделать `README.es.md` на нейтральном международном испанском.
2. Опубликовать DEV Español tutorial с 3–5 выбранными skills и открытым репозиторием.
3. Не делать одинаковый массовый cross-post по локальным сообществам.
4. AwesomeSkills.dev/es, mcpservers.org/es, MiduDev и отдельные блоги проверять вручную: каждый из них назван только одним отчётом.

Уверенность: **med-high** для DEV Español; **low** для остальных площадок.

### Шаг 5. Россия и остальные языки

1. Для России использовать Habr как подтверждённый статьёй канал.
2. Перед PR или outreach отдельно проверить `claude-code-handbook-ru` и `claudeskills.ru`: каждый подтверждён одним отчётом.
3. Для PT-BR, FR, DE, VI, ID, HI, TR и AR не строить отдельные репозитории и не заявлять наличие marketplace. Сначала должен появиться проверенный живой потребитель или каталог.
4. Любые локализации держать в одном репозитории, иначе разойдутся версии, stars, issues и инструкции.

Уверенность: **med-high** для Habr и отказа от неподтверждённых магазинов; **low** для одиночных каталогов.

## 5. Общая уверенность

- **High:** архитектура дистрибуции, четыре README, один GitHub-канон, статьи на Juejin/CSDN/Zhihu/Qiita/Zenn/Velog, отказ от перевода 101 тел skills.
- **Medium:** Hada, DEV Español, Gitee/GitCode как зеркала, китайские GitHub awesome-lists.
- **Low:** точные размеры каталогов и аудитории, SLA, требования к иностранным аккаунтам, отдельные marketplace-домены и любые площадки, встречающиеся только в одном отчёте.

Главный практический вывод: сначала строить локальные витрины и доказательные статьи на площадках, которые видят все четыре вендора. Каталоги с одиночным подтверждением не считать каналом дистрибуции, пока вручную не доказаны три факта: площадка жива, принимает внешние проекты и недавно приняла хотя бы один сторонний skill.
