# Insight (DR DR26-11-04-HUB-02-1908): Альтернативы Terminum для браузерных и мобильных мультиагентных сессий по SSH-хостам

> Какое ПО функционально аналогично Terminum (браузерная панель над tmux-сессиями Claude Code/Codex на нескольких SSH-хостах) и стоит ли заменять им Terminum.

## Ключевые выводы
- Для сценария «панель над уже живущим парком tmux-сессий» прямой замены Terminum не найдено: он один сочетает единый список сессий с нескольких SSH-хостов, браузерный терминал с вводом с телефона/iPad, attach к существующим tmux и файловую панель на удалённых хостах без стороннего relay (chatgpt, claudeai, grok, mistral).
- «Survives reboots» в Terminum означает восстановление раскладки (сессии/окна/сплиты/папки) и последних 300 строк (lastLines до 2000), но не возобновление задачи агента: после смерти tmux заново стартуют только оболочки, агентов запускают вручную через `claude --continue` / `codex resume --last`; реальную перезагрузку автор сам помечает как непроверенную. Обрыв клиента (закрытая вкладка) агента не убивает, так как процесс живёт в tmux.
- Terminum очень молод и держится на одном авторе: первый коммит 16 октября 2026, релизы почти ежедневно (v0.26–v0.30.4 к 4 ноября), AGPL-3.0 или коммерческая лицензия, по разным оценкам 3–10 звёзд и 3 контрибьютора, то есть высокий bus-factor; сильные стороны: loopback-only, tailscale serve, подписанные релизы Ed25519, строгий allowlist SSH-опций.
- Минус Terminum для данного пользователя: `terminum hooks install` ставит хуки статусов вместе с MCP-сервером планов/заметок, который запускается как stdio-процесс в каждой сессии Claude/Codex и дублирует уже имеющиеся скрипты планов и заметок; отдельной официальной команды «только статусы без MCP» не подтверждено (без хуков статусы читаются с экрана).
- Не подтверждены на практике: удобство на физическом iPhone (автор в релизах пишет «Not verified: a physical iPhone»), устойчивость terminumd в WSL на Windows (документированы только macOS 14+ и Ubuntu/Debian), совместимость хуков Codex и нагрузка от по одному ssh-соединению на каждую подключённую сессию хоста.
- Ближайшие альтернативы для «панели над существующим флотом»: Agent Deck (asheshgoplani/agent-deck: tmux-native, web UI, remote-инстансы по SSH, MIT, но по оценке claudeai фактически привязан к одному хосту), Agent of Empires (подключается к существующим tmux, PWA-дашборд) и herdr (несколько SSH-машин, документированный авто-resume Claude/Codex после рестарта, но терминальный клиент без браузера и агенты должны жить внутри herdr). Вендоры расходятся в ранжировании.
- Для «основной среды запуска новой работы» лидеры расходятся: Superset/Paradev (chatgpt, gemini; но claudeai называет его десктоп-only, grok и mistral отмечают macOS-first, переименование в Paradev и платное мобильное приложение), Paseo (claudeai, mistral: Apache-2.0, мультихостовый демон, нативные мобильные клиенты), HAPI (grok, chatgpt: сохраняет официальные CLI и подписки, PWA, несколько runner-машин). HAPI, Happy и Agent of Empires требуют запуска агентов через свою обёртку/Runner, то есть меняют способ запуска; Happy по умолчанию использует сторонний relay.
- Отсеяно из shortlist: Vibe Kanban (Bloop закрылась 10 апреля 2026, последний релиз v0.1.44 от 24 апреля, sunset), code-server/ttyd/WeTTY (общая IDE или голый терминал без списка агентов и статусов ожидания), cmux и Wave Terminal (десктоп, нет браузерного клиента); есть коллизии имён (tyejcoleman/agent-deck, TeamADAPT/cmux — не те проекты).
- Официальные механизмы вендоров (Claude Code Remote Control в подписках Pro/Max/Ultra, Codex Remote Connections) закрывают часть потребности (апрувы, push, продолжение сессии) без новой инфраструктуры, но не дают единой панели по всем агентам; ни один инструмент не возобновляет задачу после ребута в строгом смысле.

## Рекомендации / решения
- Не мигрировать существующий флот только ради замены Terminum: сохранить его как baseline для панели над живущими tmux-сессиями.
- Отдельно испытать Agent Deck как кандидата в «fleet control plane» над существующим парком и держать herdr как запасной вариант с авто-resume.
- Для новых сессий пилотировать HAPI или Paseo (Superset/Paradev только при готовности платить и принять macOS-first), не смешивая задачу управления текущим парком с задачей новой среды запуска.
- Проверить, можно ли оставить хуки статусов Terminum без stdio-MCP; если нет, жить с чтением статусов с экрана или не включать MCP-часть планов/заметок.
- Провести ограниченный параллельный пилот до решения (план приведён в отчёте): iPhone/iPad по tailscale serve, WSL-установка, реальная перезагрузка удалённого хоста, совместимость хуков Codex.
- Для восстановления после ребута использовать собственные средства агентов (`claude --resume`, `codex resume`), а не рассчитывать на Terminum.
- Во второй волне поиска проверить непроверенные имена (Codeman, T3 Code, vibepanel, run-kit, MulmoTerminal, Orca) по первичным источникам.

## Открытые вопросы
- Реальное поведение Terminum при перезагрузке удалённого хоста (автор помечает как непроверенное).
- Удобство Terminum на физическом iPhone/iPad и стабильность terminumd в WSL длительное время.
- Можно ли установить хуки статусов Terminum без MCP-сервера планов и заметок.
- Совместимость хуков Terminum с уже имеющимися хуками пользователя и корректная загрузка hooks.json Codex.
- Нагрузка от множества ssh-соединений (по одному на каждую подключённую сессию хоста).
- Актуальные факты об альтернативах: Agent Deck реально ли привязан к одному хосту, Superset/Paradev десктоп-only или есть браузерный доступ, цена коммерческой лицензии Terminum.
- Непроверенные кандидаты второй волны (Codeman, T3 Code, Orca, vibepanel, run-kit, MulmoTerminal) и отсутствие реальной эксплуатации любых альтернатив.
