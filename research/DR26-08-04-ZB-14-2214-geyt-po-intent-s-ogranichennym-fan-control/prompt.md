# ЗАДАЧА

Мы строим персональный «второй мозг» на простом стеке: plain-markdown заметки (Obsidian-подобный волт с wiki-ссылками ...), SQLite для фактов и состояния, векторный RAG (e5-эмбеддинги + реранкер), поверх — агенты-LLM. Гибридный ретривер работает так: вектор достаёт топ-K, затем идёт РАСШИРЕНИЕ НА 1 ПРЫЖОК по графу wiki-ссылок (соседи найденных заметок подмешиваются в кандидатов), потом реранк.

## Наш собственный замер (это факт, а не гипотеза)
Мы гоняли A/B: A = только вектор, B = вектор + 1-hop граф-расширение. Судил человек по полезности выдачи.
- Запросы про КОНКРЕТНУЮ СУЩНОСТЬ (человек, компания, конкретный артефакт): граф помог 1 раз, навредил 5 раз.
- Запросы ТЕМАТИЧЕСКИЕ («что я думаю про X», «как мы решаем класс задач Y»): граф помог 5 раз, навредил 1 раз.
Наш вывод и текущее решение: граф-расширение включается ГЕЙТОМ ПО ТИПУ ЗАПРОСА (сущность → граф выключен; тема → включён).

## Внешнее возражение, которое надо рассудить
Другой ресёрч предложил вместо гейта взять из когнитивной архитектуры ACT-R механизм bounded spreading activation: активация растекается по связям, но (а) каждое ребро штрафуется «фан-эффектом» — чем больше у узла связей, тем меньше активации достаётся каждому соседу; (б) активация узла затухает со временем и подкрепляется обращениями (base-level learning). Его главное допущение: наш плохой результат на сущностях вызван «паразитными хабами» — заметками-концентраторами с сотнями ссылок, которые превращают расширение в шум. Если так, fan-penalty + decay чинят проблему, и гейт по типу запроса становится не нужен (или нужен только как страховка).
