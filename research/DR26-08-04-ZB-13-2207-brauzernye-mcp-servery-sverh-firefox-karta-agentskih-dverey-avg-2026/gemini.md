### **Анализ браузерных MCP-протоколов (Август 2026)**

Это исследование ставит целью определить, какие браузерные движки, помимо уже используемого Firefox, предоставляют надёжный агентский протокол (MCP) с ключевой возможностью подключения к **уже запущенному экземпляру браузера** (`--connectExisting`).

#### **Ключевые выводы**

1.  **Два доминирующих стандарта:** На 2026 год существуют два зрелых протокола для автоматизации:
    *   **Chrome DevTools Protocol (CDP):** Де-факто стандарт для всех браузеров на движке Chromium (Chrome, Edge, Brave, Vivaldi, Opera). Он стабилен, хорошо документирован и позволяет подключаться к запущенному браузеру. [established]
    *   **WebDriver BiDi:** Новый стандарт W3C, который приходит на смену классическому WebDriver. Firefox является его флагманской реализацией. Протокол мощный, но его поддержка в других браузерах всё ещё отстаёт от Firefox. Пакет `@mozilla/firefox-devtools-mcp` — это высокоуровневая агентская обёртка над WebDriver BiDi. [established]

2.  **WebKit/Safari — аутсайдер:** У Safari есть WebKit Remote Debugging Protocol, но его основное применение — отладка через `safaridriver`, который почти всегда запускает новый, чистый экземпляр. Возможности надёжно подключиться к существующей пользовательской сессии без сложных манипуляций и ручного включения отладки нет. Это не соответствует критерию «АК-47». [established]

3.  **Puppeteer и Playwright — это клиенты:** Важно различать протокол (сервер в браузере) и клиентскую библиотеку. Playwright (Microsoft) и Puppeteer (Google) — это клиентские библиотеки, которые «говорят» на CDP или WebDriver BiDi для управления браузером. Они оба поддерживают подключение к уже запущенному браузеру, если он был запущен с открытым портом отладки. [established]

### **DELIVERABLE 2: Топ-1 дополнение к стеку и план замера**

Единственное осмысленное дополнение — это браузер на движке Chromium.

**Дополнение:** **Google Chrome** в связке с **Playwright** (как клиентом).

**План замера на 48 часов ("понарошку сначала"):**

1.  **Подготовка (1 час):**
    *   Установить Google Chrome на Windows-хаб.
    *   Создать отдельную директорию для профиля Chrome (например, `C:\automation\chrome-profile`).
    *   Установить Playwright в Python: `pip install playwright`.
    *   Установить браузерные бинарники для Playwright: `playwright install chrome`.

2.  **Запуск и подключение (1 час):**
    *   Запустить Chrome вручную из командной строки с двумя ключевыми флагами, указав на созданный профиль и открыв порт:
        ```bash
        "C:\Program Files\Google\Chrome\Application\chrome.exe" --remote-debugging-port=9222 --user-data-dir="C:\automation\chrome-profile"
        ```
    *   Написать Python-скрипт `test_chrome_attach.py`, который использует Playwright для подключения к уже запущенному Chrome.
        ```python
        from playwright.sync_api import sync_playwright
        
        # CDP эндпоинт запущенного Chrome
        cdp_url = "http://localhost:9222"
        
        with sync_playwright() as p:
            # Подключаемся к запущенному браузеру
            browser = p.chromium.connect_over_cdp(cdp_url)
            context = browser.contexts[0] # Получаем дефолтный контекст
            page = context.pages[0]       # Получаем первую открытую вкладку
            
            print(f"Успешно подключились к Chrome!")
            print(f"Заголовок страницы: {page.title()}")
            
            # Важно: не закрываем браузер, только отключаемся
            browser.close() # В этом режиме close() == disconnect()
        ```

3.  **Тест на живучесть (46 часов):**
    *   Оставить Chrome запущенным на хабе.
    *   Настроить запуск скрипта `test_chrome_attach.py` по расписанию (например, каждые 30 минут).
    *   Скрипт должен логировать успешность подключения и заголовок страницы.
    *   **Критерий успеха:** 100% успешных подключений в течение 48 часов. Браузер не падает, сессия (если залогиниться на каком-то сайте вручную в этом профиле) сохраняется. Скрипт отрабатывает и отключается, не убивая браузер.
