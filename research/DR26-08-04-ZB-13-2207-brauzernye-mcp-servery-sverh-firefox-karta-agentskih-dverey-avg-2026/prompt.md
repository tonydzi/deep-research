# Браузеры с родным MCP: полная карта агентских дверей (сверх Firefox + Mozilla MCP)

CONTEXT (наш стек на 04.08.2026 — НЕ переисследовать, это фундамент, всё проверено руками сегодня):

**Слой кук РЕШЁН.** Chrome 127+ шифрует куки App-Bound Encryption, Chrome 146 (апрель 2026) добавил DBSC (device-bound через TPM, включён по умолчанию, off-switch в Admin нет) → извлечение Chrome-кук снаружи мертво. Firefox хранит `cookies.sqlite` открыто и DBSC не реализует → базовый робот-браузер = Firefox, профиль-на-сервис. Консенсус 3/3 внешних DR, 16.07.2026.

**Слой удержания сессии (control plane) ЗАКРЫТ СЕГОДНЯ, 04.08, замерено на нашем железе.** Проба на Windows-ноуте, Firefox 153: резидентный Firefox с `--marionette` + `--remote-debugging-port` на отдельном профиле; `npx @mozilla/[email hidden] --connectExisting --marionettePort <N>` цепляется, отдаёт 31 тул (`list_pages`, `navigate_page`, `take_snapshot`, `click_by_uid`, `fill_form_by_uid`, `evaluate_script`, `screencast_start`, `install_extension`, `restart_firefox` и др.). Браузер ПЕРЕЖИЛ отключение MCP-клиента, повторный attach прошёл. Порт Marionette задаётся pref `marionette.port`, а НЕ переменной окружения. Пакет `@mozilla/firefox-devtools-mcp` — официальный Mozilla (npm maintainer `mozilla-npm`, repo `github.com/mozilla/firefox-devtools-mcp`), флаг именно `--connectExisting` (camelCase). CDP из Firefox снят (~141+), вместо него WebDriver BiDi ⇒ Playwright `connectOverCDP` к Лисе не применим.

**Уже отвергнуто, НЕ пересматривать без нового факта:** Perplexity Comet (свой агент к бэкенду, наши логины не переиспользует, конфликт с Amazon) · ChatGPT Atlas (sunsetting 09.08.2026) · Dia (нет публичного agent-API) · Brave Leo (UI-фича человека) · облачные Browserbase/Steel (чужой IP убивает смысл нашего резидентного IP на IP-sensitive площадках).

ЧТО ИССЛЕДОВАТЬ. Вопрос узкий и практический: **какие ещё браузеры и браузерные движки имеют РОДНОЙ MCP-сервер (или официальный agent-протокол), пригодный нам сверх связки Firefox + `@mozilla/firefox-devtools-mcp`.** Не обзор браузеров вообще.

1. **Полная перепись браузерных MCP на август 2026.** По каждому строго: кто издатель (вендор браузера / платформа / community — с ссылкой на npm-maintainer или репозиторий), версия и дата последнего релиза, статус зрелости. Обязательно покрыть: `chrome-devtools-mcp` (Google), `@mozilla/firefox-devtools-mcp`, Playwright-MCP (Microsoft), Puppeteer-MCP, WebKit/Safari (есть ли вообще что-то официальное от Apple), Edge (свой ли, или наследует Chromium), Brave, Opera Neon MCP Connector, Arc/Dia, Vivaldi, Zen Browser, Waterfox, LibreWolf, Ladybird, Servo. Явно назвать тех, у кого MCP НЕТ — отсутствие двери такой же ответ, как её наличие.

2. **Главный критерий: умеет ли attach к УЖЕ ЗАПУЩЕННОМУ браузеру.** Для каждого MCP: есть ли аналог `--connectExisting` / `--browserUrl`; переживает ли браузер отключение MCP-клиента; можно ли перецепиться повторно; работает ли с существующим залогиненным профилем на диске (флаг вида `--profilePath`), или он всегда поднимает свой чистый экземпляр. Это ровно то, что мы сегодня доказали на Лисе, и по чему хотим сравнить остальных.

3. **Безлюдная работа по расписанию.** Кто из них живёт headless на Windows и на headless Linux без иксов; кто требует живого десктопа; поведение при обрыве и холодном рестарте; наблюдаемость (accessibility-snapshot vs скриншоты vs сырой DOM) и её цена в токенах.

4. **Риск-профиль.** Prompt-injection через содержимое страницы (класс CometJacking): какие из этих MCP выполняют инструкции со страницы и какие защиты есть; какие тулы опасны по построению (`evaluate_script`, `install_extension`, `unrestrictedSavePaths`) и какой минимальный набор тулов достаточен; предупреждения самих вендоров (Mozilla прямо пишет не оставлять Marionette включённым при обычном сёрфинге). Позиция площадок и ToS против агентного доступа к залогиненным аккаунтам.

5. **Что это даёт сверх Лисы.** Честно: есть ли вообще сценарий, где второй браузерный MCP нужен, если Firefox-attach уже работает — например строго-Chromium сайты, Safari-only, мобильные (Firefox for Android через ADB в MCP уже есть), WebExtension-разработка. Или второй MCP — лишняя сущность.
