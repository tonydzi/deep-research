# Insight (DR DR26-06-28-HUB-02): Архитектура мульти-агентной системы с Vault как единым хранилищем знаний, доступов и памяти

> Как спроектировать безопасный централизованный Vault и протоколы координации нескольких LLM-агентов (Codex, Claude, Gemini, Grok), чтобы они совместно читали/писали знания, приходили к консенсусу и проходили guardrails-проверки.

## Ключевые выводы
- Vault должен выдавать агентам только временные токены доступа (JWT), а не реальные ключи — Zero-Trust модель по образцу HashiCorp Vault
- Хранилище нужно версионировать (Git), использовать YAML front-matter со схемой полей и автоматическую валидацию (линтеры, pre-commit хуки)
- Доступ разграничивается по ролям на каждого агента; все изменения фиксируются в audit log, рискованные обновления требуют одобрения человека
- Семантический поиск (векторные БД: Pinecone/Weaviate/Qdrant) + RAG обеспечивают ~90% релевантности ссылок и служат долговременной памятью между сессиями
- Роли агентов специализируются: Reporter (черновик) → Analyst/Editor (проверка, ссылки) → Reviewer/Moderator (финальная вычитка); консенсус достигается голосованием или единогласием, спорное помечается тегом #review_needed для человека
- Guardrails реализуются через LangChain Guardrails (детекторы PII, инъекций, токсичности) и небольшие LLM-контроллеры (GuardAgent) для семантической проверки соответствия правилам
- Оценка системы идёт по метрикам: точность, полнота цитирования, консистентность, процент конвергенции раундов, скорость (токены/время), плюс наблюдаемость через OpenTelemetry/Prometheus/Galileo (Tool Selection Accuracy, Agent Adherence)
- Масштабирование числа агентов эффективно примерно до 3-5, дальше требуется оптимизация коммуникации (комбинированные архитектуры: часть агентов группами, часть цепочкой)
- Оркестрация задаётся статическим пайплайном либо графом (LangGraph/Bedrock) с супервайзером, динамически делегирующим роли

## Рекомендации / решения
- Провести аудит текущего Vault: формат, папки, метаданные, наличие валидации/CI, права доступа
- Выбрать платформу оркестрации (LangChain/AutoGen/Bedrock) и связать через неё Codex/Claude/Gemini/Grok с Vault, выдав каждому агенту уникальные токены
- Написать и протестировать отдельно промпты для ролей Reporter/Analyst/Reviewer
- Реализовать прототип коллаборации (Reporter→Analyst→Reviewer) с логированием всего процесса в JSON
- Определить алгоритм консенсуса с лимитом раундов (например, 3), после чего спорное помечается для человека
- Внедрить guardrails-мидлвар (PII/токсичность/фактчекинг) перед коммитом в Vault
- Настроить мониторинг/трейсинг (Grafana/Prometheus или Galileo) с алертами на затянувшиеся споры или частые срабатывания guardrails
- Итеративно дообучать агентов на истории правок Vault (RLHF, редтимминг) и расширять число агентов только после отладки базового сценария
- Документировать весь процесс как «конституцию» коллаборации для команды
