# Insight (DR DR26-06-26-HUB-08): Инвентаризация и стресс-тестирование б/у GPU (RTX 3090, 5060Ti) перед покупкой

> Отчёт описывает полный набор бесплатных утилит и командную последовательность для проверки характеристик, VRAM, стабильности и охлаждения видеокарт (в т.ч. multi-GPU с NVLink) перед принятием решения о покупке.

## Ключевые выводы
- nvidia-smi -q -x даёт полный XML-инвентарь карты (модель, BIOS, память, PCIe), а nvidia-smi -L — UUID и PCI-Bus ID для привязки результатов тестов к конкретной карте
- Ключевой тест на брак VRAM — memtest_vulkan (GitHub GpuZelenograd/memtest_vulkan): даже одна ошибка/bitflip — основание для возврата карты, особенно критично для GDDR6X на 3090
- Compute-стресс — gpu-burn (GitHub wilicc/gpu-burn) грузит GPU на 100% FP32; CUDA samples (deviceQuery, bandwidthTest, p2pBandwidthLatencyTest) проверяют число CUDA-ядер (10496 у 3090, 4608 у 5060Ti), пропускную способность (~800-900 GB/s у 3090, ~440-450 GB/s у 5060Ti)
- Для двух 3090 с NVLink ожидается >~60 GB/s по мосту против ~12-15 GB/s по чистому PCIe x16 — низкая скорость без NVLink сигнализирует о проблеме моста/PCIe-линий
- GUI-инструменты для Windows: GPU-Z (модель, BIOS, Bus Interface x16 4.0), HWiNFO64 (сенсоры, логирование температур/мощности), OCCT (стресс-тест + мониторинг), FurMark (артефакты/BSOD при экстремальной нагрузке), Unigine Superposition (реалистичный рендер-бенчмарк)
- Пороговые значения нормы: GPU до 75-80°C, Hotspot ≤90-95°C, Memory Junction до 100°C; урезанный Power Limit в GPU-Z/OCCT указывает на «майнинговый» BIOS с заниженным питанием
- Признаки брака/отказа: любая ошибка memtest_vulkan, драйверные сбои/BSOD под нагрузкой, цветные артефакты в FurMark/Unigine, несоответствие заявленных характеристик (объём памяти, разрядность шины <384-bit), PCIe линк ниже x16 (x8/x4)
- Код-агент не может проверить: физические признаки (запах гари, коррозия, люфт вентиляторов), реальную историю майнинга (нет «одометра»), полноценную нагрузку 24/7 — это остаётся на визуальную/интуитивную оценку человека

## Рекомендации / решения
- Собрать файл tools.md со списком всех утилит, URL скачивания и SHA256/MD5 контрольными суммами перед стартом проверки
- Пройти план: инвентаризация (nvidia-smi -q, lspci) → VRAM-тест memtest_vulkan 10-20 мин на каждую карту → compute-тест gpu_burn + deviceQuery/bandwidthTest 5-10 мин → multi-GPU p2pBandwidthLatencyTest при 2 картах → стресс-тесты OCCT/FurMark/Unigine по 10-15 мин каждый → непрерывный лог nvidia-smi --loop-ms во время всех тестов
- Скачивать утилиты только с официальных источников (TechPowerUp, hwinfo.com, ocbase.com, geeks3d.com, GitHub Releases, developer.nvidia.com) и сверять контрольные суммы
- По итогам составить отчёт PASS/FAIL по каждому пункту с приложенными контрольными суммами файлов; при VRAM-ошибках или критичном перегреве — вердикт «не покупать» или требовать снижения цены
- Дополнительно проверить все видеовыходы (HDMI/DisplayPort) на стабильность картинки и визуально осмотреть карту на физические повреждения/следы майнинга

## Открытые вопросы
- Как достоверно определить, что карта майнилась, при отсутствии прямых индикаторов кроме косвенных (высокая Memory Junction temp, перепрошивка, шум вентиляторов)
- Достаточно ли короткого (10-20 мин) теста стабильности вместо полноценной длительной нагрузки 24/7 для гарантии надёжности карты
- Насколько актуальны указанные версии утилит (HWiNFO 8.48/8.49, OCCT v16.1.11, FurMark адрес узла) на момент реальной покупки — требуется свежая проверка на сайтах
