# Insight (DR DR26-06-26-HUB-07): Сравнение мессенджер-каналов и моделей идентичности для мульти-агентных Claude-команд

> Какой мессенджер-канал и какая модель идентичности агентов (Telegram/Discord/Matrix, отдельные боты vs один userbot) лучше подходит для 4-10 агентов с human-in-the-loop.

## Ключевые выводы
- Telegram с отдельным ботом на агента даёт чёткую адресацию и видимость всей переписки людям, но имеет суточные/скоростные лимиты и риск бесконечных зацикленных рассылок между ботами
- Telegram с одним userbot-аккаунтом для всех агентов упрощает аутентификацию (один токен) и даёт полный доступ к истории через Telethon/MTProto, но требует своей маршрутизации сообщений и подвержен гонкам/дублированию ответов без явных правил
- Discord с отдельными ботами — зрелая платформа с нативными нитями и правами доступа, но жёсткий антиспам может деактивировать бота, а по умолчанию боты не видят историю чата друг друга без доп. настройки
- Discord без доработок склонен к каскадным упоминаниям (бот A → B → C → A), решается требованием 'отвечать только на упоминание' (require_mention=true)
- Matrix (самохост Synapse) снимает все внешние rate-limit и антиспам-ограничения, даёт полный контроль и чёткую адресацию, но требует разворачивать и поддерживать собственный сервер и менее удобен для обычных людей
- Matrix сам по себе не соединяется с другими мессенджерами — нужны мосты для мультиплатформенного роутинга
- Рекомендация для 4-10 агентов с human-in-the-loop: Matrix для надёжности/масштаба; Telegram-боты для быстрого MVP без развёртывания; Discord — если у аудитории уже есть присутствие в Discord
- Отдельная логическая шина (MCP/внутренний брокер, напр. NATS/MQTT) рекомендована для тяжёлого межагентного взаимодействия, а мессенджеры оставить только для human-readable контроля/статусов

## Рекомендации / решения
- Для продакшена использовать отдельные аккаунты (боты или Matrix-пользователи) на каждого агента, а не один общий userbot
- Настроить require_mention=true / DISCORD_ALLOW_BOTS=mentions для Discord, чтобы избежать каскадных срабатываний
- Реализовать чтение последних 10-50 сообщений при старте агента + дедупликацию по msg_id
- Использовать явные метки адресации (@AgentX или протокол [src→dst]), чтобы агент реагировал только на свои сообщения
- Мониторить лимиты и ошибки (коды 429/401) с явными оповещениями, а не тихим молчанием
- Обеспечить людям возможность вмешаться (права писать/упоминать агентов) и задокументировать команды управления (/stop, /retry)
- Подготовить запасной канал (напр. приватная комната Matrix) для критических логов на случай падения основного мессенджера
- Начинать MVP с одного userbot-аккаунта и простых префиксов, затем мигрировать на отдельные аккаунты в проде

- Не оценена стоимость/сложность развёртывания и поддержки собственного Matrix/Synapse сервера
