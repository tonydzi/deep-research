## ✅ СОШЛИСЬ ВСЕ ТРОЕ (3/3) — считаем установленным
1. **Вердикт одинаковый до буквы: `adopt-with-fences`.** Ни один не сказал ни «adopt», ни «avoid».
2. **Забор №1 идентичен у всех: подписочный OAuth Anthropic через шлюз не пускать НИКОГДА.** Anthropic прямо пишет, что не разрешает третьим сторонам маршрутизировать креды Free/Pro/Max; энфорсмент активен (сообщения о внезапных 401 и требовании ключа `sk-ant-`).
3. **Ключи коммерческого API — легальный путь.** Через `sk-ant-` или чужие платные ключи риска бана для аккаунта нет: это другой юридический режим (Commercial Terms). ChatGPT добавляет, что Anthropic сам документирует LLM-gateway-паттерн на API-ключах.
4. **Независимых долгих продакшн-отзывов (>1 мес) практически НЕТ.** Рост звёзд + промо мейнтейнера + рерайты README; измеренного опыта почти нет. ChatGPT нашёл кластер почти одинаковых промо-постов по мелким сабреддитам ~10.04.2026.
5. **Компрессия — маркетинговый потолок, не средний результат.** Все трое: 15–95% нельзя закладывать в расчёт.
6. **Bus factor = 1.** «500+ contributors» — эффект бота all-contributors (кредит за доки, переводы, идеи), а не команда инженеров.

## ⚖️ РАЗОШЛИСЬ — и я развёл фактом сам
**Спор о CVE-2026-49352:**
- ChatGPT: «не нашёл авторитетной записи, привязывающей CVE к OmniRoute; возможно ошибочный ID или выдумка» → **ложный негатив**.
- Grok: «это апстрим 9Router, не OmniRoute».
- Gemini: «9router CVSS 9.8, и OmniRoute его бандлит и спавнит ⇒ установка вносит дремлющий вектор эскалации».

✅ **Проверено детерминированно 04.08:**
- Advisory РЕАЛЕН: `GHSA-jphh-m39h-6gwx` = `CVE-2026-49352`, critical, пакет **9router**, диапазон `>=0.2.21, <=0.4.41`, опубликован 02.07.2026. ⇒ ChatGPT ошибся, Grok и Gemini правы по атрибуции.
- Но: в нашей установке 3.8.49 **9router НЕ является зависимостью и не ставится сам** — есть лишь инсталлер `src/lib/services/installers/ninerouter.ts`, который делает `npm install 9router@latest` по требованию.
- И: `npm view 9router version` = **0.5.45**, то есть ВЫШЕ уязвимого диапазона.
⇒ **Вывод Gemini «установка вносит уязвимость» на сегодня неверен.** Риск реализуется, только если оператор сам включит 9router И запиннит старую версию.

**Спор о стелсе:** Grok описывает «extensive Claude Code fingerprint/stealth»; Gemini честно помечает «TLS-masking specifics — not verified». Мой замер: `ENABLE_TLS_FINGERPRINT=true` в `.env.example` **закомментирован**, MITM требует sudo через `sudoGate.ts`. ⇒ стелс существует, но **opt-in**, не поведение по умолчанию.

## 🆕 ЧТО ДАЛА ТОЛЬКО ОДНА РЕЛЬСА (уникальное, проверил статусы issue сам)
**Gemini (самая ценная добавка — конкретные номера):**
- `#7699` «silent SSE close on mid-stream upstream failure» — ✅ **проверил: ОТКРЫТ на 04.08**, 3 комментария. Клиенты Anthropic-формата требуют терминальный `message_stop`; шлюз закрывает поток молча ⇒ Claude Code не отличает сетевой сбой от обрыва модели и не делает чистый ретрай. **Это главный технический довод против даже «безопасного» использования в агентных сессиях.**
- `#4268` компрессия пишет строку в аналитику **только при положительной экономии**, нулевые попытки молча не логируются ⇒ дашборд экономии структурно завышает. ✅ закрыт 29.06.
- `#2292` opencode-zen отдаёт Claude-формат на OpenAI-эндпоинте, HTTP 200 ⇒ шлюз пропускает без перевода, клиент падает на валидации. ✅ закрыт 16.05.
- Socket.dev-находки конкретно: скрейп **Zed OS keychain** с автосохранением в SQLite без подтверждения + установка MITM root-CA через base64-PowerShell. Лечение мейнтейнера: 2-шаговое подтверждение + `.ps1` вместо encoded-команд + **`OMNIROUTE_BUILD_PROFILE=minimal`**, который вырезает keychain-reader, MITM-cert-installer, cloudSync и ninerouter.
- Free-tier провайдеры «мягко» лимитируют **тихим обрезанием ответа вместо 429** ⇒ отравляет контекст агента; «free-tier models are cron poison, not primary material».

**ChatGPT:** матрица альтернатив с рангом риска (ниже) + различение «локальный ≠ автоматически безопаснее»: локальность снижает утечку промптов оператору роутера, но импорт OAuth меняет комплаенс-риск, а установка root-CA расширяет поверхность компрометации.

**Grok:** документированы баны Google/Antigravity за фичи этого класса; публичных банов Anthropic именно за OmniRoute не найдено (speculative).

## 🎯 РЕШЕНИЕ (не меняется, но теперь на базе 3/3 + фактов)
**OmniRoute не входит в путь Claude.** `ANTHROPIC_BASE_URL` не трогаем, Claude Code говорит с Anthropic нативно.
Если понадобится перелив — **LiteLLM на API-ключах** (зрелее, меньше поверхность), OmniRoute держим как песочницу для грунта.
Заборы, если всё же гоняем OmniRoute: только API-ключи · `OMNIROUTE_BUILD_PROFILE=minimal` · `ENABLE_TLS_FINGERPRINT` и MITM выключены · `*-web` провайдеры не трогать · 9router не включать · Stacked-компрессию на агентных задачах не включать · не полагаться на авто-фолбэк во free-tier (тихое обрезание).
**Что перевернёт решение:** письменное разрешение Anthropic на локальные шлюзы поверх consumer OAuth (сейчас обратное) · закрытие `#7699` · независимый аудит компрессии на кодинге.
