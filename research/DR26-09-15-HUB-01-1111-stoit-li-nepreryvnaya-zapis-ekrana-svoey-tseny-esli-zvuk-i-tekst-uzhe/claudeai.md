Замеры и исследования (сильнее всего)

Архивы почти не открывают. Классическая критика lifelogging (Sellen & Whittaker, CACM 2010) ссылается на исследования: цифровые семейные архивы (фото, видео, почта) открывают редко. 2. Граница между экраном и звуком

Прямых A/B-замеров «экран + звук против только звука» не нашёл. Косвенно граница выглядит так.

Звук и текстовые рельсы покрывают:

содержание встреч;
переписку и диалоги с ИИ;

Уникально для экрана:

(а) контент, который вы только читали: веб, PDF, чужие страницы без экспорта;
(б) визуальная часть созвонов. Screenpipe в июне 2026 добавил отправку до четырёх ключевых кадров встречи в модель-выжимку, чтобы в итог попадали диаграммы, слайды и демонстрации экрана (changelog);

История браузера даёт URL, но не то, что было на странице в момент просмотра.

4. Дубли как архитектура

Зачем каждое представление:

full_text с FTS: поиск, выжимки, «что я делал».
elements с координатами: API отдаёт /frames/{id}/text — нет, это не из поиска, см. ниже.

Уточню без цитаты. В API screenpipe /frames/{id}/text отдаёт позиции текста с рамками, нормированными к монитору, чтобы подсвечивать совпадение на скриншоте (API). /elements ищет по роли узла (кнопка, поле) и иерархии (API). Для кликов записывается путь предков элемента, по которому кликнули. Всё это нужно для реконструкции действий и SOP.

accessibility_tree_json: сырьё для повторного разбора. Роли узлов позволяют отделить служебные элементы интерфейса от содержимого.
text_json: вывод OCR с позициями, для кадров без дерева.

Дублирование — нормальная практика, не только у screenpipe. Разбор базы Recall показывает, что Microsoft хранит на каждый снимок четыре эмбеддинга изображения и четыре текстовых: полный OCR, по регионам, по отдельному региону и заголовок окна.

Для UI-автоматизации пассивный поток всё равно не тот материал. Воспроизведение действий в OpenAdapt хранит на каждый шаг вырезку-шаблон, OCR-метку, смещения до соседних ориентиров и постусловия, выведенные из того, что изменилось на экране после действия. При воспроизведении первым пробуется структурное совпадение по DOM/UIA-дереву, затем шаблоны, OCR и геометрия. Нужны улики в момент клика, а не 33 млн строк всех текстовых узлов каждого кадра. 
pypi
PyPI

Главный аргумент: сам вендор считает эти слои временными. Режим lean после срока хранения удаляет элементы, accessibility JSON и события интерфейса, но оставляет поисковый текст и воспоминания. В changelog сказано прямо: иначе файл базы не уменьшается, чистится только медиа. Режим появился в июне 2026. Версия 0.4.25 датирована концом июня, так что в 0.4.50 он, скорее всего, есть. Проверьте в Settings → Storage. 
screenpipe docs

Основатель screenpipe на HN (49026824) описывает то же: чистить mp4 и многословные деревья, пока агенты строят высокоуровневые воспоминания со ссылками на сырьё. Ещё там же (49035249): скриншоты можно выключить совсем, оставив accessibility-данные, и большая часть значимого сохранится.

6. Отказ от экрана

На уровне компании — самый сильный случай, который я нашёл. Rewind в 2024 году переименовался в Limitless и ушёл в носимый микрофон. Ранний пользователь предположил, что команда поняла: большинство платящих не ставили в приоритет контекст рабочего стола. В декабре 2025 после покупки Meta приложение Rewind отключило весь захват экрана и звука с 19 декабря. 
Substack
9to5Mac

Что потеряли пользователи, по отзывам: поиск по всему, что проходило через экран. Сегодня его ищут в screenpipe. Документированного описания конкретных провалов «без экрана не нашёл X» не нашёл.

На уровне людей и команд, отключивших экран и оставивших звук с разбором потерь, — не нашёл. Есть обратный пример: практик со screenpipe отключил звук и оставил экран.

Это пробел в публичных данных, и вы можете его закрыть сами. Две недели работайте с фильтрами из п. 3 и ведите журнал промахов: каждый раз, когда хотелось данных экрана, которых нет. Это будет ценнее всего, что есть в открытом доступе.

7. Приватность и риск

Автоматические фильтры конфиденциального не держат.

Tom's Hardware, Recall: фильтр сработал только на двух магазинах. Номер карты и пароль в Блокноте Recall захватил. 
Tom's Hardware
Kevin Beaumont, Recall: зафиксирована карта, введённая в интерфейсе самого Microsoft, включая CVV. Сохранились и исчезающие сообщения Signal. 
Medium
Screenpipe о своём фильтре: модель PII даёт — больше 99% на частых категориях по собственным тестам. Вендор сам предупреждает, что не стоит полагаться на неё как на единственную защиту (privacy filter).

Главное для вашей базы: дерево элементов не чистится. По разбору практика, асинхронный редактор screenpipe чистит текст OCR, accessibility и UI-событий, но не таблицу elements. Секрет может лежать там открытым текстом до удаления по сроку. У вас это те самые 20 ГБ. Короткий срок для этого слоя — вопрос безопасности, а не только места.

Специфика Windows и четырёх мониторов

Windows

Защитный DRM-флаг окна. На Windows приложение может закрыть своё окно от захвата. Signal ставит DRM-флаг, и содержимое не видят ни Recall, ни другие приложения. Такие окна у вас будут чёрными кадрами. У screenpipe есть --pause-on-drm-content. 
Bleeping Computer
Ориентир из политик Recall: список исключений задаётся по имени exe или AUMID через точку с запятой. Для поддерживаемых браузеров есть отдельный список URI. Имеет смысл повторить эту схему у себя. 
Microsoft Learn
Electron-приложения. Claude.exe на Electron. В changelog screenpipe сказано, что на Windows окна Chromium/Electron сразу идут в резервный обход дерева (changelog). Раньше бюджеты обхода, дросселирование OCR для терминала и пропуск экрана блокировки фактически не работали. Вероятно, отсюда непропорциональный вклад claude.exe в elements. Это гипотеза, проверьте по объёму строк на приложение.

Четыре монитора

Все мониторы пишутся по умолчанию. Флаг --use-all-monitors включён, а статичные мониторы с окнами Claude порождают кадры в простое.
Есть поштучный выбор мониторов. Появилась пауза захвата для отдельного дисплея (changelog). Если браузер живёт на одном-двух мониторах, остальные можно не писать.
Проверка. Посчитайте кадры по монитору и по часу суток до и после.
