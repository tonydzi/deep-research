# Insight (DR DR26-07-28-HUB-05-2338): Claude Code Execution (50 бесплатных часов/день) как замена текстовому кодингу при пошаговом plan→code→test→review

> Отвечает на вопрос, экономит ли лимит пошаговое планирование и можно ли использовать инструмент Claude Code Execution вместо описания кода текстом для реальной экономии токенов.

## Ключевые выводы
- Каждая организация получает 1550 бесплатных container-hours в месяц (≈50 ч/день); сверх лимита — $0.05 за час контейнера, минимальный биллинг 5 минут за вызов.
- Песочница Code Execution: Python 3.11, ~5 ГБ RAM, 1 CPU, 5 ГБ диска, предустановлены pandas/numpy/sklearn/matplotlib; сети и pip install нет; лимит REPL-ячейки 90 сек; контейнер живёт до 30 дней, чекпоинтится после ~5 мин простоя.
- Ключевое разоблачение мифа: Code Execution НЕ уменьшает автоматически число токенов модели — он сокращает количество диалоговых сообщений (циклов «код→ошибка→фикс»), потому что Claude сам запускает и правит код в контейнере; это даёт оценочно ×2 и более экономии токенов на многошаговых задачах.
- На трёх кейсах (CSV-анализ 10K строк, разработка 5-файлового модуля с тестами, кластеризация 100K крипто-транзакций) Claude CodeExec тратит ~200–2000 токенов против ~600–4000 у GPT-4 Turbo без выполнения кода, при этом compute-стоимость почти нулевая в рамках бесплатного лимита.
- Ценовое сравнение: Claude Sonnet ~$3/$15 за 1M токенов против GPT-4 Turbo ~$0.03/$0.06 за 1K токенов — цена за токен сопоставима; но OpenAI Code Interpreter стоит ~$0.09/час за 1 ГБ контейнера, тогда как Claude — $0.05/час за 5 ГБ, то есть больше вычислений за доллар.
- Безопасность: sandbox без исходящего сетевого доступа, файлы ограничены рабочей директорией контейнера, данные хранятся до 30 дней — сопоставимо или строже типичных LLM code-interpreter решений.
- Ограничения: нет GPU, нельзя доустанавливать пакеты через pip во время выполнения, потолок 5 ГБ RAM/диска, минимальный биллинг 5 мин за вызов, возможны расхождения окружения (Linux/Python 3.11) с локальной средой разработки.
- Профильные применения под задачи Антона: Deep Research и анализ данных, биохакинг (обработка CGM/DEXA), кластеризация крипто-кошельков, OSINT-парсинг/дедуп, кластеризация списков VC для стартап-аналитики.

## Рекомендации / решения
- Использовать пошаговый workflow план→код→тест→ревью для ЛЮБЫХ LLM (не только Claude) — это снижает контекст, повторы и галлюцинации.
- Применять Claude Code Execution именно для data-heavy и итеративных задач, где иначе пришлось бы вручную гонять код туда-обратно.
- Переиспользовать ID контейнера между вызовами, чтобы сохранять загруженные данные/модули в памяти; большие датасеты грузить через Files API, а не пересылать в сообщениях.
- Следить за расходом через `/usage` в Claude CLI, оставаться в пределах бесплатных 1550 ч/мес; по умолчанию брать Sonnet 4.6 (дешевле), Opus 4.8 — только для сложных задач.
- Для тривиальных одноразовых скриптов (простая функция, однострочник) оставаться на обычном LLM-тексте без Code Execution — оверхед не окупается.
