# Designing an Essence and Evidence Split for a Personal Knowledge Vault

## Executive Summary

The cleanest architecture for a large heterogeneous vault is a **two-plane system**: **ESSENCE** as the semantic memory layer you embed and search by meaning, and **EVIDENCE** as the source-of-record archive you keep retrievable on demand, with explicit provenance links from every essence object back to its originating spans. That boundary is not arbitrary. It matches long-standing knowledge-management practice—fleeting/literature material being recast into durable permanent notes in Zettelkasten, evergreen notes being atomic and concept-oriented, and progressive summarization turning long dense material into progressively more discoverable layers—and it also matches modern agent-memory systems, which increasingly separate semantic memory from episodic history and raw messages. citeturn12view4turn6view0turn6view1turn12view0turn12view1turn6view4turn14view0turn16view0

For your stated goal—a “digital twin” whose *mind* is the distilled, reusable reasoning accumulated over months—the primary semantic index should contain only notes that are durable, self-contained, reusable, and worth re-reading **outside** their original source context. Raw transcripts, chat imports, email dumps, tool logs, ledgers, and message archives should stay outside that index unless they have been compressed into semantic objects or explicitly routed to a separate episodic namespace. Retrieval research supports this split: dense retrieval is sensitive to indexing granularity; proposition-like atomic units outperform broader passages; chunking materially changes retrieval quality; and naive RAG degrades on large heterogeneous corpora, where domain scoping and routing become necessary. citeturn22view0turn18view4turn18view5turn21view1turn21view3turn21view4

The strongest practical recommendation is therefore this: **make `layer: essence|evidence` the source of truth, backfill it with a deterministic-first classifier, and require provenance on every essence object**. Use folder and importer metadata only as priors; do not let them remain the final gate, because folder heuristics inevitably leak. For retrieval, keep one high-trust “mind” index for essence, and one or more “proof” access paths for evidence: BM25/grep over raw markdown; optional transcript-specific vector search in a separate namespace; and direct span lookups by ID when an essence note cites evidence. This mirrors production memory systems that selectively retain useful knowledge rather than stuffing raw interaction history into one undifferentiated pool. citeturn18view2turn25view1turn25view2turn11view4turn16view2turn6view7turn6view8turn11view5

The important caveat is that **over-distillation is real**. Emerging conversational-memory research has found cases where verbatim conversation chunks outperform extracted artifacts, because extraction loses details that later matter. So the correct conclusion is **not** “summaries replace records.” It is: **the twin’s semantic mind should be distilled, but the twin’s proof layer must preserve raw evidence with tight links and cheap retrieval**. In other words: *embed the essence, retain the evidence, and link them rigorously*. citeturn6view9turn20view1turn20view0

## Key Findings

Knowledge-management theory draws the boundary in a way that maps unusually well to your problem. Ahrens-style fleeting notes are explicitly temporary capture material meant to be rewritten and then discarded or de-emphasized; evergreen notes are meant to evolve across projects; and Matuschak’s formulation pushes toward notes that are atomic, concept-oriented, and densely linked so they can be recombined later. Tiago Forte’s progressive summarization makes the same move from another direction: long, dense source material should become increasingly discoverable through layers of compression, and not every note deserves full treatment. The shared pattern is clear: raw capture is valuable, but durable knowledge is a transformed artifact, not the original dump. citeturn12view4turn6view0turn6view1turn13search2turn13search3turn12view0turn12view1turn12view2

AI memory systems have largely converged on the same split. LangChain’s memory overview explicitly distinguishes **semantic memory** for facts and concepts from **episodic memory** for past actions and experiences. LangMem then operationalizes that split further: semantic memory stores facts and knowledge, episodic memory preserves successful interactions as examples, and procedural memory stores behavioral rules. Mem0 separates episodic summaries from semantic facts, promoting only durable details into semantic memory while leaving the rest episodic or discarding it. Zep represents raw episodes separately from entities and semantic relationships in a temporal graph. Letta separates in-context memory blocks from out-of-context archival memory and still keeps messages retrievable. LlamaIndex explicitly offers distinct long-term memory blocks for static facts, fact extraction, and vectorized chat history rather than forcing one storage model. Cloudflare’s Agent Memory is retrieval-based and opinionated for extracted memory rather than raw filesystem dumping. Claude Code’s own auto-memory feature also saves selective notes—build commands, debugging insights, architecture notes, code style preferences, workflow habits—rather than recording every token of every session into one memory substrate. citeturn6view4turn17view0turn17view1turn17view2turn14view0turn14view1turn16view0turn16view1turn16view2turn16view3turn16view4turn6view7turn11view4turn6view8

Retrieval research strongly favors **higher signal density and better corpus scoping**. Dense X Retrieval shows that proposition-level indexing—atomic, self-contained fact units—significantly outperforms passage-level indexing in dense retrieval and downstream QA. RAPTOR shows that hierarchical summaries can improve retrieval on long multi-step reasoning tasks by providing abstractions at multiple levels. Chunking studies show that chunking strategy materially affects retrieval performance and that preserving semantic coherence matters. “Lost in the Middle” shows that even strong long-context models degrade when relevant information is buried in the middle of long input contexts. These results do not prove that raw transcripts are useless; they show that **raw source shape is usually the wrong shape for the primary semantic index**. citeturn22view0turn22view1turn18view4turn18view5turn23view0turn23view1

Large heterogeneous corpora add another failure mode: **retrieval dilution**. Recent work on domain-scoped retrieval reports that as corpora expand across heterogeneous categories, dense retrieval loses discriminative power, even when approximate-nearest-neighbor search itself is functioning correctly. Related architectural work argues that naive flat RAG degrades on heterogeneous corpora and benefits from explicit domain organization and routing. That is directly relevant to a vault mixing concepts, beliefs, decisions, person-notes, transcripts, email dumps, ledgers, and logs. Putting them all in one semantic plane means the retriever is being asked to discriminate across fundamentally different information regimes. citeturn21view1turn21view3turn21view4

At the same time, **raw evidence should not be thrown away**. Evidence tracing work frames provenance as the accountability layer connecting retrieved evidence, tool outputs, memory items, intermediate claims, and final answers. Traceable-text research shows that linking summaries back to source passages helps users verify claims and use summaries as an index into the underlying source. In other words, the right move is not to erase raw logs after distillation; it is to keep them available as the auditable substrate beneath the semantic layer. citeturn20view0turn20view1turn20view2turn20view3

## Contradictions & Debates

The main live debate is not whether distillation is useful; it is **whether distilled artifacts can safely substitute for verbatim history**. A recent controlled ablation on long-conversation memory reports that verbatim chunks beat extracted artifacts by large margins on two conversational-retrieval benchmarks, attributing the gap to lossy distillation. That result matters, and it is the strongest argument against an “essence only, raw discarded” architecture. But it does **not** imply that raw chat logs belong in the same semantic index as curated knowledge. It implies that some queries require a fidelity-preserving evidence layer that can surface raw spans when exact historical detail matters. citeturn6view9turn20view1

There is also a debate inside knowledge-management practice around what counts as “permanent.” Some practitioners define permanent notes narrowly as polished statements in one’s own words; others emphasize that a permanent note is simply one that is **permanently useful**, not fixed or sacred. That debate is actually helpful here, because it suggests that essence should be treated as **revisable semantic state** rather than a final published truth. In a vault architecture, that means essence notes can and should be updated, superseded, merged, and split as beliefs evolve, while evidence remains immutable. citeturn12view5turn8search7turn13search17

Industry systems also disagree on representation. LlamaIndex explicitly supports vectorized chat-history memory blocks, which means “store old messages and retrieve relevant ones” is still a valid pattern in some systems. By contrast, Mem0, Zep, Cloudflare, LangMem, and Claude Code lean much harder toward selective extraction, typed memory, graph structure, or promotion of durable facts. The convergence is therefore not on one storage format; it is on **typed memory** and **separation of concerns**. Raw message retrieval exists, but it is usually not treated as the same thing as durable semantic memory. citeturn6view7turn14view0turn16view0turn11view4turn17view0turn6view8

A final debate concerns evaluation. LLM judges are attractive for scaling note classification and retrieval evaluation, but survey work is clear that reliability, consistency, and bias remain open problems and require rubric design and calibration. That means an LLM can help classify the gray zone of mixed notes, but it should not be the uncalibrated source of truth for your layer labels. citeturn19view0

## Best Practices

The principled boundary is this: **ESSENCE is what you want the future system to “know”; EVIDENCE is what you want the future system to be able to “prove.”** Essence should be durable across projects, interpretable without reopening the original transcript, compact enough to retrieve cheaply, and shaped like a semantic object: a decision, principle, concept, preference, belief, person-model, procedural rule, or conclusion-with-rationale. Evidence should preserve source shape and chronology: transcripts, email threads, raw imports, call notes, message logs, ledgers, tool outputs, and dead-ends. This boundary synthesizes evergreen/permanent note theory with semantic-vs-episodic memory design in agent systems. citeturn6view0turn6view1turn13search2turn13search3turn6view4turn17view0turn17view1turn14view0turn16view0

In practice, an item belongs to **ESSENCE** if it passes most of these tests: it can stand alone; it states one reusable idea or a tightly-coupled set of related ideas; it is useful beyond the immediate conversation or source; it is authored for future retrieval rather than raw capture; and its value survives even if the original evidence becomes tedious to reopen. This is why concepts, synthesized beliefs, decisions, user preferences, “what I think about X,” architecture conclusions, and person-notes that model stable relationships belong in essence. Matuschak’s atomicity and concept-orientation, Ahrens’s rewriting step, and proposition-level retrieval all point in the same direction: semantic memory works best when the retrieval unit is compact, coherent, and self-contained. citeturn6view1turn13search2turn12view4turn22view0

An item belongs to **EVIDENCE** if its value depends primarily on source fidelity, chronology, or verbatim detail. That includes chat exports, transcript files, email dumps, raw call notes, deterministic ledgers, tool logs, and imported message histories. These records are still useful—sometimes critically useful—but mainly for audit, replay, exact quote recovery, debugging, or reconstructing how a conclusion was reached. Evidence should therefore be stored durably and made easy to access, but it should not dominate the semantic plane. Emerging agent-search work even suggests that raw conversational corpora can be better served by lexical retrieval modes such as grep/BM25 in some settings, especially when queries hinge on exact phrases, timestamps, or specific spans. citeturn20view0turn20view1turn26view0

Boundary cases should be handled explicitly rather than hand-waved. A curated note that quotes a transcript is still **ESSENCE** if the note’s primary function is semantic synthesis and the quoted material is subordinate evidence; in that case, keep the essence note embedded, but store explicit `evidence_refs` to the quoted spans. A raw meeting note with a short “takeaways” section is still **EVIDENCE** if most of the content is chronological source record; extract the takeaways into a separate essence note rather than embedding the whole meeting note. Person-notes split the same way: stable preferences, relationship models, and recurring interpersonal patterns are essence; raw DM archives and chronological interaction logs are evidence. citeturn12view2turn12view3turn16view0turn20view1

For automatic classification at scale, the cheapest reliable pattern is **deterministic-first, probabilistic-second, LLM-third**. Metadata-aware document classification research shows that metadata can materially improve weakly supervised categorization. Weak-supervision systems like Snorkel show that arbitrary heuristics can be combined into useful training labels without hand-labeling everything. Information-density research also supports using lexical and structural signals as features, while warning that no single density metric is sufficient on its own. So the right classifier is not “let an LLM read 170k files”; it is a pipeline of explicit markers, folder/importer priors, structural heuristics, density features, and then a judge only for uncertain cases. citeturn18view2turn25view1turn25view2turn18view0turn18view1

## Failure Modes

The most dangerous failure is **evidence leakage into the essence index**. Once raw archives, transcripts, logs, and dumps enter the same dense space as curated notes, you get more semantic near-misses, more reranker load, lower signal density per retrieved token, and more corpus heterogeneity. Research on vector-search dilution and heterogeneous-corpus RAG says this failure is structural, not anecdotal. The symptom is not just larger storage; it is retrieval that increasingly returns source-shaped noise when the user really wanted a distilled belief, decision, or principle. citeturn21view1turn21view3turn23view0turn18view4

The opposite failure is **over-distillation**. If you compress every conversation into facts and summaries, you will lose nuance that later queries may need: the exact wording of a preference, the chronology of a decision, the rejected alternative, or the step where a mistaken assumption was corrected. The 2026 ablation showing verbatim chunks beating extracted artifacts is a warning against treating semantic promotion as a total replacement for history. Distillation should create the indexed “mind,” but it must not destroy the “proof.” citeturn6view9

Another failure is **broken provenance**. If an essence note cannot reliably point back to the spans it came from, trust erodes and the system becomes harder to debug. Provenance surveys, traceable-text work, and citation-enforced RAG all converge on the same lesson: summaries and semantic objects become more useful when they carry inspectable links back to underlying evidence, ideally at span level rather than only document level. citeturn20view0turn20view1turn20view3

A subtler failure is **maintenance drift**. Notes evolve. Memory systems now increasingly model temporal updates, invalidation, and changing relationships, and Zettelkasten practitioners explicitly reject the idea that permanent notes are unchanging. If your essence plane lacks `supersedes`, `valid_from`, `valid_to`, or confidence metadata, the digital twin will start speaking with stale certainty while the evidence plane keeps accumulating contradictions underneath it. citeturn16view1turn16view0turn12view5turn14view4

The final operational failure is **using a weak classifier as policy**. A folder heuristic is too brittle; a pure LLM judge is too expensive and insufficiently reliable; a pure density metric is too blunt. The way out is staged classification with abstention: high-confidence auto-labels, an uncertainty queue, and periodic calibration against a small human-verified set. citeturn18view2turn25view1turn19view0

## Strategic Recommendations

For this vault, the best low-complexity, repairable design is:

1. **Primary semantic plane**: embed only `layer: essence` notes.  
2. **Evidence plane**: keep all raw markdown, transcripts, chats, email dumps, ledgers, logs, and imports on disk and searchable via lexical methods first; optionally add a separate episodic namespace for transcript summaries or selected raw chunks if you later need semantic recall over discussions.  
3. **Promotion pipeline**: distill evidence into essence objects that are atomic enough to retrieve cleanly and always carry provenance back to source spans.  
4. **Temporal update model**: let essence notes be revised and superseded; keep evidence immutable.  

That design fits both knowledge-management theory and modern memory-system practice, while avoiding the failure modes seen in heterogeneous flat RAG. citeturn22view0turn21view3turn16view2turn16view0turn11view4turn6view8

I would make the frontmatter schema mandatory and explicit. A practical minimal version looks like this:

```yaml

title: Why short fasting windows improve my adherence more than longer ones
layer: essence            # essence | evidence
memory_type: semantic     # semantic | episodic | procedural | source_record
source_type: distilled_note

  - fasting
  - adherence
person_scope: self
evidence_refs:
  - note_id: Personal-DMs/_session-md/claude-2026-05-31
    span: "#L421-L468"
    kind: transcript
  - note_id: ledgers/turnstate-2026-05-31.json
    span: "$.decision[3]"
    kind: ledger
classifier:
  method: deterministic_plus_review
  score: 0.94
```

For evidence notes, keep the same `id`, `source_type`, timestamps, and any parsing metadata, but omit embedding and retain precise anchors. This is the key repairability move: if a classifier mistake is found later, the data model already supports reclassification without re-ingesting everything from scratch. Provenance and temporal state are not decoration here; they are what keep the semantic plane trustworthy. citeturn20view0turn20view1turn20view3turn16view1

For backfill classification, use a **deterministic-first scoring model**. In order of precedence: existing frontmatter marker wins; then importer/source-type tags; then folder priors; then hard evidence detectors such as speaker-role prefixes, email headers, timestamp density, tool-output blocks, log/JSON/code ratios, and very long chronological structure; then hard essence detectors such as claim-like titles, summary/decision headings, link density, reusable framing, and low source-quote ratio. Convert those signals into weak labels, auto-accept the high-confidence tails, and send the ambiguous middle band to an adjudication step. Over time, train a small local supervised classifier on the reviewed set using metadata plus structure features. Weak-supervision and metadata-aware classification literature strongly supports this staged approach. citeturn18view2turn25view1turn25view2

A useful practical distinction is to treat **signal density** as a helper metric, not the decision rule. Lexical density, entropy, surprisal, link density, and assertion density can help rank notes for likely essence promotion or likely evidence exclusion, but they are not reliable enough to decide alone because information density is domain-sensitive. In practice, signal density is best used to prioritize review, not to define ontology. citeturn18view0turn18view1

The retrieval side should also be split by query type. Queries like “what do I believe about X,” “what principle did I adopt for Y,” or “how do I usually prefer Z” should hit the essence plane first. Queries like “what exactly did we say,” “when did that decision happen,” “show the proof,” or “find the email/chat/log where this came from” should route to evidence search first. Retriever-routing research and domain-scoped RAG both support query-dependent routing over static one-size-fits-all retrieval. For evidence search in transcript-heavy corpora, lexical retrieval is often the simplest strong baseline. citeturn21view4turn21view1turn26view0

## Action Plan

Start by freezing the ontology. Adopt a short policy document that defines `layer: essence|evidence`, `memory_type`, and `source_type`, and makes one rule non-negotiable: **if a note is not explicitly essence, it does not enter the primary semantic index**. That single default will stop future leakage faster than any later cleanup. The theory behind this is the same one visible across progressive summarization and production memory systems: promotion is selective, not automatic. citeturn12view0turn11view4turn6view8

Then run a backfill in three passes. First, auto-label the obvious tails with deterministic rules. Second, review a stratified sample from the ambiguous middle and use that to calibrate both rules and a cheap classifier. Third, re-run the backfill and generate a diff report: count of files moved to essence, count moved to evidence, count still uncertain, and count of essence notes lacking provenance. Weak supervision is the right way to keep this cheap without trusting heuristics blindly. citeturn25view1turn18view2

Next, split retrieval into two explicit services. The **mind service** is your current dense retrieval plus rerank over essence only. The **proof service** is evidence search, starting with BM25/grep over raw markdown and exact-span lookup by note ID and anchor; if needed later, add a separate episodic vector namespace for transcript summaries or raw turn windows. This lets you preserve every artifact without paying the primary-index precision cost. Emerging conversational-search results make that a pragmatic, not merely ideological, choice. citeturn26view0turn21view1

After that, enforce provenance creation in your distillation pipeline. Every promoted essence note should carry one or more `evidence_refs` with file ID plus line/span anchors. For summaries generated from multiple sources, require multi-span provenance. If provenance is missing, treat the note as quarantine rather than essence. Provenance research is very clear that traceability is the accountability layer, and traceable summaries are more verifiable and more useful. citeturn20view0turn20view1turn20view3

Finally, run an A/B evaluation before and after the split. Use a gold set of real vault queries divided into at least three buckets: **essence queries** (“what do I think about X?”), **evidence queries** (“where did this come from?”), and **mixed queries** (“what conclusion did I reach, and show the source?”). Measure note-label precision/recall, leakage of evidence into the essence index, retrieval P@10 and NDCG@10 on essence queries, evidence-hit rate on proof queries, answer accuracy and faithfulness, latency, and storage growth. Use humans for the gold set and optionally RAGAS/LLM judges for scale, but calibrate judges against human labels rather than trusting them by default. Retrieval and evaluation literature supports this exact kind of multi-metric setup. citeturn24search6turn24search3turn24search8turn24search1turn19view0
