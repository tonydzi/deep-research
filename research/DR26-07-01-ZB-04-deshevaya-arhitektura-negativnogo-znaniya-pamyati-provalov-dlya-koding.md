# Insight (DR DR26-07-01-ZB-04): Дешёвая архитектура «негативного знания» / памяти провалов для кодинг-агентов

> ⚠️ **UPDATE 2026-07-14:** эта заметка была сгенерена по ПРОМПТУ (тела отчёта тогда не было — ChatGPT не отдаёт DR через экспорт). Полный отчёт СОБРАН 14.07 (Export→Markdown), лежит в `_originals\deep-research\` (путь в «Источник»). Актуальный синтез: [[decision-agent-stack-dr-bundle-synthesis-2026-07-14]].


> Незавершённый DR-запрос: как дать личным кодинг-агентам долговечную структурированную (не векторную) память о неудачных подходах, чтобы не переоткрывать тупики каждую сессию — фактического отчёта с результатами исследования в файле нет, только пересланный промпт в Deep Research App.

## Ключевые выводы
- Файл содержит только пересланный запрос в ChatGPT Deep Research App (2 системных вызова /Deep Research App/start) — итоговый исследовательский отчёт с результатами в этом документе отсутствует.
- Референс-точка задачи: статья 'Negative Knowledge as Failure-aware Shared Memory for AutoResearch' (arXiv 2606.21024, репо github.com/hch-wang/Negative_Knowledge).
- Схема статьи: Depth-1 записи с закрытым словарём полей — task_id, attempted_route, observation, failure{layer, scope, degree, recommended_action, risk}, rationale, recommended_alternative.
- Есть также Depth-N паттерн-записи (обобщения поверх повторяющихся Depth-1 провалов) и роль curator, который пишет/курирует записи.
- Ключевой механизм — 'forced grounding': агент ОБЯЗАН прочитать и явно принять/отклонить релевантные негативные записи перед следующим действием, а не просто иметь к ним доступ.
- Явное предостережение статьи: наивный retrieval 'похожий прошлый фикс' через векторную близость/эмбеддинги активно вводит в заблуждение — извлекать нужно по структурированным тегам (домен/слой), а не по fuzzy similarity.
- У Антона уже есть подходящая инфраструктура для такой памяти: SQLite-таблицы (leads.db, system.db) + markdown-карточки (concept-*, reglament-*) + принцип 'SQL/grep до LLM' — то есть реализация ложится на существующий стек без новых зависимостей.

## Рекомендации / решения
- Повторно отправить/забрать фактический результат Deep Research (в этом файле сохранился только исходящий промпт, а не ответ) — без него нельзя закрыть DR26-07-01-ZB-04.
- При реализации памяти провалов проектировать retrieval строго по закрытым структурированным тегам (domain/layer/scope), не через векторную схожесть текста.
- Ввести 'forced grounding' — обязательное чтение+явное решение агента (adopt/reject) по релевантным негативным записям перед повторной попыткой того же класса действия, а не пассивное хранение.
- Использовать уже существующий стек Антона (SQLite-таблица + markdown-карточка + grep-перед-retry) вместо новой БД/сервиса — соответствует принципу АК-47.
- Заложить механизм борьбы с 'stale negative' (устаревшее 'не делай X', которое позже стало валидным) — иначе память провалов рискует стать свалкой или чрезмерно подавлять эксперименты.
