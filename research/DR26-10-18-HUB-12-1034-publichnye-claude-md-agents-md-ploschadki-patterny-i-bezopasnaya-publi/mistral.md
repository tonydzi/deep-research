# Публичные инструкции AI-агентов: глубокое исследование

**Дата исследования:** 18 октября 2026. Все файлы прочитаны «вживую» по зафиксированным коммитам, все ссылки на документацию вендоров открыты и проверены в ходе исследования. Чужой код и текст не копируются — анализируются только идеи и структура.

---

## Вопрос

Как устроены публичные файлы инструкций AI-агентов (CLAUDE.md, AGENTS.md, GEMINI.md, .cursorrules): где они публикуются, какие паттерны в реальных рабочих файлах стоит перенести в большой личный документ, что говорят эмпирические данные о длине и перегрузке инструкций, и как безопасно и обратимо опубликовать собственный документ (allowlist, без личных путей и секретов, с канарейкой и измеримыми критериями).

## Резюме

1. **Фактический стандарт де-факто — AGENTS.md.** Он читается не только OpenAI Codex, но и Claude Code (с v2.1.277), Cursor, Gemini CLI (через настройку `context.fileName`) и десятками других агентов; спекфикация ведётся фондом Agentic AI Foundation под эгидой Linux Foundation ([agents.md](https://agents.md/)). Два крупных проекта из выборки (Supabase, PostHog) держат единый `AGENTS.md`, а их `CLAUDE.md` — однострочный указатель на него.
2. **Рабочие файлы начинаются с команд и запретов, а не с описаний.** Homebrew открывает файл требованием запустить проверку; Bun — командой сборки; Electron — запретом `npx` с обоснованием; Cal.com — списками «Do / Don't» и границами «Ask first / Never do». Это главный признак, отделяющий рабочие файлы от шаблонов.
3. **Эмпирика подтверждает перегрузку, но с оговорками.** IFScale: лучшие модели следуют лишь ~68% из 500 инструкций, с перекосом в пользу инструкций из начала ([arXiv:2507.11538](https://arxiv.org/abs/2507.11538)); «Lost in the Middle» — U-образная кривая по позиции ([arXiv:2307.03172](https://arxiv.org/abs/2307.03172)); Context Rot — деградация от одной только длины входа ([Chroma](https://www.trychroma.com/research/context-rot)). Все три исследования — синтетические задачи; прямых исследований «длина CLAUDE.md → качество» нет.
4. **Вендоры задают инженерные лимиты, а не эмпирические.** Codex обрезает цепочку файлов на 32 KiB ([документация OpenAI](https://developers.openai.com/codex/guides/agents-md)); авто-память Claude Code читает первые 200 строк / 25 KB ([документация Anthropic](https://code.claude.com/docs/en/memory)); Anthropic прямо пишет: чем конкретнее и короче инструкции, тем стабильнее выполнение.
5. **Масштабирование больших документов идёт тремя механизмами:** вложенные файлы по каталогам (монорепо-паттерн Supabase, «в OpenAI 88 файлов AGENTS.md» по данным agents.md), импорты `@path` (глубина до 4 у Claude), правила с гло-скоупом (`.cursor/rules/*.mdc`, `.claude/rules/`) и «прогрессивное раскрытие» — отсылки к тематическим документам, которые агент читает по необходимости (Bun, PostHog, Cal.com).
6. **Безопасность публикации решается гигиеной и автоматикой, а не надеждой:** GitHub push protection блокирует пуш с секретами до попадания в репозиторий ([GitHub Docs](https://docs.github.com/en/code-security/concepts/secret-security/push-protection)), gitleaks работает как CI-проверка ([gitleaks-action](https://github.com/gitleaks/gitleaks-action)), а личные пути/идентификаторы выносятся в непубликуемый `CLAUDE.local.md` или отдельный приватный слой.
7. **Канарейка обратима, потому что инструкции — это код в git:** метрики фиксируются до rollout (через `/context` и eval-набор), расширение идёт по одному инструменту/репозиторию, откат — один `git revert`.

### 4. Реальные рабочие файлы против шаблонов и рекламы

**Признаки рабочего файла (наблюдения из п. 3):**
- начинаются с **команд, которые нельзя выдумать** (`bun bd`, `./bin/brew lgtm`) и с **проверяемых запретов** (`npx` у Electron, ветки `claude/*` у Bun);
- ссылаются на **реальные артефакты репозитория** (REVIEW.md, `.claude/docs/landing-prs.md`, `docs/internal/monorepo-layout.md` у PostHog);
- содержат **обоснования** («если нужен абзац, чтобы оправдать workaround — код неверен» у Bun; объяснение, почему `npx` опасен, у Electron);
- включают **гочу-ловушки, которые агент иначе не выведет из кода** (правило о консервативном стек-сканере у Bun; границы TypeORM/шифрования у n8n; порты `port: 0` у Bun);
- живут: свежие коммиты (Bun — 16.10.2026, т.е. за 2 дня до исследования), изменение под реальную практику.

**Признаки шаблона или рекламы:**
- SEO-гайды и «генераторы» (agentsmd.net, prpm.dev, гайды morphllm, thepromptshelf.dev, cursorgenerator.dev, cursorrules.org) — пересказ вендорской документации с промптом «сгенерируй файл за 5 минут»; полезны максимум как навигация, факты брать у вендоров;
- файлы-шаблоны в awesome-списках: универсальные правила («пиши чистый код», «следуй best practices») без единой команды или ссылки на реальный код;
- списки с очевидным коммерческим следом (спонсорские блоки у awesome-cursorrules; «90.8k+ разработчиков» на витрине cursor.directory — маркетинговая цифра витрины, а не рецензия);
- `.cursorrules`, оформленный как манифест тона (PostHog — рабочий пример, но это отдельный класс: тон-файл, а не техническая документация).

| Запреты с обоснованием и критерием нарушения | Bun, Electron, n8n, Cal.com | Не «не делай X», а «не делай X, потому что Y; если всё же считаешь X — приложи доказательства Z» |
| Тон отдельно от техники | PostHog (.cursorrules), n8n (языковой стандарт) | Стиль ответов — отдельный маленький модуль, подключаемый по необходимости |
| Процесс PR/коммитов | PostHog, Cal.com (лимиты размера PR и примеры дробления) | Конвенции оформлены как явные списки и чеклисты |
| Правила честности и верификации | Bun («никогда не преувеличивай сделанное»; «тест невалиден, если не проверил, что он падает») | Анти-галлюцинационные правила прописаны явно |
| Безопасность как раздел | PostHog, n8n, claude-code (весь файл — hardening) | Безопасность — первоклассный раздел, не сноска |
| Живой документ | agents.md FAQ, Anthropic («refine over time», `/init`) | Файл правится итеративно, а не пишется один раз навсегда |

#### Рекомендации — что из этого следует для вашего документа

1. **Ядро + модули.** Держите корневой файл ≤ ~8–12 KB (эмпирика и вендорские лимиты — ниже) с командами, критическими запретами и картой модулей; остальное — импорты/вложения/правила по скоупу.
2. **Один источник истины.** Если пользуетесь несколькими агентами — `AGENTS.md` как источник, `CLAUDE.md` и `GEMINI.md` как однострочные указатели (`@AGENTS.md`), Gemini CLI — через `context.fileName`.
3. **Каждое критическое правило = правило + «почему» + признак нарушения.** Так замена контекста не ломает интерпретацию, и правило переживёт смену модели.
4. **Тон — отдельным модулем**, не смешивайте с техникой (паттерн PostHog).
5. **Критичное — наверх**: и из-за перекоса моделей к началу инструкций (IFScale), и из-за U-образной кривой позиций (Lost in the Middle).
6. **Измеримость встроена в файл:** в конце — раздел «Как проверить, что инструкции загружены и работают» (`/context`, контрольные вопросы).
7. **Жёсткие запреты — не в файле, а в hooks/allowlist:** инструкции — «контекст, а не принудительная конфигурация» (Anthropic); то, что нельзя нарушать никогда, должно блокироваться механизмом, а не текстом.

### 6. Эмпирические данные о длине и перегрузке инструкций — и их ограничения

**Что установлено (наблюдения из первоисточников):**

| Источник | Результат | Дата |
|---|---|---|
| [IFScale, arXiv:2507.11538](https://arxiv.org/abs/2507.11538) (Distyl AI) | 20 моделей, 7 провайдеров: при 500 одновременных инструкциях лучшие frontier-модели дают лишь ~68% выполнения; деградация трёт тремя паттернами, коррелирует с размером/reasoning-способностями; систематический перекос в пользу инструкций из начала | 15.07.2025 |
| [Lost in the Middle, arXiv:2307.03172](https://arxiv.org/abs/2307.03172) (Stanford/UC Berkeley/Samaya) | На multi-document QA и key-value retrieval качество заметно падает, когда нужное — в середине длинного контекста; U-образная кривая; эффект есть даже у моделей, позиционированных как long-context | 2023 (v3 — 20.11.2023) |
| [Context Rot, Chroma](https://www.trychroma.com/research/context-rot) | 18 frontier-моделей: деградация от роста длины входа даже на намеренно простых контролируемых задачах (семантический NIAH, LongMemEval, повтор слов); деградация нелинейная и неравномерная | 2025 |
| Вендорские инженерные лимиты | Codex: цепочка файлов AGENTS.md обрезается на 32 KiB ([OpenAI](https://developers.openai.com/codex/guides/agents-md)); Claude Code: авто-память читает первые 200 строк / 25 KB, импорты — глубина ≤ 4 ([Anthropic](https://code.claude.com/docs/en/memory)); Cursor: содержимое правила включается в начало контекста ([Cursor](https://cursor.com/docs/rules)) | 2026 |

**Ограничения этих данных (обязательно учитывать):**
- IFScale — **синтетическая задача** (вставка ключевых слов в бизнес-отчёт), один тип инструкций, модели поколения 2025 года; прямая проекция на «следование CLAUDE.md» — экстраполяция;
- Lost in the Middle — модели 2023 года и задачи извлечения, не следования правилам; архитектуры и обучающие данные с тех пор менялись;
- Context Rot — намеренно простые искусственные задачи; авторы сами подчёркивают, что реальные приложения сложнее;
- **ни одно исследование не измеряло эффект длины именно файлов инструкций агентов** — это нерешённый пробел; вендорские лимиты (32 KiB, 25 KB) — продуктовые решения, а не результаты измерений;
- выводы «короткий файл лучше длинного» у вендоров — практический опыт, а не контролируемый эксперимент.

**Практическое следствие (рекомендация):** относитесь к «сколько можно» как к эмпирическому вопросу вашей собственной канарейки (см. п. 9), а не как к константе из чужих бенчмарков.

### 8. Безопасная публикация через allowlist

Принцип: публикуется не «всё, что не запрещено», а **только то, что явно внесено в allowlist разделов** — прямая аналогия с сетевым allowlist-файлом из собственного CLAUDE.md репозитория anthropics/claude-code (режим `enforce`, запрет wildcard-хостов).

**Чеклист санитизации перед публикацией (рекомендация):**
1. **Пути:** убрать `~/Users/...`, `/home/<имя>`, имена машин, внутренних хостов, портов внутренних сервисов; заменить плейсхолдерами (`$REPO_ROOT`, `$EDITOR_CMD`).
2. **Идентификаторы:** убрать имена, почты, ключи учёток, ID проектов, ссылки на приватные репозитории и вики.
3. **Секреты — никогда**, включая «закомментированные на всякий случай»: GitHub push protection блокирует пуш с секретами до репозитория ([GitHub Docs](https://docs.github.com/en/code-security/concepts/secret-security/push-protection)), gitleaks — как CI-проверка ([gitleaks-action](https://github.com/gitleaks/gitleaks-action)). Если секрет попал в историю — он скомпрометирован, вращать ключ, а не просто удалять коммит.
4. **Личный слой отдельно:** `CLAUDE.local.md` (Claude Code) или отдельный непубликуемый файл для личных предпочтений; публичная версия — только командно-проектные правила ([Claude memory docs](https://code.claude.com/docs/en/memory)).
5. **Чужое не копировать:** в выборке есть файлы под несвободными/особыми лицензиями (anthropics/claude-code — all rights reserved; n8n — fair-code Sustainable Use License). Анализировать идеи — можно, переносить текст — нет. Для своего файла выбрать явную лицензию (MIT/Apache-2.0/CC-BY-4.0).
6. **Автоматический контроль перед каждым пушем:** push protection включён; gitleaks в CI; ревью PR на файл — обязательное, файл = код.

### 9. План обратимой канарейки с измеримыми критериями

**Этап 0 — базовая линия (1–3 дня):** до любых изменений зафиксировать метрики на текущем документе: (а) набор из 15–20 типовых задач с чеклистом критических правил; (б) доля контекста, занятая инструкциями (`/context` в Claude Code; аналогично в Codex/Cursor); (в) частота «агент не знал/нарушил правило» за неделю.

**Этап 1 — канарейка (1–2 недели):** новая структура подключается в **одном** репозитории/одном инструменте (или в ветке через импорт). Остальные окружения — на старой версии.

**Критерии продолжения (все обязательны):**

| Метрика | Способ измерения | Порог |
|---|---|---|
| Следование критическим правилам | eval-набор: 15–20 задач, чеклист на каждую | ≥ 90% (и не ниже базовой линии) |
| Доля контекста на инструкции | `/context` | ≤ 10% окна |
| Секреты/личные данные в файле | push protection + gitleaks CI | 0 срабатываний |
| Загрузка файла подтверждена | `/context` (Claude), ответ Codex «Summarize the current instructions» (приём из гайда OpenAI) | файл виден в каждом запуске |
| Регрессии по работе | ошибки CI/проверок из-за неверных команд в файле | 0 |

**Триггер отката:** падение следования правилам > 10 п.п. против базовой линии, либо 2+ регрессии CI, либо рост «нарушений правила» в обратной связи — откат.

**Этап 2 — расширение:** критерии выполнены → подключить второй инструмент через указатель `@AGENTS.md` (не копию), затем остальные репозитории, по одному за итерацию; после каждого шага — короткое сравнение метрик с базовой линией.

**Почему это обратимо (наблюдение → рекомендация):**
- файл версионируется в git → откат = `git revert` одного коммита; изменения идут через PR → можно вернуться к любой точке;
- указатели (`@AGENTS.md`) позволяют выключить модуль, не трогая источник;
- у Cursor правила имеют режимы (Manual/Intelligently) → можно точечно отключать без удаления;
- «контекст, а не конфигурация»: пока жёсткие запреты остаются в hooks/allowlist, откат файла инструкций не ослабляет безопасность.

## Рекомендации и следующие шаги

1. **Переориентируйте документ на AGENTS.md** как единый источник истины; для Claude Code/Gemini CLI/Cursor оставьте указатели (одна строка) или настройку `context.fileName` — это подтверждённая практика Supabase и PostHog.
