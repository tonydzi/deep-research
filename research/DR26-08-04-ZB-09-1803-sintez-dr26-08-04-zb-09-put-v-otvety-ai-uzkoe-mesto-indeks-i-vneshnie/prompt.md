# Запрос на глубокое исследование: пошаговый протокол попадания в ответы AI-движков для малой независимой лаборатории

  13 845 обращений AI-краулеров, из них PerplexityBot 499, ClaudeBot 164 + anthropic-ai 6,
  GPTBot 50, Googlebot 114, bingbot 80. При этом страниц в индексе Bing/DuckDuckGo — НОЛЬ
  (проверено с контролем на заведомо проиндексированной чужой фразе).
- Perplexity на профильный вопрос «какие независимые лаборатории публикуют open-source
  для governance AI-агентов» вернул 10 источников. ВСЕ 10 — репозиторий GitHub или
  курируемый список (4 из них «awesome-*»), плюс Microsoft Agent Governance Toolkit,
  AI Alliance Open Agent Lab, governance.agentrust-io.com. Ни одного «сайта компании».
- Gemini на тот же вопрос назвал троих, третьим — СОЛО-ИНЖЕНЕРА с одним hook-репозиторием.
- Внешних ссылок на наш домен 0, форков 0.

## Гипотеза, которую надо проверить или опровергнуть
«Планка входа в ответ движка — не известность организации, а наличие атрибутируемого
артефакта на поверхности, у которой уже есть авторитет индекса (GitHub, курируемые списки),
поэтому малой лаборатории выгоднее вкладываться в артефакты и списки, чем в собственный сайт.»

Опровергай честно. Если данные говорят обратное — так и напиши.

## Что нужно: ПОШАГОВЫЙ протокол, а не общие советы
1. **Разбери механику по стадиям**: краул → индекс → retrieval движка → цитата в ответе.
   Что именно определяет переход между каждой парой стадий у Perplexity, ChatGPT Search,
   Gemini, Claude с веб-поиском? Где у них общий слой (Bing/Google индекс), где свой?
2. **Что конкретно повышает шанс цитирования** — ранжируй по силе эффекта, с источниками
   и датами: наличие в awesome-списках · количество звёзд · свежесть коммитов · CITATION.cff ·
   llms.txt · структура README · упоминания в постах/новостях · Wikipedia/Wikidata сущность ·
   упоминания на площадках с высоким доверием (HN, Reddit, arXiv) · схема Organization в
   разметке. Что из этого доказано исследованием, а что — фольклор индустрии?
3. **Отдельно: как движки решают, что организация СУЩЕСТВУЕТ.** Gemini на наш домен ответил
   «no verifiable independent lab operating under that name or domain». Какие сигналы делают
   сущность «верифицируемой» для LLM — Wikidata, Crunchbase, GitHub org, arXiv-аффилиация,
   упоминания в новостях? По каждому: сколько времени занимает и что реально требуется.
4. **Роль имени.** Насколько сильно коллизия имени с крупным брендом (у нас — Palo Alto
   Networks) подавляет выдачу? Есть ли замеры/кейсы? Что выигрывает уникальный коинованный
   токен и за какой срок?
5. **Личный бренд против бренда организации.** Что для движков надёжнее верифицируется —
   человек (GitHub-профиль, публикации, единый handle во всех сетях) или молодое юрлицо?
   Кейсы, когда соло-инженер попадал в ответы движков раньше, чем компании.
6. **Дай КОНКРЕТНУЮ последовательность шагов** для команды из 1-3 человек с нулевой
   ссылочной массой: что делать в неделю 1, 2-4, 5-12, с ожидаемым сроком до первого
   цитирования и с метрикой проверки на каждом шаге.

## Формат
Таблицы. Каждое утверждение — ссылка + дата + что именно оттуда взято. Разделяй
established / emerging / speculative. Явно перечисли, чего найти НЕ удалось.
Не выдумывай кейсы, репозитории и цифры.
