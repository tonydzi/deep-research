# Insight (DR DR26-08-25-MACANTON-14-0740): Первые команды и первый урок для новичков в Claude Code, Codex и Grok Build

> Ресёрч выясняет, какие проблемы чаще всего возникают у новичков в кодинг-агентах (Claude Code, Codex, Grok Build) и какой набор первых команд/промптов даст студентам «вау»-эффект и желание продолжать.

## Ключевые выводы
- Первый урок должен строиться не вокруг терминала/установки/Git, а вокруг эмоциональной последовательности: описал на естественном языке → агент создал файлы → это сработало → попросил изменение → изменилось → проверил → узнал, что можно откатить
- Нет вендорского нормализованного датасета частоты вопросов новичков — ранжирование проблем построено по повторяемости в официальной документации/issue-трекерах, а не по статистике
- Главные проблемы новичков кросс-платформенно совпадают: запуск не из той папки, проблемы PATH/установки/shell, путаница с авторизацией, тревога из-за permission-запросов, расплывчатые промпты, невозможность проверить правильность результата, страх разрушительных правок, замусоренный контекст в долгих сессиях
- OpenAI прямо указывает, что многие «проблемы качества» Codex на деле — проблемы окружения: не та рабочая директория, нет прав на запись, не хватает инструментов
- Рекомендуемый универсальный workflow для всех трёх платформ: Folder → Ask → Plan → Build → Verify → Inspect → Iterate → Recover — освоив его, переход между агентами сводится к разнице в названиях команд
- Grok Code (модель, запущена 28.08.2025) и Grok Build (терминальный агент, запущен май 2026, open-sourced 15.07.2026) — разные вещи; нужно называть продукт правильно
- Claude Code хорошо подходит для первого урока новичков: есть гайд для тех, кто никогда не пользовался терминалом, /powerup (интерактивные уроки), plan mode, checkpoints, /rewind, /doctor
- Codex хорош, если аудитория уже пользуется ChatGPT: CLI приветствует /init, /status, /permissions, /model, /review; OpenAI формализует структуру промпта Goal/Context/Constraints/Done-when
- Рекомендуемое первое упражнение — zero-dependency статичное мини-приложение («My Command Center» на index.html/style.css/app.js) без фреймворков/npm/API, чтобы исключить лишние точки отказа (сеть, зависимости, sandbox)
- Опасные режимы (Claude bypass-permissions, Grok --yolo/always-approve, Codex full-access) нужно явно запретить в первом уроке — цель «машина может делать вещи, а я остаюсь в контроле», а не «машина может всё»
- Верификация важнее умного промптинга: без теста/сборки/скриншота/линтера агент может только решить, что работа выглядит законченной — нужен явный чек
- Правило от контекстного замусоривания: одна связная задача = одна беседа (использовать /clear, /compact между несвязанными задачами)

## Рекомендации / решения
- Не учить все три платформы сразу — сначала дать один универсальный workflow (Understand → Plan → Change → Verify → Review → Recover), потом различия команд
- Первый урок оптимизировать под «вау-эффект», а не техническую полноту: избегать React/Next.js/npm/Docker/API-ключей/деплоя/GitHub в первом занятии
- Преподавателю заранее установить и авторизовать агента студентам — установка не имеет демонстрационной ценности
- Дать студентам ровно 3 концепта на старте: working directory, prompt (спецификация, не заклинание), diff/verification/undo
- Использовать копипаст-сценарий: создать disposable-папку → запустить агента → короткая ориентационная команда (/powerup для Claude, /status+/ для Codex, /help для Grok) → единый структурированный промпт (Goal/Context/Constraints/Done when) → итеративные доработки → критика («skeptical senior engineer») → обучение восстановлению через /rewind или /diff
- На день 1 ограничить набор команд до 5-6 на продукт: Claude — /powerup, /init, /plan, /review, /rewind (+/permissions); Codex — /status, /init, /plan, /diff, /review; Grok — /help, /plan, /view-plan, /rewind, /compact (+/terminal-setup)
- Учить студентов промпт-паттерну GOAL/CONTEXT/CONSTRAINTS/DONE WHEN как единственному, что стоит запоминать на стену
- Использовать приём «интервьюирование» — просить агента задать до 5 уточняющих вопросов перед реализацией, если идея расплывчата
- Не вводить MCP, subagents, plugins, hooks, worktrees, автономные режимы, пока студент не может уверенно ответить на 6 базовых вопросов (директория, цель, ограничения, верификация, diff, откат)
- В качестве первой платформы курса при terminal-first формате — Claude Code; при аудитории из ChatGPT-пользователей — Codex; Grok Build — хорошая вторая платформа для демонстрации переносимости концепций
