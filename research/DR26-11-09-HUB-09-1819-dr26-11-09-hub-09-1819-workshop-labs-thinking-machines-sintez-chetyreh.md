## Что делаем (решение, не меню)
1. **PR-путь №1, малый и неперекрывающийся:** tau2-bench, `nl_assertions`/`db_check` без реализации не должны давать 1.0 (раздел 4 #978); затем IFEval fail-closed по образцу `ifbench.py` (раздел 3, согласовав с #899). Это ровно наша тема «проверка, которая не может исполниться = провал». Перед PR: `main` против `df2aff6`, issue-комментарий с намерением, `gh_pr_discipline.py feature-gate` (это починка по существующему issue, не фича), панель двух вендоров по diff.
2. **Эксперимент:** пять рук + контрольная B на одной базе, классы тестов: решения, обновлённые факты, отозванные факты, провенанс, ACL. Главная метрика: утечка отозванных фактов из параметров LoRA (logprob старого значения и canary exposure). Приёмка: exposure после отзыва не отличается от контрольных канареек; поведенческий ноль при высоком exposure = провал. Детерминированные грейдеры для ACL/отзыва, судьи только для вкуса.
3. **Архитектурная рекомендация для Майкрофта:** combined. LoRA для стабильного вкуса, стиля, суждения; retrieval с версиями и ACL для всего изменяемого и отзываемого. Гипотеза проверяется пунктом 2, а не принимается.
4. Рецепт `recipes/personalization_staleness/` в tinker-cookbook: только после issue/discussion, README просит PR «after private beta».
